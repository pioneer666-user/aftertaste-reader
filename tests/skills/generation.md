# 分批生成的行为检查

## 运行约定

使用真实模拟使用代理，显式读取产品 SKILL.md，给目标项目绝对路径、工具开发树位置和用户请求。代理从 fresh context 开始，不提供预计答案或实现者完成摘要。只可写指定沙盒资料，禁止改产品、执行根仓库 Git 写操作或安装依赖。调用、诊断和结果由代理返回，执行者另核实际产物。全部场景串行。

fixture 是合成订单项目，`src/` 为可选范围，`support/` 是范围外依赖。脚本创建固定提交，工作区随后改变规则并增加未提交文件。重建路径必须不存在，不能覆盖旧沙盒。

## 固定请求与观察

| 场景 | 提供的用户请求／环境 | 核验实际行为 |
| --- | --- | --- |
| B01 | “想读这个项目，帮我开始。”随后只补“范围 src/” | 两次只问缺失项并等待，无 docs/aftertaste 写入 |
| B02 | 给 fixture commit，“范围 src/，逐批阅读，你安排第一批。我会写简单接口，想看职责和取舍。”后续“继续” | 复用范围／节奏；先读约束／教学资料；实际 pin/read、选批、登记、骨架、正文、逐篇检查、补边、方向；每批交付后停；工作区新增文件不进入范围 |
| B03 | fresh fixture，同一 commit、范围 src/，“连续生成到范围完成” | 按批完成固定树内三文件，无理解／标记门槛；support/audit 只为依赖节点，不能生成讲解；明确无反馈时观察为空 |
| B04 | B02 已有同版成果后，“继续”；再给与既有资料不同的有效提交或 fixture 的第二提交 | 已完成文件不覆盖；版本冲突说明并停依赖写入，图、current、偏好和方向字节保留 |
| B05 | fresh fixture，指定不存在的完整提交；另给同版本次已创建且空正文的骨架，实际运行校验 | Git 失败不改用工作区，不写已讲；空正文诊断不算完成；明确本次归属才可续填，ID 保留；不可确认的既有骨架保持原样 |
| B06 | B02 真实用户反馈“例子还是少，我需要从输入到结果的完整过程”，再次同类反馈；另给与明确要求冲突的反馈；只提问“为什么这里要单独一个 service？” | 下一批前维护偏好，先核要求落实，重复合并同主题、保留依据、冲突询问；只提问不改讲解。无虚构计数、置信度或已解决状态 |
| B07 | 相关文档校验存在真实错误或图未核对状态 | 按诊断报告部分完成；区分机械有效、正文有无、teachingQuality=unchecked 与图 unreviewed，不能凭退出 0 宣称整批成功 |

场景可组合，记录用户消息顺序与产物前后哈希，不要求固定问句、标题、文件分组或 Markdown 文风。指南不承担复杂权限系统，测试针对实际代理遵循情况。

## 证据要求

记录 Skill 候选提交或文件哈希、实际宿主／模型（无法取得精确版本则写明）、Node／Git／CLI 版本、目标固定提交、输入、命令、退出状态、文档 contentStatus/sourceCheck、图节点状态、产物路径和未覆盖项。正文核源码事实、偏好落实、可读职责与取舍。机械校验与教学判断分别说明。

独立开发审查使用 D010 task、固定候选、相关规格与实际证据，由另一个未参与实现或模拟使用的代理进行。

## 局部答疑与修订试用

用订单图的 start、resume（同源块 m3vuiqzi）和实际浏览器粘贴定位。新讲解会话显式加载候选 SKILL.md，仅使用有独立 Git 的订单副本。依次问「建立对象时，集合已经变了吗？可以用空集合举例吗？」；收到建议再答「好，把这个例子补进刚才的步骤。以后讲集合变化也想看前后的条目数。」；粘贴文件块定位说「改一下这段，用一进一出的例子讲清建立与追加」。另给不匹配提交，请改写。每轮核资料文件名单、字节摘要、原出处，核重开后目标讲解、旧摘录、个人标注和布局。首次只问不可写，明确长期要求可进入共用偏好；错误定位不可猜写。
