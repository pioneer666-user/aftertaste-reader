# D044 · 阅读器五套主题与全站用色核验

## 目标与批准依据

实现任务。读者读到订单闭环第 03 步，能从顶栏「主题」切到深黑，接着读刚才的句子。两张图、六个页面、已经打开的阅读栏和笔记编辑器随之换色。再切回浅绿，仍能辨认自己点的是哪个文件、哪些文件经过所选闭环、哪个块标了「不理解」。下次用同一浏览器打开同一站点，沿用上次选择。

[B006](../../../../product/backlog.md#b006--个人阅读记录做完后查漏再集中优化页面) 已定暖色、科技蓝、浅白、深黑、现有浅绿，共用一套布局与操作。2026-11-23，作者在主脑会话指定「用主题这个按钮」，要求实际执行时把该随主题改变的地方「找全，让审查也是仔细找找」。主脑提出以现有浅绿建立基线、用语义颜色 token 支撑五套固定主题、独立复扫全站并实切六页五主题，作者答「可以，这个任务需要很细节很深入，你出任务吧」。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

**选择和记忆。** 在顶栏「界面语言」旁提供「主题」按钮（英文 Theme）。打开即能认出五项的名称和当前项，选定后全站当场生效。沿用现有顶栏风格、焦点与菜单操作，窄窗及较长英文名下仍可用。首次使用浅绿；用独立的浏览器站点偏好保存选择，参照 `src/web/i18n.ts` 的语言偏好读取和异常处理。重新打开恢复有效值；值无效时用浅绿。存储受限时当页仍可切换，保存状态如实反馈。主题、语言各自生效。切换期间保留当前页面、阅读位置、闭环步骤、图的视野与分组、笔记草稿与编辑会话。键盘焦点可随主动选择回到主题按钮。主题操作只写浏览器偏好；项目教学偏好、个人资料、站内前进后退和布局保存均沿原用途。

**五套配色怎样落地。** 先以相同订单内容核现有浅绿的正文层次、图上状态和浮层，再把原有颜色迁到按用途命名的 token，最后补齐其余四套值。优先用文档根上的 CSS 自定义属性供页面、浮层、SVG 和绘图共用；Canvas 等实际需要颜色值的地方从同一主题来源取值并重画。可在设计时生成色阶，由执行在真实内容上调色，固化五套经过检查的值。暖色应能辨出温暖的纸面与强调色，科技蓝用于主要操作和当前项，浅白保持中性层次，深黑适合连续阅读，浅绿以版前订单页为对照。若为提高可读性调整浅绿个别颜色，在回执说明位置和依据。首版离线导出、在线调色器与自定义配色不属本单。

先按**含义**区分颜色，再决定哪些值能共用。例如科技蓝主题的主要按钮可以用蓝色，「已理解」仍有绿色与 ✓，「不理解」仍有红色与 ?；同个文件既是闭环参与文件又被当前点选时，两种状态都能一眼读出。覆盖页面底色和各层表面、正文与次要文字、源码板与行号、边线、强调色及其上方文字、链接、焦点、选文、悬停、选中、禁用、错误／警示／成功，以及图和笔记特有的角色。对照实际半透明叠层、阴影及渐变检查最终颜色。按需沿用局部变量映射到共同角色，避免按色值机械替换、以组件数量复制五份样式。

## 验证与停点

1. **对照同一份订单。** 从 [D043 试读副本](../D043-reading-qa-and-revision/handoff.md) 取得独立输入，以当前 D043 固定构建或同基线构建留下浅绿参照，记录浏览器、视口、页面与状态。建议取同一文件的正文／源码、已选路线的依赖图及打开的笔记三处。迁移后按同一状态比较，留意底色发灰、浮层过透、图线消失和新增按钮引起的遮挡。新候选另用空闲本机端口。原试读端口和作者资料保持各自用途。
2. **五套主题 × 六个页面。** 在 Edge 用有内容的文件讲解、文件依赖图、闭环阅读、书签、标注和笔记逐一实际切换五主题。回执用六行五列汇总，每格可回溯到所用场景、观察和证据；同一份接触表或串行操作记录可覆盖多格。打开后再原位切换，另试深黑→浅绿。核状态和几何延续，特别看已展开的第 03 步、已选文件、笔记编辑草稿和回访；分开核主题操作的站点偏好与项目数据写入。复验刷新、重开、存储不可用和旧／无效值。桌面和约 390 CSS px，补顶栏断点附近英文排列、键盘打开／选择／取消与可见焦点。
3. **三条现场必查路径。** ① 已经选中订单闭环及一个参与文件时切换主题，在同一视野确认文件与库节点、路线成员、直接关系、箭头、分组、点阵、小地图都立即换到正确颜色，两种叠加状态仍可辨。检查首次重画，不能靠拖图或刷新让旧色消失。② 在《订单步骤核对》及随手记使用真实引用，切浅白／深黑检查编辑光标、选择、标签和预览，点引文回第 03 步，再后退接着读。③ 在同一规则块对读书签、标注，试悬停、键盘焦点、选文浮条和实际错误／恢复样例；用原生绘制与 Firefox 回退查看已打开区域的即时颜色。其余主题复用同语义色对的自动检查，遇独有颜色或绘制差异补实测。
4. **可读性核数值，也核实际像素。** 五主题按实际配对测正文／背景至少 4.5∶1，大字至少 3∶1；用于辨认控件、焦点、状态或理解图形的必要视觉线索，与相邻颜色至少 3∶1。结合最终叠层算前景与背景，记录每套主题风险最高的实际色对、所在表面和结果。禁用控件、装饰点阵和阴影按各自用途处理。系统强制色下保留系统色、选中形状、焦点和可操作性，颜色之外的符号、线型或文字仍然可用。[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [控件与图形对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
5. **关掉既有 Firefox 验证缺口。** [D042 的 Firefox 记录](../D042-loop-route-highlights/handoff.md)在 `tests/browser/dependency-canvas-selection.mjs` 的顶栏颜色断言停止，双图菜单专项已有自己的结果。先在 Firefox 看实际当前页、悬停和焦点，核 SVG 圆角与系统强制色的绘制路径；如确属旧断言读错表面，换成能检出视觉倒退的等价断言，在同场景单独辨认三态。随后跑完整脚本直至实际框选、成组及该用例结束，分别报告原失败与框选结果。若页面本身有缺陷就修产品。Edge 主验、Chrome 与 Firefox 复核各自受影响路径；浏览器与用例串行，复用 `reader-center.mjs`、`loop-route-highlights.mjs`、`loop-note-revision.mjs`、`record-details.mjs` 等已有入口，补主题专项与类型检查、生产构建。遇失败沿共同两轮停点。
6. **独审自己找漏。** 执行冻结提交、构建和输入后交独立审查者。审查先在固定候选独立枚举前端颜色来源、真实渲染路径和测试中的固定颜色假设，再与执行方清单对照，核剩余固定色和第三方默认色的用途。审查在自己的订单副本实际操作六页五主题，重点复现上面三条路径、存储退化和 Firefox 原失败链。报告写清自己实走的页面／状态、使用的浏览器、剩余固定色例外、发现与复核；用执行方已有证据的地方注明出处。读到变量变了、组件重新挂载后的截图或单张首页图，均不足以证明已打开的画布和弹层当场换了颜色。
