# D050 · 首次选择讲解方式的调整

## A1 · 偏好只留当前有效的讲法

2026-11-24，作者在主脑会话明确「我们只要只留最新的就行」「偏好首先是一个独立的文档文件」「替换后AI直接用这个新的偏好去讲解」。本调整替代[原单](task.md)（`9360af8`）中换档时保留被替换旧讲法原句的要求，适用于 `eb1bd1f` 后执行收到调整的首个产品候选。[原两轮独审和失败证据](review.md#旧偏好并存路径)按当时口径保留。

项目继续使用独立的 `docs/aftertaste/preferences.md`。读者明确更换项目讲法时，更新同一份文档，删除被取代的讲法，不留历史副本。旧句同时包含仍有效的信息时，保留这部分。例如「我懂基本语法，今后先讲简单版本」在换成第 3 档后，仍可保留「我懂基本语法」。独立的「保留控件英文」继续有效。当次简述只作用于本次，长期反馈沿已有偏好维护流程更新相应内容。作者提到的可分享、整份替换的风格模板留待后续设计。

沿原任务续修这一处，统一写入、读回及受影响的验收表述。复用原合成前端项目和中性提问，先从旧第 2 档明确改选第 3 档，再在新会话询问筛选结果如何得到。核偏好文件只含当前讲法，仍有效的基础、控件文案要求及独立观察均保留。再读实际正文，核读者能沿调用方、筛选规则和返回结果追到页面更新。此前 `NP1` 已展示符合新决定的保存结果，但没有接着运行中性新会话；该次结果可作对照。受影响项按新候选复验并独审，其余证据按版本与影响复用。执行继续负责本分支的提交和回执。

## A2 · 同一讲法用于文件与闭环时的侧重点

2026-11-24，作者明确「这个更适合放到初始模板里面」「三类，自己是小白还是老手，主要影响的是文档讲解，当然闭环图也会受影响，但是影响程度小」「闭环图里面的重点就是去回答了，多去回答为什么」。本条细化原单的三档定义和「按真实代码施教」条款，与 A1 一起适用于执行收到调整后的新候选。沿普通生成与闭环制作已有入口落实。

- **通用讲法和个人偏好。** 把下段作为产品内置第二档的起始讲法，与三档定义同处维护。首次选择仍给三条简明选项。项目偏好记当前选择，以及读者明确表达的基础和个人要求。例如读者说「我会 Python，读其他语言时希望用熟悉的语法作对照」，就可以在确实有帮助的地方作简短对照，点出会影响理解的差别，再回到目标项目的真实代码。单凭选了第二档不推定其熟悉的语言。

  > 我会写基本功能，想学会读真实项目的架构。请从眼前这个功能里，挑一个我用简单写法也能完成的地方。顺着一次真实调用，告诉我这个项目多分出了哪一步、谁负责它。再举一个具体变化，让我看懂这样拆能省什么事，又增加了什么成本。熟悉的语法可以略过。源码只能证明调用关系时，就讲到调用关系；设计动机属于推测时请点明。

- **文件正文以讲代码为主。** 读者只指定文件也能从头往下读。按源码顺序覆盖各块，相邻几行共同完成一件事时连起来讲，在决定行为的具体语句讲清值、条件和结果。第一档在这里展开基础与例子，第二档在确有分工的关键处用初始讲法解释设计，第三档压缩熟悉语法，把篇幅给本文件的职责、调用和边界。
- **闭环串讲以回答路线上的问题为主。** 沿已经确认的目标，在关键步骤和连线上解释为什么会得到这个结果、哪条路径走不到及源码依据。档位只调术语说明、例子和详略。同一条路线在三档下都要能回答同一个问题。沿用已有路线选择，AI 可以随路线提出它能回答的问题。使用现有串讲、步骤和连线说明即可。
- **交回实际对读。** 复用已有订单样例，在新候选中并列给出同一段代码的文件正文和一次保存后的闭环读回。例如文件讲清数量校验、追加订单及其顺序，闭环回答「为什么数量非法时会返回 400，订单却一条也没多？」并串起入口、规则和写入点。结合原三档证据，复验本轮改动影响的正文，由执行调用独立审查子代理复核新候选。A1 的换档跨会话场景独立验收。
