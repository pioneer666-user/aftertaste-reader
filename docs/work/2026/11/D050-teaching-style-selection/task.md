# D050 · 首次生成前选择讲解方式

## 目标与批准依据

实现任务。用户第一次请回味为当前项目写文件讲解或生成闭环时，讲解 AI 先问「这个项目，你希望我怎么讲？」，给出三种可直接选的讲法，等用户回答。选定后，同一项目的两个生成入口沿用这项偏好，结合实际源码组织讲解。

2026-11-24，作者指出主要读者「会基础的，但是不会特别深」，希望第一次使用就能选好适合自己的讲法。作者给出三类读者：「纯小白」「有一定基础，但是没做过那种工业级的架构」「老手，只希望看文件依赖关系，希望理清架构思路」，并确认「可以，先补这个，你出任务吧」。Python 接口和 ORM 是作者说明自己基础的例子，用户选定的项目可以采用任何语言，也可以跨语言。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。遇到已不支持的旧文档格式，识别脚本只负责报错或警告，让使用产品 Skill 的 AI 知道哪个文件受影响、原因是什么。AI 按当前 Skill 的正常生成、校验流程改好或重做相应讲解、闭环，无需维护逐版迁移脚本或另写兼容指南。实际改写或删除作者资料仍按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

仓库 `D:/project/SpecDev Harness/aftertaste-reader`，基线 `dev@1267e95`，分支 `codex/feat-teaching-style-selection`。任务批准提交见派单消息。本单的选择入口在讲解 AI 的对话里。

| 给读者的选项 | 实际讲出来的区别 |
| --- | --- |
| 1 · 从基础讲起 | 结合眼前这段代码，用日常语言解释关键语法和概念。用一个小例子带读者从输入走到可观察的结果，说明第一次遇到的术语。 |
| 2 · 我会基础，想弄懂项目为什么这样设计 | 从读者会写的简单版本或一个容易理解的等价场景切入。指出本项目多出的模块、接口或中间步骤各承担什么，举一个具体变化说明拆开有什么用、付出什么成本。源码仅能证明转发时就讲到转发；推测的设计动机标明依据与不确定性。 |
| 3 · 我熟悉技术，想理清依赖和架构 | 围绕谁依赖谁、边界在哪里、关键路径如何跨文件展开来讲。保留能说明分支或设计取舍的细节，省去常规语法教学。单文件没有项目内依赖时，按实际职责和调用方讲。 |

- **先选择，再生成。** 明确目标项目后，可只读查已有偏好。项目缺少明确选择时，在开场给出三项及各一行效果说明；已知的项目、范围、节奏或阅读目标直接复用，其他必要问题可以同轮问。等待期间只读取必要信息，首次文件讲解、闭环成果和项目教学资料的写入均在答复后。用户直接点名某一项、用自己的话明确选同一种讲法，或主动说「按默认讲」，都算回答。第二项作为主要受众的推荐／默认，提问时说清含义，沉默不会选中它。
- **一个项目共用一次选择。** 沿用 `docs/aftertaste/preferences.md` 的用户明确要求区记录，保存方式接入已有授权写入时点。保留旧文件里的文字、细化要求及独立的 AI 观察。缺文件、空模板、「未说明」或只有 AI 对读者水平的推测都属于尚未选择。旧偏好或当次明确要求已无歧义地选了同一种项目讲法，可直接复用。后续批次、换会话、文件与闭环互切均读回；另一个项目使用自己的选择。「这一段讲短一点」按当次要求处理；明确换项目讲法后对后续生成生效。单纯提问、浏览已有成品或重读已保存闭环仍可直接进行，生成闭环原有的路线选择继续有效。
- **按真实代码施教。** 从固定提交读取实际涉及的文件，按各段语言、框架和项目领域选例子。Java 工程用该工程里的类与调用解释，前端项目可以从组件、状态或事件解释，跨语言路线按真实边界衔接。用户只选讲法；讲解深度和架构重点应能从最终正文辨认。
- **落点。** 在[产品 Skill 入口](../../../../../skills/aftertaste-reader/SKILL.md)、普通生成与[闭环制作](../../../../../skills/aftertaste-reader/references/loops.md)共用一份三种讲法的定义；同步[教学方法](../../../../../skills/aftertaste-reader/references/teaching.md)、[偏好维护](../../../../../skills/aftertaste-reader/references/feedback.md)、[偏好模板](../../../../../skills/aftertaste-reader/assets/templates/preferences.md)和受影响的初次使用说明。按 Spec Kit v1.4.0 的 `speckit-specify`／`spec-template` 增量更新 [005 普通生成](../../../../../specs/005-generation-skill/spec.md)、[008 闭环制作](../../../../../specs/008-loop-authoring/spec.md)及 [08 现行流程](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)的受影响条款，特别是旧的「范围和节奏已知即可开始」与「偏好为空可直接讲」。方案或偏好结构有变化时按 `speckit-plan`／`plan-template` 同步已有设计。

## 验证与停点

1. **实走首次对话。** 按[现有 Skill 行为检查](../../../../../tests/skills/generation.md)，在干净会话显式加载候选安装包里的 Skill。普通生成用已给足范围、节奏的合成项目；首次从闭环进入时用已有有效文件块和依赖图、已有明确路线但尚未选讲法的合成项目。分别记录第一句实际提问、停等时项目资料的状态、用户选择后的产物与校验读回。单纯在指南中搜到三个选项不能代替对话验证。
2. **看讲法是否真的不同。** 用同一小段有实际跨模块关系的合成源码对照三种正文，指出初学者会在哪读懂概念、中间读者会在哪读懂多一层的原因、熟练读者会在哪看清依赖和边界。再用另一种语言或跨语言的小路线核查例子确实来自目标文件。至少包含一个非 Python、非后端的场景。生成代理只接收使用者会给的信息，参考答案留在核验侧。
3. **验选择的寿命。** 核旧模板和已有个性文字的偏好文件、显式接受默认、换项目、临时要求及文件→闭环／闭环→文件两个方向的复用。至少一次在新会话读回同项目选择。保存闭环后用 `read-loop` 查实际成果，并验证重读或单次答疑不强制选档。[已有闭环行为样例](../../../../../docs/work/2026/11/D015-loop-authoring/sample/session.md)
4. 只用仓内合成项目；测试串行，运行材料放 `.local/D050/<run-id>/`。冻结候选后由执行调用独立审查子代理，复核首次停等、三档实际差异、真实源码依据和项目偏好保护。回执提供作者可直接试的首次提问场景、同段代码的三档试讲及文件／闭环读回入口。
