以下前三项由主脑在 `dev@4d7d94e` 对应源码的隔离构建中复现，环境为 Windows、Node 24.11.1、Git 2.50.1.windows.1。后两项已核源码；未实跑其他系统。

| 编号 | 当前事实与重建要点 | 本单必须达到的结果 |
| --- | --- | --- |
| H01 固定提交身份 | SHA-1 合成仓库创建 A/B，建立名为 64 个 `a` 的分支。用该名称作为 read 的 commit，分支指向 A 时返回 `A\n`，移向 B 后返回 `B\n`；两次 CLI 均退出 0，报告相同 commit 字符串 | read 核对实际完整提交身份，拒绝把可移动引用冒充固定提交；后续对象读取始终沿已核定的不可变依据。有效 SHA-1／SHA-256 完整提交仍可读取，pin 仍可解析本地版本名 |
| H02 历史子项目 | pin 仓库内 `packages/demo` 的 A 后移走整个 demo 工作目录；仓库及 A 的文件对象仍可由 Git 读取，service.read 却报 `PROJECT_UNAVAILABLE` | 使用已固定的仓库根、项目相对路径和提交读取，当前子目录消失不阻断；共用用例与真实 CLI 均提供这条可用路径。pin 首次定位仍核现存项目；仓库／对象确实不可用时准确失败 |
