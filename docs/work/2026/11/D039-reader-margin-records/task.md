# D039 · 文件讲解页的页边书签与理解标注

## 目标与批准依据

实现任务。读者正在看「服务随后忽略这个返回值」时，可以在这一块旁边收藏或记下疑问，收起后接着读原句。下一块的位置、当前句的换行和阅读位置在整个过程中保持稳定。

2026-11-22，作者在文件讲解页试读后指出，书签、理解状态和批注希望「只在用户有需要的时候才展示出来」，并要求「不要挤页面，导致页面跳动，布局位移」。作者认可双页边入口与覆盖浮层的演示，进一步提出红色问号和绿色已理解标记。主脑说明未标记采用中性灰空心圆，已有批注的未标记块仍可辨认；作者确认「行，那就这样了，你出任务吧」。本单替代 [D022](../D022-reader-navigation/task.md) 在正文下方常设控件和就地撑开编辑器的安排，沿用其按原记录回访的结果。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

仓库 `D:/project/SpecDev Harness/aftertaste-reader`，基线 `dev@3894db8`，任务分支 `codex/feat-reader-margin-records`，批准提交随派单提供。4341 的版前实测来自 D038 受审构建 `da10bbc`（回执提交 `ac91232`）；其笔记工作台独立待验。这一批改文件讲解页里的源码对照块、纯讲解块及从管理页回到它们的落点。书签／标注管理页的布局、选区浮条与右上笔记列表沿用现状。

1. **在块边就能找到记录。** 原块尾的两排控件及其占位收掉。在讲解右侧页边放两个有独立名称的图标「书签」「理解标注」，与块开头的复制操作、原生选文及选区浮条错开。桌面细指针移入该块或键盘聚焦该入口时显现，移过正文只显示入口；点击才开浮层。长块读到中段也能就近操作，入口始终对应所读的块。已有书签常显书签图标与条数，已标理解状态或已留批注的入口常显。空块在触屏保留可发现、可分别点中的入口（每项至少 44 × 44 CSS px）。
2. **理解状态的颜色和形状同时表达含义。** 未标记用中性灰 `○`，不理解用红色 `?`，已理解用绿色 `✓`。颜色限图标；悬停、键盘聚焦和辅助技术都能读出完整名称。仅有批注、尚未自评时，常显中性的批注图标，可辨「未标记，有批注」。打开标注浮层可直接点选三态，选择即保存；可以独立查看、填写、编辑或清空批注，批注显式保存。改状态保留原话。系统强制色下仍可从形状与文字区分三态。
3. **打开就能处理当前这条。** 空块点书签直接进入可选收藏理由，可直接保存空理由书签。已有书签则先显示各条原理由，提供「再加一条」与逐条编辑、移除。每次针对该条书签的身份，保留同块的其他书签。书签理由、理解状态与批注分别沿用原有保存语义；单纯开合、查看或切换入口零写入。
4. **浮层覆盖，阅读原位。** 桌面用贴近块边的非模态浮层，窄窗贴底覆盖，层内标出对应块。复用讲解页连续圆角；长理由、长批注、多条书签在浮层内可读可操作。页边记录浮层一次只开一处，正文仍可阅读、选文和滚动。切换类型、打开输入框、保存反馈及关闭都不撑高块、不挤窄正文、不添历史步骤。Esc 或显式关闭回到原入口，点到正文可自然继续读。在同一次页面会话，切入口、收起或暂离原块后，回来能续写该块该条草稿；主动取消才放弃本次编辑。真实失败留下原稿、错误和重试，不能以收起浮层冒充保存成功。
5. **从管理页回访直达原话。** 从书签列表或详情回原文，自动打开目标块的书签浮层，显示并聚焦所选的那一条；从「不理解」回原文，直接显示该块的状态和已有疑问。显式回访可滚到目标，随后操作浮层保持原位；站内返回恢复管理页原筛选、选中项及位置。目标失效时保留已有记录和提示。

**实施入口。** 依据 [08 现行规格 R14、R15](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)、[006 User Story 6、FR-010、014—017、SC-008](../../../../../specs/006-file-reader/spec.md)、[010 块级书签](../../../../../specs/010-block-bookmarks/spec.md)及 [012 理解标注](../../../../../specs/012-understanding-marks/spec.md)。按 [Spec Kit 增量流程](../../../../development/spec-kit.md#incremental-input)在 006 使用 specify、plan、tasks 及各自生效模板更新这次呈现与验收，analyze 核一致后 implement；010、012 复用现有数据契约、并发语义和回访身份。同步[阅读器使用说明](../../../../usage/file-reader.md)。从 `src/web/ReaderDocument.vue`、`BlockBookmarks.vue`、`BlockUnderstandingMark.vue` 入手，接续 `bookmark-drafts.ts`、`mark-drafts.ts` 与 `App.vue` 的回访。视觉沿用 [D029 的连续圆角](../../../../../specs/006-file-reader/plan.md#d029-连续圆角)，按[项目技能适配](../../../../development/skills.md)使用 Ponytail full 和 Impeccable。浏览器回归归 `tests/browser/`，固定证据及试读副本归 `.local/D039/<run-id>/`。

## 验证与停点

1. **量正在读的句子与下一块。** 版前在 4341、1440 × 900 Edge 的 `src/service.mjs` 首块 `zhidif44`，两组控件收起时块尾高 101 CSS px；两个编辑框都打开后，下一块相对首块下移 402 CSS px。候选在同一句「服务随后忽略这个返回值」旁依次显现入口、开书签、切标注、写两行、保存、关闭，逐步比较句子位置与换行、阅读区滚动位置、下一块起点，预期操作引起的位移为 0 CSS px。补一段长块，另在 390 px 触屏模拟下核入口命中和贴底浮层，区分用户主动滚动及软键盘引起的视口变化。留版前／版后实图和实际坐标。沿[阅读中区回归](../../../../../tests/browser/reader-center.mjs)更新旧块尾定位断言，保住块复制／选文操作。
2. **少点一步，同时保住原话。** 在隔离副本上分别验证空块、两条同块书签及仅有批注的未标记块。收藏空理由、添加第二条、改或移除其中一条，核另一条原文；选「不理解」、写批注、改「已理解」、再选「未标记」，各阶段核颜色、形状、批注原文、重开读回。走一次未保存时收起并找回及一次真实写失败后重试；验证点外、Esc、Tab、触屏及强制色的反馈。复用[书签](../../../../../tests/browser/bookmarks.mjs)和[标注](../../../../../tests/browser/understanding-marks.mjs)的草稿、冲突与磁盘断言，按受影响入口串行适配。
3. **从所点的记录回到原块。** 沿[阅读导航](../../../../../tests/browser/reader-navigation.mjs)和[工作台回归](../../../../../tests/browser/record-workbench.mjs)，在 `src/rules.mjs` 的 `x4y6az2y` 分别回访两条书签，辨认「这个边界例子讲得巧」及另一条的原话与焦点；从「不理解」回访「为什么要先校验数量？」，后退回原筛选。取有源码块及纯讲解块，另核切篇时已有草稿归属。沿用原来真实操作的保护断言，替换依赖旧表单位置的步骤。

自测与独审各用[共用试读的独立副本](../../../../../tests/README.md#页面改版共用试读)，写入、移除与失败注入均在副本进行。由执行冻结候选、构建与输入后派独立审查子代理，实走几何稳定、三态与仅批注的可辨性、草稿和精确回访。若实现需要改现有记录格式或无法确定回访的是哪一条，先交回该处证据；两轮修复验证仍失败按共同停点处理。
