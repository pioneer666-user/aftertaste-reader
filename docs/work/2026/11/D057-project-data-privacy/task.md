# D057 · 生成资料前确认 Git 可见性，保存个人记录时保留权限

## 目标与批准依据

实现任务。读者决定哪些回味资料可以进入 Git 的日常提交流程；讲解 AI 在第一次可能暴露资料的写入前停下来。读者将笔记设为仅本人可读后，在阅读器里再保存，其他本机账号也不能因此多获得读取权限。

2026-11-26，作者为 alpha.2 发布前安全维护批准「必须获得用户授权才能继续，至于到底是忽略不忽略，这个由用户自己取舍」「你出任务吧，先修这两个」。第二项指笔记、书签和自评／批注在安全替换文件时可能放宽权限。作者还询问如何记住选择；本单给读者“仅本次”与“本机记住此项目”的选择。只批准这两项和必要验证，发版决定另行作出。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。遇到已不支持的旧文档格式，识别脚本只负责报错或警告，让使用产品 Skill 的 AI 知道哪个文件受影响、原因是什么。AI 按当前 Skill 的正常生成、校验流程改好或重做相应讲解、闭环，无需维护逐版迁移脚本或另写兼容指南。实际改写或删除作者资料仍按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

桌面是主要阅读和操作环境，交互与视觉细节优先在桌面打磨。手机默认只需能打开讲解或图，读到主要内容，需要时可滚动查看。新功能可以只在桌面提供，例如画布编排。手机专属布局、精细手势和逐项体验验收仅在当次明确需要时安排。

### 讲解 AI 什么时候必须停下来

1. **先查本批实际会写的路径。** 用随包工具统一确认目标项目在 Git 工作树中的位置、索引和有效忽略规则，返回「已忽略且未跟踪」「未忽略、可能加入提交」「已跟踪」或可处理的检查失败。核尚不存在的文件、嵌套规则与反选、仓库本地排除和用户全局忽略。已暂存或跟踪的文件即使匹配忽略规则仍须报出。固定源码读取刻意[隔离用户 Git 配置](../../../../../src/adapters/git-source.ts#L13)，该路径继续沿原规则；隐私检查须反映用户平时在这个仓库的实际 Git 行为。[Git 忽略规则](https://git-scm.com/docs/gitignore)
2. **第一笔资料写入前就生效。** 普通生成、闭环制作、偏好和阅读方向维护、同提交修订均走同一判断。包含 CLI 造骨架、AI 直接填正文及同批附带的图资料；先写偏好、临时素材或空骨架再提问均不合格。纯问答、只读核查和重读已有资料可以照常进行。D050 的讲法选择可在聊天中先完成，选择讲法本身不授予 Git 可见性许可。若写到批中新增的另一类路径，先核新范围。
3. **用户能据实选择。** 全批已忽略且未跟踪，直接按原授权生成。否则，若没有覆盖此次范围的有效明确授权，点出实际相对路径或可辨认的路径组，区分哪些可能被加入、哪些已经在索引里；说明有仓库权限的人在提交并推送后可能读到什么。允许「仅本机忽略后生成」「保持现状并允许生成」或先停。未答、拒绝、选择含糊或工具无法判清状态时，依赖写入保持为零。Git 可见性授权只许可生成或修订回味资料，不包含暂存、提交或推送。

   例：「这次会新建 `docs/aftertaste/current/…` 的讲解和一份依赖图。它们目前没有被 Git 忽略，以后提交并推送时，团队成员可能看到。你希望只在这台电脑忽略这些资料后再生成，还是保留现有 Git 设置、允许我继续生成？」实际目录部分已跟踪时须换成对应提示。

4. **选择忽略后，复核结果再写。** 解释本次会改动的本机排除规则，按用户选择只处理已说明的范围，保留其他规则；正常入口优先使用本仓的本地排除文件，团队共享的 `.gitignore` 需用户明确指定。只要有目标文件仍受跟踪或仍未忽略，就定位给用户，由用户决定是否明确允许继续。不得代为移出索引、清理历史或改远端。该选择不会撤回已经传出的文件。
5. **授权记在本机，由读者控制。** 忽略事实直接从 Git 读取。一次放行只覆盖当前批次；用户明确要求下次沿用时，把许可存在目标仓库以外、当前系统用户的回味状态目录，Windows 推荐 `%LOCALAPPDATA%\Aftertaste Reader\state\`。按实际仓库和目标子项目绑定，只记必要的项目标识、获准的路径范围与可见状态；不保存正文、聊天、令牌。用户可以通过讲解 AI 改选或撤销，下一次写入生效。每批重新查实际 Git 状态；范围扩大、可见性超出原许可、换项目或没有可核的记录时重新问。仓库内的偏好、克隆来的文件和模型记忆都不能自行批准。无法保存长期许可时据实告知，本次明确放行仍可完成。

### 笔记、书签和自评的保存

沿三个存储器共用的 [PersonalFile.save](../../../../../src/adapters/personal-file.ts#L47) 修复。新建个人记录使用当前用户私有的访问范围（保留系统必要访问）；更新已有记录时保留原有访问限制和用户明确的共享权限。包含正文的临时文件从第一字节起就受相应保护，不能先公开写完再收紧。保留同目录原子替换、并发冲突检查、链接拒绝和失败时原文／原权限不变，页面沿原入口保住未保存草稿。保持现有 JSON 和资料位置，不改目标仓库或父目录权限。POSIX 核文件权限；Windows 在 NTFS 核实际访问控制列表（ACL），只读属性或 `chmod` 不能证明其他账号的读取权限。[Windows 文件替换与权限](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)

## 验证与停点

- 用安装包在独立目标仓和隔离的用户配置目录验证。无规则的项目请 AI 生成第一批，展示实际提问；未答和拒绝时项目资料及 Git 配置不动。分别验证选择本机忽略、仅本次允许、明确记住后在新会话沿用，以及撤销后再问。用部分忽略／已跟踪混合的老项目修订一篇讲解或生成闭环，核提示与 Git 实际状态一致。覆盖全局忽略、例外路径和同仓不同子项目，检查不会暗中暂存或提交。保留提问、答复和前后状态作为证据。
- 通过笔记、书签、自评三条正常入口保存并读回。在独立 NTFS 目录用宽松的父目录权限和具备明确限制的旧文件验证；在实际 POSIX 文件系统用较宽的创建默认值和仅本人可读写的原文件验证。比对首次创建、再次保存、临时文件保护及一次失败保原场景。记录平台与结果；缺平台就标未验，不把 Windows 模拟的权限位计作 POSIX 实测。
- 测试落 `tests/unit/`、`tests/integration/`、`tests/skills/` 及必要夹具。串行构建、类型检查、全仓回归；复核 D056 的访问保护和个人记录读写。使用 `.local/D057/<run-id>/`、独立资料及空闲端口；保留现有真实服务和试读资源。若某文件系统无法安全更新既有文件，给出可定位原因并保留原件。
