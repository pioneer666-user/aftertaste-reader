# D040 · 书签原位编辑与紧凑标注浮层

## 目标与批准依据

实现任务。打开页边书签，点一条收藏理由旁的铅笔，就在那一行改字；打开理解标注，一眼分清哪里切换状态、哪里保存批注。两种浮层共用紧凑的编辑布局和阅读器已有的连续圆角。

2026-11-22，作者在 [D039 试读](http://127.0.0.1:4342/) 的两张截图中指出「首先连续圆角给我换上」「目前的按钮很占地方」。主脑给出可操作草图，演示书签原位编辑、逐条草稿、三态分段选择及输入框内的文字操作。作者确认「行，你出任务吧，把这个做好」。[讨论中认可的排版示意](reference.png)供执行对照；图中并排展示两种编辑场景，产品在当前块仍一次打开一个浮层。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

仓库 `D:/project/SpecDev Harness/aftertaste-reader`，基线 `dev@475b6b4`，任务分支 `codex/feat-margin-record-editors`。批准提交随派单给出。本单处理文件讲解页的书签、理解标注两种浮层内部及其外框轮廓。页边入口、桌面贴边／窄窗贴底、管理页回访、正文原位及资料格式沿用 [D039 回执](../D039-reader-margin-records/handoff.md)。

1. **书签从所点的那一行开始编辑。** 顶栏保留块标题，将「再加一条」移到标题栏的 `＋`，与关闭 `×` 明确分开。每行展示完整理由或一次「无备注」，行尾放铅笔和「更多」；移除放进该条的更多菜单。点铅笔后，输入框和操作替换原行，光标进入原文。其他条目仍可读、可切换编辑，`＋` 可进入或找回新增草稿。空块打开即能保存第一条，收藏理由可空。
2. **每条草稿都能找回。** 编辑已有书签，仅在文字与进入编辑时的原文不同后才显示「未保存」，改回原文即撤下提示。新建空理由仍可显式保存。切到另一条或新增项、关闭、Esc、点外后再打开，各草稿仍对应原记录。输入区右下同排放轻量文字「取消」和主要文字按钮「保存」；取消只放弃当前条的改动，保存只提交当前条。回访按书签 ID 聚焦。对有未提交改动的条目保留移除保护；冲突时可同时核对已存原话和本人草稿，失败时可见原因并可重试。
3. **标注的一条状态栏，一处批注编辑区。** 灰 `○ 未标记`、绿 `✓ 已理解`、红 `? 不理解` 排在同一条浅色分段控件中，仅选中段单独提亮。文字和符号都保留，选择即保存自评。已有批注打开可读，进入编辑后在原处写，允许清空；「保存」只提交批注。切状态保留原批注和在写的批注草稿。`×`、Esc 收起留稿，「取消」才撤销本次编辑；查看及开关本身不写资料。
4. **紧凑的控件与完整的轮廓。** 外壳用面板档，输入区、记录行及小控件按表面职责复用 [D029 连续圆角](../../../../../specs/006-file-reader/plan.md#d029-连续圆角)。检查选中底、边线与键盘焦点，输入区聚焦时只有一圈清楚的外轮廓。现版外壳已有原生 squircle，Firefox 回退按声明 `--corner-size` 的选择器接入，须核实际绘制。桌面常用按钮约 32 CSS px 高，触屏每个操作保有至少 44 × 44 CSS px 的独立命中区。图标有可访问名称，悬停或键盘聚焦能读到用途；键盘可进出更多菜单、回到该条，再关闭浮层回到页边入口。长理由、多条记录和错误信息在浮层内可读可操作。

**实施入口。** 以 [08 的 R14、R15](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)、[006 FR-010、017 与 SC-008、016](../../../../../specs/006-file-reader/spec.md)、[010 块级书签](../../../../../specs/010-block-bookmarks/spec.md)和 [012 理解标注](../../../../../specs/012-understanding-marks/spec.md)为依据。在 006 依 [Spec Kit 增量流程](../../../../development/spec-kit.md#incremental-input)用 specify、plan、tasks 及对应生效模板维护本轮变化，用 analyze 核对后按 implement 执行；沿用 010、012 的保存契约。更新[阅读器使用说明](../../../../usage/file-reader.md#收藏讲解块与回访)中书签与标注的实际步骤。前端从 `src/web/BlockMarginRecords.vue`、`BlockBookmarks.vue`、`BlockUnderstandingMark.vue` 入手，复用 `bookmark-drafts.ts`、`mark-drafts.ts` 和连续角样式／回退。按[项目技能适配](../../../../development/skills.md)用 Ponytail full、Impeccable 检查编辑层次与实际视口。行为回归归 `tests/browser/`，运行输出归 `.local/D040/<run-id>/`。

## 验证与停点

1. **同块、同窗、同状态比对。** 在 4342 的受审候选 `013c6f6`，1440 × 900 Edge 打开 `src/service.mjs` 首块 `zhidif44`。当时标注编辑窗为 350 × 308 CSS px，已有一条书签时的编辑窗为 350 × 464 CSS px，两窗各有六个 40 px 高的可见按钮。用当时的作者试读副本再复制出隔离输入，用相同数据及步骤记录候选高度、按钮尺寸和版前／版后实图；重点看原条替换、重复理由和禁用按钮腾出的空间。另核 390 px 触屏命中、键盘与强制色，以及 Firefox 实际连续角、焦点和弹出菜单的可见边界。沿[页边记录回归](../../../../../tests/browser/reader-margin-records.mjs)对照输入、保存和收起时的原句换行、阅读区滚动及下一块起点，均维持 0 CSS px 位移。
2. **用两条书签区分收起、取消与保存。** 在隔离副本编辑 A、切到 B、再点 `＋` 输入第三份草稿。收起重开，分别找回；取消 B 后，A 和新增草稿仍可续写。核未改／改回时的提示、空理由保存、从更多移除指定条及其他原话仍在。刷新从项目书签回访所点条目，核身份、内容和焦点。沿[书签回归](../../../../../tests/browser/bookmarks.mjs)适配操作入口，保留磁盘、失败、重试与陈旧编辑的断言。
3. **区分自评与批注的提交。** 写一段尚未保存的批注时改选「不理解」，核只有状态已落盘。Esc 后重开能续写，取消还原原批注，再试显式保存及清空；有批注的未标记块仍可回访原话。沿[标注回归](../../../../../tests/browser/understanding-marks.mjs)以真实失败和双页冲突验证草稿及明确重试，核提示在紧凑布局中可读。

各项串行。自测与独审分别从 4342 的作者试读项目创建独立副本做编辑、删除、并发与故障验证。执行冻结提交、构建和输入后派独审，重点复走原位编辑、草稿切换、两类保存语义、真实轮廓和窄窗操作。若发现必须改写作者资料或改变保存协议，交回该处证据；同一问题按共同两轮停点处理。
