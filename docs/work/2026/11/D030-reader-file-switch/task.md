# D030 · 文件树切篇的即时反馈与阅读占位

## 目标与批准依据

类型为实现。在文件树点开另一篇讲解时，读者能立刻认出选的是哪一篇。读取很快时直接接读，等得稍久时正文就近给出目标文件和占位。读取成功、改点别篇、离开阅读页或读取失败，都有明确落点。

2026-11-20，作者试读 D029 后指出「我切换文件的时候，它会底层加载，然后瞬间就变页面内容。没有做那种响应，和加载占位」「我们开一单解决这个问题」。截图中包含 `api.mjs`、`rules.mjs` 和 `service.mjs`。本单聚焦从文件讲解页的文件树显式打开另一篇，包括键盘及窄窗操作。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

仓库 `D:/project/SpecDev Harness/aftertaste-reader`，基线 `dev@51ca38b`，任务分支 `codex/feat-reader-file-switch`，派单提交见交接消息。[D029 回执](../D029-reader-continuous-corners/handoff.md)记录现用构建 `138c401`、共用订单项目及验收过的连续圆角。

- **点下有回应。** 点击或按 Enter 打开不同文件，目标行在下一个可绘制的界面更新里显示“正在打开”的状态，有离开鼠标后仍成立的识别方式；当前已读项的语义保留到成功。阅读区同步标明忙碌及目标文件，既有窄窗和临时侧栏收起后也看得到回应。仍能改点其他文件、切页或用站内导航。键盘焦点按原有导航规则走，读屏能获得简短的本地化状态。
- **快切直接，慢切有占位。** 短等待内保有原篇身份与画面；本地快速返回就直接提交新篇，取消尚未出现的占位。以约 120 毫秒作为首次调校起点，按真实试读定稿；计时只用来决定何时展示占位。超过该时机，在阅读区当前视口露出目标文件名和轻量骨架，读到旧篇中段也能看到。骨架沿用题头、源码和讲解的起始对齐、浅色及连续圆角，窄窗随阅读栏改为上下排。目标内容到齐就可阅读和操作。普通模式可用短淡入，系统减少动态效果时静态交接。占位的出现和消失不挤动顶栏、已展开的文件树或阅读区外框。
- **展示与资料归属一致。** 待开文件只展示已经知道的身份。占位期间，旧目录、元信息、选文浮条及记录动作不能被当作目标内容使用。新篇成功后，当前行、题头与路径、源码、讲解和本篇目录一起对上；显式换文件仍从篇首读。保有普通 Markdown 降级及纯讲解块的既有呈现。交接不产生额外历史步骤，也不改变从磁盘重读文件的能力。
- **改点和失败都能接回去。** 等待 B 时改点 C，只有最后有效目标能提交和取得焦点；退出文件阅读页随即结束这次反馈，迟到的结果和定时器不会再显示 B。若 B 读取失败，指出失败的文件和原因，读者能在原 A 篇、原块内位置继续读，已有书签或批注草稿仍归原块，再点 B 可重试。遇到同名文件以可辨路径说明目标。首次打开、刷新资料、从图或个人记录回访、站内前进后退保持各自现有语义；共享读取代码只补受影响的回归。

实现从 [App.vue](../../../../../src/web/App.vue) 的 `readFromTree`、`openDocument`、`openingDocument`、导航序号及 `rememberPosition` 入手。文件树目前只接收成功的 `selected`；阅读区的 `readingLoading` 另有初载、刷新及历史恢复用途。占位替换原文前须保住原读点，别从已经缩短的占位层读取旧篇滚动位置。沿用现有请求取消、错误处理与草稿归属。文件落在 `src/web/` 的文件树、阅读视图、样式及中英文文案，行为回归落在 `tests/browser/`，运行证据归 `.local/D030/`。资料格式、服务接口和其他页面的加载设计均在本单范围之外。

基于 [006 文件阅读规格](../../../../../specs/006-file-reader/spec.md#functional-requirements) 的 FR-005、FR-008 至 FR-016 和已验外观 FR-017，按 [Spec Kit 增量约定](../../../../development/spec-kit.md#incremental-input)用 specify、plan、tasks 对应技能与生效模板维护 006 受影响部分。切篇新要求及最终验收时序在该规格定义一次，试读和实施步骤引用它。采用仓内 Ponytail 与 Impeccable 的局部交互检查，独审使用 Ponytail Review。

## 验证与停点

派单前在 4341 现用构建上用 Edge 157、1440 × 900 CSS px 实测。打开 `src/service.mjs` 第二块，点 `src/rules.mjs`，仅在测试浏览器暂缓该次真实响应。等待时焦点落在 rules 行，文件树当前项与题头仍为 service，阅读区 `aria-busy=false`，旧篇三个目录项可见，正文没有状态提示。放行后题头切为 rules，目录变为一项，本次观察零写请求。[等待截图](../../../../../.local/D030/baseline-9xKqdp/pending.png) · [观测值](../../../../../.local/D030/baseline-9xKqdp/observations.json)

必要构建后先用[共用试读项目的固定副本](../../../../../tests/README.md#页面改版共用试读)重复上述真实操作。快慢两种输入要分开，不能用一张加载完成截图说明中间行为。

1. **本机自然切换。** 从 service 中段用鼠标打开 rules，然后用键盘切到 api。观察实速下的目标行、正文交接、单一当前项和读点。用短录屏或逐帧序列配操作／响应时间，核快速返回没有骨架闪一下、空白帧或人为等待。另以减少动态效果试一次。
2. **暂缓一次响应。** 沿上面的 service → rules 路径，用 [reader-navigation 现有请求拦截方法](../../../../../tests/browser/reader-navigation.mjs)分别观察点击后、等待中和放行后。核目标可辨，旧资料与动作没有错配，正文和目录在放行后对应。用桌面及 390 CSS px 窄窗检查，中途收栏或从窄窗文件树选篇，状态都在读者视野内；窄窗放行后键盘能接着读。
3. **覆盖与恢复。** 挂住 rules 后点 api，再放行 rules；最终仍在 api，后退一次回到 service 原块及偏移。另在等待时切到书签，核迟到响应、焦点和占位都不抢页。最后从 service 中段打开 rules，令该次读取失败，核原文、目录、位置、草稿及历史，解除拦截后重新打开成功。复用 [reader-history](../../../../../tests/browser/reader-history.mjs) 的既有覆盖。异常和写入验证用副本，共用试读端沿用真实读取速度。

执行自测后冻结候选、输入和受控响应，按场景把时序与实图交给独立审查者。独审亲手看一次自然切换，并从原中段复验受控慢读、连续改点及失败恢复。修复用原失败输入重验，补受影响路径。若需变更读点、个人资料写入或导航历史的既有语义，交回主脑说明具体取舍。
