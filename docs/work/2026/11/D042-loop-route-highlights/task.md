# D042 · 从依赖图高亮闭环参与文件，进入步骤讲解

## 目标与批准依据

实现任务。读者在已经排好的文件依赖图上选一条闭环，认出它经过的文件，直接进入该闭环读某一步的讲解，再退回原图继续看。首次试读的人也能发现讲解入口。

2026-11-23，作者在本地主脑会话试读订单闭环，指出「用户很大概率看不到右边的能展开介绍」，要求底部按钮直接展开右栏，并提出「依赖图里面也是去掉查看关系这个按钮和逻辑」。作者在[闭环试读图](loop-before.png)圈出原按钮和右侧把手，在[依赖图试读图](dependency-before.png)标出顶栏开关、左侧目录区域及要去掉的按钮。随后认可本单的选闭环、高亮、跳转、展开讲解与回访方案，并指定「『阅读此闭环』和『清除高亮』。可以放在正上方中间的位置。然后你出任务吧」。本次作者反馈确认了入口难发现，订单成功和失败分支的教学效果仍待亲验。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

仓库 `D:/project/SpecDev Harness/aftertaste-reader`，基线 `dev@50111ad`，任务分支 `codex/feat-loop-route-highlights`，批准提交随转交消息给出。

1. **在文件依赖图选闭环。** 现有窄浮动工具条常驻，左下角小地图与操控照常可用。顶栏左侧开关改为开合默认收起的闭环目录，沿用闭环阅读页的目录样式、真实标题、路线缩影和键盘操作。选一条后目录收起，读者留在原视野看参与文件。选另一条就替换本次高亮。普通文件选择、直接依赖和库用法与闭环高亮可以区分，点文件或画布空白后仍可接着看已选路线。
2. **在画布正上方居中放置闭环操作。** 选中后显示当前闭环名，旁边是「阅读此闭环」和「清除高亮」。以顶栏下方的整幅依赖图画布为居中基准。目录收起或点过文件后，两项操作仍可直接使用。「清除高亮」回到普通依赖图并收起这组操作。「阅读此闭环」按已选闭环 ID 打开正式闭环阅读页，直接看到这张图，沿用其首次进入与回访规则。站内后退一次即恢复此前的依赖图、高亮、文件选择和视野。选路线、清除和开合面板只影响页面状态。
3. **只高亮有依据的文件。** 用闭环成品步骤的项目相对路径去重，匹配当前依赖图文件节点。订单闭环的五步应只点亮 `src/service.mjs`、`src/rules.mjs`。依赖图继续呈现原有边、库图例、分组和位置；分支顺序在闭环图里读。核对闭环与当前依赖图所对应的固定源码版本和有效路径；版本不符或参与文件无法完整对应时清掉先前高亮，说明实际原因。可读的旧闭环仍有「阅读此闭环」入口。目录为空、条目读失败、迅速换选或清除时，以当前选择和实际可读资料为准。首版跨提交更新、历史和恢复仍按原发布安排。
4. **在闭环底部展开本步讲解。** 选中步骤后，底部「来自／通向」继续沿真实连线换步。原「关系详情」及其展开面板退出，原按钮位改为可见的「展开讲解」，按下直接展开右侧栏并显示当前步骤，展开时可用「收起讲解」回到全图。右侧把手和底部按钮控制同一栏，状态同步。多个来路、出口及其完整目标和理由仍可查读，包含超出原底条摘要数量的分支。开合时保住画布位置和当前步骤，使读者能接着读。
5. **在依赖图就地查单条关系。** 去掉底部「查看关系」按钮及原通用展开面板。点文件仍见现有简要关系、核对状态，有讲解时可直接「阅读讲解」。点或用键盘选一条线，可看这条线的完整两端与原因。点库图例直接读介绍和逐文件用法。用现有边和图例的说明，保留长路径、同名文件及多文件用法的辨识能力。涉及的控件、提示和操作名随现有中英文界面切换。

**实施入口。** 产品依据为 [08 发布顺序、R16–R18](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)及[两图语义与高亮裁决](../../../../../specs/001-first-release/04-reading-modes.md#shared-graph-canvas)。执行按 [Spec Kit 增量流程](../../../../development/spec-kit.md#incremental-input)，用 specify、plan、tasks 及实际生效模板维护 [007 文件依赖图](../../../../../specs/007-dependency-canvas/spec.md)和 [009 闭环阅读](../../../../../specs/009-loop-reader/spec.md)，跨页回访按需对齐 [006 阅读历史](../../../../../specs/006-file-reader/spec.md)。用新批准替换旧按钮、工具栏开关及高亮待办的相应条款，更新受影响的验收，再以 analyze 核对并按 implement 实施。[项目技能适配](../../../../development/skills.md)用 Ponytail full 和 Impeccable 的既有页面交互流程。

## 验证与停点

- **订单往返。** 用共用订单项目的隔离副本，在已有布局选订单闭环，核对两张文件卡和原有连线；再选文件，点击画布正上方的「阅读此闭环」。在「规则转换并检查边界」用底部按钮打开讲解，分别沿成功和失败出口换步，核对右栏、关系条和把手状态。后退一次确认原选择、高亮、缩放及平移，再清除高亮。记录真实节点、操作区位置及该链路的布局写请求，观察开合与回访全程。
- **换路线和查理由。** 用同项目的「路径工具怎样处理文件名」换选，核对两条路线的不同参与文件。用隔离样例验同名异路径、同一步骤来源重复、旧提交仍含同路径、参与路径缺失，以及迟到的旧请求不能恢复已清除或已换选的高亮。点依赖线读原因，点 `node:path` 读各文件用法，点文件读讲解再后退。另用超过两个出口的步骤核对取消旧面板后的分支可达性。
- **实际呈现。** Edge 主验桌面及 390 CSS px 窄窗，检查长闭环名、正上方居中两项操作、左栏及底条在鼠标、键盘与窄窗点按下均可用；按影响补 Chrome、Firefox。复用现有 `dependency-canvas-selection.mjs`、`dependency-legends.mjs`、`loop-catalog.mjs`、`loop-reading-panel.mjs`、`reader-history.mjs` 等受影响脚本，更新旧按钮的预期，串行验证。

执行和独审分别使用从 `.local/2026-11-19-page-preview/project` 复制的独立输入，运行输出落 `.local/D042/<run-id>/`。4341 和 4342 已各有固定构建和作者资料，来历见[整合交接](../D041-record-management-details/mainbrain-handoff.md)。D042 在空闲回环端口用固定受审构建与隔离订单项目提供作者试读，交回实际网址。若需迁移个人资料或更换作者原试读入口，先交回具体影响；其他问题沿共同停点。
