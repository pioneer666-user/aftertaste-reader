# D038 · 笔记工作台的篇首、标签筛选与连续圆角

## 目标与批准依据

类型为实现。读者在左栏按标签找回「数量无效时，订单去哪了？」后，第一眼能读到自己的问题；点编辑即可改原句，需要时另起篇名。筛选器、编辑框和标签沿用文件讲解页已认可的连续圆角。

2026-11-22，作者接回 [D037](../D037-quick-note-overlay/handoff.md)，在笔记管理页截图划去重复的「笔记」、圈出空的可选标题框。主脑建议本单先做篇首与左栏，将标签操作收在篇首、合并侧栏两个筛选控件；行内引用的另一种外观留待试读决定。作者随后圈出筛选框、正文编辑框、标签输入及按钮等边角，指示「我们这个笔记页面里面的能复用就复用过来。然后你出任务吧」。本单按以上次序交付。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

仓库 `D:/project/SpecDev Harness/aftertaste-reader`，基线 `dev@3894db8`，任务分支 `codex/feat-note-workbench`。批准提交见派单消息。4341 的版前对照为 D037 受审构建 `e9edc31`。改动范围是顶栏「笔记」进入的管理页；顶栏「笔记列表」的浮层、书签和标注页沿用原交互。正文引用沿 D037 保留原句、可见来源、整块编辑与回访；草图中的下划线与来源浮示是另行讨论的提议。

1. **篇名跟着原文走。** 打开已有篇默认阅读。对示例这类无自定义标题、以独立首行写下问题的笔记，该行直接承担阅读标题，只出现一次；点「编辑」聚焦正文，在左栏改首行，列表篇名和右侧预览跟随。空标题框收成轻量的「另设标题」入口。已有自定义标题的笔记直接展示该标题，编辑时可改名；清空后按原规则取首个非空行，空篇沿用原空白名称。打开标题入口或退出编辑不产生额外写入。复用现有取名规则，只调整呈现，保住正文中的普通首段、Markdown 标题、列表、代码和首行块引用的结构、可操作性及完整文字；不得拿截短的列表名写回正文或据同名删段。
2. **篇首和侧栏各管一件事。** 标签贴近篇首，阅读时可辨，编辑时原位移除或点「＋ 标签」再输入。篇首右侧放「编辑」或「已保存／保存中」与「完成」等适用操作，删除收入编辑态「更多」并沿用二次确认；失败与重试须始终找得到。桌面左写右预览，窄窗保留编辑／预览切换。左栏从「全部笔记 ▾」直接开始，省去重复页名及其占位，保留工作台的可访问名称。打开这个入口即可看全部标签，输入部分文字找标签、选中一个完整标签才按它精确筛笔记；收起后入口显示所选标签，同一处可回全部。标签查无结果时能清掉查询或退出，保留仍可见的当前篇，筛后选篇及返回位置沿用工作台规则。筛选与标签编辑各用各的入口和状态。
3. **把连续圆角落到实物。** 参照文件讲解页顶栏控件、文件树选中行及阅读面板。逐项核侧栏筛选入口、弹层与列表选中项，篇首标题／标签输入、添加／移除标签、完成／更多按钮及菜单，还有正文编辑器的可见外框。沿用 [D029 四档与浏览器回退](../../../../../specs/006-file-reader/plan.md#d029-连续圆角)，按表面职责复用行内、控件、整行及面板档，贴边分隔仍用直边。工作台内原有引文块也检查可见边角，沿用其来源侧线、来源文字和整块选中态。背景、边线、选中填充与焦点须沿同一轮廓；按实际控件检查禁用、悬停、强制色和长内容滚动。现有普通控件与列表已部分接入，先查真实效果。共享编辑器的外框变化应限定在工作台，保住右上浮层已调好的边界、尺寸和操作。

**实施入口。** 以 [08 现行规格 R13、A13、A14](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)、[011 项目笔记 FR-006、009—011、SC-005／006](../../../../../specs/011-project-notes/spec.md)及 [D029 回执](../D029-reader-continuous-corners/handoff.md)为依据。依 [Spec Kit 增量流程](../../../../development/spec-kit.md#incremental-input)在既有 011 目录使用 specify、plan、tasks 及相应生效模板，编码前用 analyze 核本批一致性，再用 implement 执行。沿用[笔记契约](../../../../../specs/011-project-notes/contracts/notes.md)，按实际操作更新[使用说明](../../../../usage/file-reader.md#记录项目笔记)。按[项目技能适配](../../../../development/skills.md)用 Ponytail full 和 Impeccable 核读写两态的层级、轮廓和窄窗。

前端从 `src/web/ProjectNotes.vue`、`RecordWorkbench.vue` 和 `style.css` 入手。复用 `markdown.ts` 的 `noteName`、`NoteSaveStatus.vue` 及共享草稿；标签操作参照 `QuickNote.vue`。连续角沿用 `style.css` 的尺寸变量与 `reader-corners.ts` 的回退，检查 `NoteBody.vue` 中实际接收边线的编辑器外壳。行为回归归 `tests/browser/`，运行输出归 `.local/D038/<run-id>/`。

## 验证与停点

1. **找回再续读。** 用共用试读副本，从「全部笔记」搜「回」、选「回访」、打开订单笔记。读第一段引用、后退，核筛选、选篇、侧栏滚动、原句与键盘焦点，再用 Tab 续到第二段。清除筛选恢复全部。另核无匹配、空篇和长标题。打开、筛选、阅读及单纯切换编辑／完成均零笔记写请求。沿用[工作台回归](../../../../../tests/browser/record-workbench.mjs)。
2. **改标题与标签，再读回来。** 在副本上分别改示例首行、另设标题、清空自定义标题，再增删标签、完成、刷新，对照列表、详情、预览及磁盘原文。测一篇首行本身就是 Markdown 或块链接的记录。核桌面左右栏、窄窗切换及同一篇在右上浮层的读回；删除取消保住原篇，确认删除用副本专设的记录。保存失败保留草稿、可重试，既有冲突／删除保护沿[笔记回归](../../../../../tests/browser/notes.mjs)，引用的原格式剪贴、撤销沿[引用回归](../../../../../tests/browser/note-references.mjs)。按改动适配既有断言并串行验证。
3. **同篇同窗看边线。** 用同一篇订单笔记取版前／版后阅读态及编辑态实图。Windows／Edge 桌面可用 1440 × 900，另走 390 px 窄窗。挑筛选入口、选中行、编辑外框与标签作局部对照，核键盘焦点、弹层开合回焦、长标签换行及正文可滚动；在 Firefox 核实际连续角回退，并实查强制色下的系统描边。回执标明视口、浏览器与候选，保留足以看清角部及整页比例的图。

自测和独审各用[共用试读的独立副本](../../../../../tests/README.md#页面改版共用试读)。独审绑定冻结提交、构建和输入，重点复走首行与自定义标题的读写往返、单标签过滤后的引用返回，以及不同浏览器中的边线和焦点。保护原项目 `.local/2026-11-19-page-preview/project` 中当时实际存在的笔记、书签、批注、讲解和布局。若方案需改写原资料或改变引用存储，交回具体原因；同一问题两轮修复验证仍失败，按共同停点交回。
