### 本批交付与验收

保持既定位置 `docs/aftertaste/dependency-graph.json`，以 UTF-8 JSON 保存格式标识、固定提交、文件节点和关系。文件节点用项目相对 Git 路径标识，依赖边方向为“被依赖文件 → 使用者”，允许环；原因由 AI 提供。字段细化与命令命名由执行按既有技术授权落实，不迁移为候选三文件布局。

| 编号 | 必须达到的结果与验收场景 |
| --- | --- |
| G01 登记与版本 | 明确写操作可在图不存在时初始化，并登记指定批次的真实源码路径；新节点为 unreviewed，重复登记保留已有边及 reviewed 状态。只读查询／检查不建图。复用并核验完整固定引用与项目映射，空图也不能绕过提交身份核验；已有图与请求提交不一致时拒绝写入，不能仅替换 source_commit 或改读 HEAD／工作区 |
| G02 局部依赖提交 | 接收小份 JSON 文件，以明确完成核对的使用者为单位替换完整依赖列表。例：service 从 schema、old_repo 改为 schema、new_repo，只替换指向 service 的关系，service → router 等其他使用者的关系保持；重复提交结果相同，不累积边。明确已核对的空列表与未提交／未完成核对严格区分。新引用的项目文件可登记为 unreviewed，不生成其讲解或递归分析 |
| G03 查询与独立检查 | 按文件路径查询依赖、使用者、分析状态及实际固定版本；未登记、未核对、已核对且无依赖可区分，不把无边当作无依赖。共用检查覆盖 JSON／字段、节点与关系重复、引用一致、路径和固定提交中的真实文件。允许循环，报错定位到文件／字段／关系。AI 直接编辑 JSON 后可单独检查，机械合法不代表语义完整或用户已理解 |
| G04 明确删除 | 只有明确指定才删除图节点，连带移除其关联边并返回移除关系及受影响的存续文件；未出现在本次输入中的节点不删。被动失去依赖边不能被当作完成了新一轮依赖核对，受影响使用者的状态处理须在协议中明确。删除仅影响本图，源码、讲解、个人记录、闭环及历史不变；删除一条依赖也可通过 G02 的完整列表修订完成，无需再造一套通用补丁语言 |
| G05 写入与失败保护 | 写前校验合并候选，完整生成后再发布／替换，失败不截断旧图、不发布部分更新。损坏、版本不符或不可读取的旧图必须诊断，不能当作空图覆盖；输入文件保留供修复。对真实 CLI 验证首次创建、更新、重复提交、显式删除、非法输入与写入失败，记录准确退出状态及落盘结果 |

图只保存源码引用、分析状态和关系说明，不保存源码内容或源码缓存。查询既有图不因 Git 对象不可用而丢弃已保存关系；需要核查源码却无法读取时明确报告未完成校验，不假报通过。范围外依赖仅指同一目标项目中未选作讲解的文件；仍校验固定提交中的真实路径，不扩展仓库支持或读取任意磁盘。库／标准库教学节点、图例和布局在后续对应任务落实，不在本单伪造成源码路径。

本单只维护图自身的固定分析依据，不实现整套资料版本同步、跨提交图更新或重命名身份迁移。程序不推断阅读范围、教学顺序、未连边文件的无依赖结论或依赖分析完整性。命令输入须明确项目、固定依据和意图，不能把 cwd 或 Skill 安装目录当目标项目。

## 验证与停点

- G01—G05 的场景进入正式测试，走通真实 Git 与 CLI 的完整路径。补查空图及无源码读操作时的固定引用校验、项目为子目录、不同 cwd、工作区／HEAD 改动、缺对象／非法路径／悬空引用／损坏 JSON；相关失败不得写入或切换来源。
- 纯规则测试核局部替换只影响指定使用者、登记不降级既有状态、重复应用的幂等性、显式空列表、循环关系和删除后的引用一致。property-based-testing 方法用于可表达的真实性质，使用独立预期并保留具体反例；无需为技能本身安装新测试库。
- 存储检查沿 D008 的实际教训：普通 `Docs/AfterTaste` 大小写别名可用，同时拒绝现存 symlink／junction 绕界；源码节点身份仍按 Git 路径，不能统一转小写来修资料路径。失败注入覆盖临时名碰撞、写入／替换失败、清理只处理自己拥有的临时文件，核发布前失败时旧图原文及无关资料保持；发布后清理异常须如实报告目标是否已更新。采用单文件可靠写入，不扩大为数据库、多进程协调或自动恢复系统；实际未测文件系统与并发边界如实交回。
- 串行完成 typecheck、build、本批单元／集成及真实 CLI 示例；既有固定取源和文档功能按实际改动补回归。未变代码及环境可复用绑定版本的有效证据，最终回执清楚对应版本与检查，不把各版局部验证拼称为最终版全套重跑。
- 执行以固定候选调用未参与实现的独立审查子代理，按 Ponytail Review 追完整调用链，必要时以 Sharp Edges 聚焦 JSON 输入、路径、局部替换和失败保护。重点检查未提交者是否保留、未完成分析是否冒充无依赖、删除影响是否准确、旧图能否被错误清空以及版本是否偷换。取得写入交还后归档原文到本单 `review.md`，修复另提交并复核。
- 本单无页面或教学呈现，作者体验验收不适用；工具结果不冒称 A08／A09 的页面体验已通过。若必须改变既定图路径、节点语义、源码只引用或扩大业务范围，暂停依赖部分交主脑；常规协议字段与实现细节自主处理，修复停点沿共同规则。
