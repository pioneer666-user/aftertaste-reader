# D045 · 首次安装回味，读通真实后端的一次收藏请求

## 目标与批准依据

实现任务，包含一次独立安装实验。第一次拿到回味的读者，仅凭拟公开的 README 和本地预构建包，能让 AI 为一个已有 Git 提交的项目生成第一篇讲解，打开源码对照，再从已经讲过的文件中选一条业务路线，读到数据落库和返回前端。交付可重建的包、走通的说明和作者能亲自打开的闭环。

2026-11-23，作者要求“让第一次拿到回味的人能用起来”，并说“你出任务吧，我们可以在实验目录下去尝试”。随后明确试读重心是正式后端，“我更看重后端的数据怎么处理，怎么变，接口调用时的顺序”，希望从 API 入口追到 ORM 存储和返回给前端的内容。早期设计已有后端创建表单的例子，并明确闭环按读者的关注点串起已有文档块。[闭环设计 U46—U47、U79](../../../../../specs/001-first-release/04-reading-modes.md) · [作者的后端学习目标 U60](../../../../../specs/001-first-release/07-skill-design-map.md)

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

**工作落点。** 实验入口在 [experiments/D045-alpha-first-run](../../../../../experiments/D045-alpha-first-run/README.md)。将复现脚本和固定输入说明留在那里，包、日志、临时项目与运行记录由该实验的 `.local/<run-id>/` 管理。接收方优先使用仓库外的临时空目录，防止 Node 向上借用开发树依赖，实验目录记录复现方法与位置。正式打包改动落在根包清单、必要的锁文件和 `scripts/`，CLI 或产品 Skill 的定位问题在现有入口修正。公开文档和正式运行不依赖实验脚本。新用户无需编译 Vue、安装 Python 或运行 Apache Answer 自身的后台。

执行按 Ponytail full 复用现有实现，特别核 `src/server/reader.ts` 从安装后的模块找 Web 资源、`skills/aftertaste-reader/references/tools.md` 从实际 Skill 找 CLI。现有开发树首用证据见 [D010](../D010-generation-skill/evidence.md)。按[项目 Spec Kit 接入](../../../../development/spec-kit.md)在既有 005 生成 Skill、006 文件阅读等受影响材料中增量维护安装入口与 quickstart；形成新的正式要求、方案或实施清单时使用对应的 specify、plan、tasks 技能与官方模板。产品 Skill 包结构或打包方式变化时按项目技能入口使用 skill-creator，并用真实会话验证。

## 验证与停点

1. **只给读者公开材料。** 实际构建、打包并检查 tarball 文件清单，在干净接收目录从该文件安装，安装位置和目标 Git 项目分开。新开的讲解 AI 只收到 README 可见的准备步骤、包内 Skill、目标项目和读者问题。记录实际解析到的 CLI、Skill 和页面资源位置。运行依赖来自安装结果，使用端不调用开发树、已有试读服务或全局同名工具。依赖安装可联网，阅读已生成资料时验证本地资源可用。包不携带开发技能、实验、任务记录或本机资料。
2. **从第一篇走到选线。** 从读者的问题开始：“我想读这个项目的后端。先讲收藏问题涉及的文件，我关心前端传什么、谁决定写库、最后返回什么。” 按现有 Skill 确认范围和节奏，在这条路线内生成首篇及走通所需的其余完整文件讲解。用安装后的工具校验，实际打开第一篇，对照固定提交的源码与非空讲解。之后由讲解 AI 根据已有块提出可讲完整的路线，读者明确选择后保存闭环。若还缺关键讲解，指出缺口并由试用读者发起针对该文件的普通生成，再接回选线。实验给读者的问题与独审核对用的答案分开，避免把节点、边或正文事先喂给讲解 AI。
3. **跟着同一笔数据读到底。** 在阅读器从真实接口走到请求字段、身份来源、服务判断、仓储接口与实际实现、ORM 写入、返回给前端的数据。通过实读块和连线回答三个问题：① 哪些字段来自客户端，哪些由后端补出？② 第一次收藏时哪张表存哪几个关键字段，收藏数怎样算出并写回，二者的操作顺序和事务边界是什么？③ 同一用户再次提交“已收藏”时在哪一步提前返回，响应数据与首次有何差别？连线区分调用、数据传递、条件和映射，说明拆开接口与存储实现对这条业务有什么用。在原图读步骤、源码对照和分支，复制一个步骤定位；关闭本次服务、用同一安装包重开项目，从保存的闭环再次读到该步。作者入口使用专用副本和空闲端口。
4. **按源码核实讲解。** 独立依据包括[控制器](https://github.com/apache/answer/blob/3f1ed50f6776452c11b6ffdbdc767cd1887d629b/internal/controller/collection_controller.go#L51)、[服务分支](https://github.com/apache/answer/blob/3f1ed50f6776452c11b6ffdbdc767cd1887d629b/internal/service/collection/collection_service.go#L50)、[收藏关系写入](https://github.com/apache/answer/blob/3f1ed50f6776452c11b6ffdbdc767cd1887d629b/internal/repo/collection/collection_repo.go#L52)及[问题计数写回](https://github.com/apache/answer/blob/3f1ed50f6776452c11b6ffdbdc767cd1887d629b/internal/repo/question/question_repo.go#L128)。沿实际调用核完响应包装。特别核请求中的分组字段与最终写入的分组 ID、服务层提前返回与仓储事务内复查各自的含义。教学示例标出假设输入，区分固定源码所示行为与真实运行结果。旧订单数组样例可复用作技术回归。
5. **陌生人复走。** 冻结代码提交、拟公开 README、包文件名与 SHA-256。执行调用 Ponytail Review 独立审查者，在另一份干净安装目录和无讲解的目标副本，按同一份读者说明复走安装、调用 Skill、生成讲解、打开和重开。审查者对照固定源码，独立核验作者将看到的闭环能否回答上述三个问题，记录需要猜路径、补隐含步骤或看不懂连线的地方。产品 Skill 的真实试用和独审分别留证。Windows／Edge 主验，浏览器和服务串行，回执注明实际操作系统和 AI 宿主。

若安装依赖回退到开发树、正式闭环缺少落库或返回依据，记录实际停点，修复后从干净目录补走受影响过程。隔离安装与公开项目读取在本单范围内。改变作者全局环境、引入必须由读者承担的新服务或扩大产品行为，先说明具体使用影响。按共同两轮修复停点保护现场。维护作者已有的试读服务、Git 源码与个人资料。
