### 能力边界

1. 明确目标项目根与 Git 根的映射，支持目标项目位于仓库根或仓库内子目录；调用进程所在目录不改变目标。文件路径相对于目标项目解释，只读取该项目范围内的指定文件。
2. 提供“固定版本”和“按固定版本读取”的明确调用方式。固定阶段默认解析本地 HEAD，也可指定本地已有提交，返回确定的完整提交标识；后续读取使用该标识，不能每读一个文件又解析一次 HEAD。历史或分叉提交不因版本新旧被拒绝。
3. 从提交对象读取文件，允许内存处理与返回给调用者；文件即使在当前工作区被修改或删除，仍按提交中的内容读取。返回必要版本与路径依据，便于上层可靠复用。
4. 提供真实可运行的命令入口及可被后续服务复用的用例。输入输出、诊断标识、退出状态由执行定稿，中文说明与稳定问题标识分开；成功的源码输出不是诊断日志。定位失败、对象缺失、文件不存在及不支持的文件类型／编码应明确诊断，不能以空串或替换字符假装成功。
5. 工具对目标项目只读：不 checkout、不改索引／提交／配置、不 fetch 或自动修 Git；不生成源码缓存、临时源码、含源码的诊断日志。路径和 Git 参数作为数据处理；不经 shell 拼接，不通过符号链接或子模块悄悄读取另一个工作区。尚不支持的目标形态明确诊断，不扩为多仓库管理器。

本单不实现文档头解析、镜像 Markdown 生成、行范围与块校验、文件枚举／依赖分析、diff／更新事务、HTTP 服务、网页、图、导出或产品 Skill。取源返回整文件，分块时需要的行范围处理留给文档结构任务。双语界面 B003 仍在首批正式页面前落实，本单不安装 UI 或国际化依赖。

## 验证与停点

以下是本批验收范围，执行将其映射至 002 的场景与实施清单，回执报告实际证据；不是另一份可勾选的实施任务表。

| 场景 | 观察结果 |
| --- | --- |
| 在合成仓库固定 A，随后改工作区、产生 B、删除工作区文件，再按 A 读取多文件 | 始终返回 A 的文件内容与完整提交依据；固定阶段不带目标时解析当时 HEAD，显式选择历史／分叉提交也可读 |
| 目标分别为仓库根、仓库内子项目，并从不同 cwd 调用；路径含中文、空格或 Git 特殊含义字符 | 文件定位一致、按字面读取，项目边界清楚；拒绝路径越界和参数注入，拒绝时无额外命令或文件读取 |
| 提交包含空文件、Unicode 文本、不同换行及末尾无换行的文本 | 原内容不被悄悄裁剪、改写或误判为空；二进制／不支持编码返回已声明的诊断 |
| 非仓库、无提交、无效提交、目标提交没有该文件、Git 不可用／读取失败 | 返回可区分的问题和必要定位；不换成 HEAD、工作区、缓存或空内容，不在错误信息中附源码正文 |
| 构造符号链接、子模块或其他非普通源码条目；检查成功和失败前后文件／Git 状态 | 按声明边界处理，不跳到其他工作区；目标源码、索引、引用和用户资料未被修改，无产品维护的源码落盘副本 |
| 构建后从真实命令入口执行成功与失败场景 | 输出／退出状态符合 contracts，复用同一取源用例；类型检查、构建、相关测试通过，不能只有内部函数测试 |
