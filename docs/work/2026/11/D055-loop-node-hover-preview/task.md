# D055 · 闭环步骤上方的 Markdown 悬浮预览

## 目标与批准依据

实现任务。读者跟着一个例子看闭环时，在「用返回的 4 建立订单」上停一会，就能读到订单已经建好、集合仍为空。气泡从节点上方轻轻出现，下面已经展开的注释可以同时读。想看完整讲解和固定源码时，沿用点选步骤的入口。

2026-11-25，作者看过订单悬停示意后要求「把这个悬浮改到节点上面，节点说明已经放下面了，不要抢地方」「可以做一个小倒三角，像这个节点的聊天框」「轻轻出现，轻轻消失」「这个悬浮窗可以内容多一些，多几行，里面还是支持md文档格式」。作者批准本次派单，并要求提交标题沿用项目现有风格。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。遇到已不支持的旧文档格式，识别脚本只负责报错或警告，让使用产品 Skill 的 AI 知道哪个文件受影响、原因是什么。AI 按当前 Skill 的正常生成、校验流程改好或重做相应讲解、闭环，无需维护逐版迁移脚本或另写兼容指南。实际改写或删除作者资料仍按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

桌面是主要阅读和操作环境，交互与视觉细节优先在桌面打磨。手机默认只需能打开讲解或图，读到主要内容，需要时可滚动查看。新功能可以只在桌面提供，例如画布编排。手机专属布局、精细手势和逐项体验验收仅在当次明确需要时安排。

## 范围与材料

在回味仓库根目录接单。本地基线 `dev@7fdce86` 含 D054 和已独审的连续圆角执行约定，任务分支 `codex/feat-loop-node-hover-preview`。批准提交由转交消息提供。

1. **气泡讲什么。** 闭环图普通教学步骤在全图和选例两种状态都可预览。直接从该步的 `explanation` 取材，复用[现有 Markdown 渲染器](../../../../../src/web/markdown.ts)和右栏的排版语义。允许多段、列表、强调、行内代码、代码块和已有安全链接。保住段落或列表等结构，在合理宽度内可连读数行；长文明确提示还有内容，读者能在现有步骤详情读到全文。避免重复卡片标题。D051 的可选 `annotation` 仍单独呈现在节点旁。现有成品即可使用，无需讲解 AI 另写气泡文案或在悬停时生成。示例保存的是情景和路线，共用步骤的讲解可能涉及多个输入；保留原文中的前提和推演措辞。
2. **上方说话，下方留给注释。** 气泡贴近触发节点的上沿，底边伸出小倒三角。正文、连续圆角外壳和尾尖看起来是一体；沿[工程约定](../../../../development/engineering.md#continuous-corners)复用已有轮廓。左右靠边时横向收进可读画布，尾尖继续对着原卡。按画布可用区域避开右栏、工具与已展开的注释。[D051 注释](../../../../../src/web/LoopAnnotation.vue)在底部不足时也可能占用上方，已展开的内容优先。先尝试在上方调整宽高或横向位置；上方确实容不下可读正文时，保留节点原有点选阅读入口。气泡不翻到卡片下方，也不推动节点或自动平移画布。
3. **轻轻出现和消失。** 指针扫过沿用现有卡面和直接连线反馈；停稳后才出现预览。建议从停留约 350 ms、整体向上约 3 CSS px 并以 ease-out 淡入约 150 ms 起调，退出以 ease-in 淡出约 100 ms。尾尖随主体一起动，打开后静止供阅读。以实际手感调整，取消过期的开关动作；连续划过、返回同一节点或换步都不会闪出旧内容。减少动态效果时直接显隐，保有内容与焦点反馈。已选 D054 示例且能确定该步来向时，可按获认可的示意在那条实际来线上走一次短光；同一轮展示只播一次。首步、路线外节点及重访导致来向不唯一时，只读该步预览。教程推进和小球播放留给后续讨论。
4. **让人读完，也方便离开。** 鼠标从节点跨过尾尖进入正文后可停留、选文；节点或气泡仍被指向、或焦点还在其中时持续显示。键盘聚焦步骤也可读，Tab 可进入实际存在的链接，Esc 就地关闭，必要时把焦点还给节点，原地停留不会立即重开。一次最多展示一个气泡，抑制与卡面重复的原生标题提示。点击或 Enter 激活步骤仍按现有规则选步、读注释和查看详情；气泡内部操作与画布拖动分开。开始拖放、切图或触发节点被收起时，撤去失效的预览。悬停本身不改当前步骤、路线、开关、布局和浏览历史。依赖图、库图例和文字开关继续沿用现有交互。
5. **实现入口。** 从[现行阅读规格](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)进入，按 [Spec Kit 增量维护](../../../../development/spec-kit.md#incremental-input)使用 `speckit-specify`、`speckit-plan`、`speckit-tasks` 及相应 `spec-template`、`plan-template`、`tasks-template` 更新[009 闭环阅读](../../../../../specs/009-loop-reader/spec.md)受影响的段落及验收，特别对齐已写「只轻抬」的旧描述。[007 共享画布](../../../../../specs/007-dependency-canvas/spec.md)管双图的直接关系指向。[共用画布](../../../../../src/web/DependencyCanvas.vue)、[闭环阅读](../../../../../src/web/LoopReading.vue)和 `src/web/` 的定位、主题及圆角样式为产品落点。局部 UI 按[项目技能适配](../../../../development/skills.md)执行。

**动效与交互依据。** Atlassian 给小浮层举例用 150 ms 进场、100 ms 退场。Adobe 的非模态预览允许悬停或键盘聚焦触发、Tab 进入交互内容、Esc 返回。W3C 说明可移入、可关闭及持续显示的条件。上面的停留时间、位移和尾尖外观是本项目的试调选择。参考 [Atlassian 动效](https://atlassian.design/foundations/motion/applying-motion/)、[Adobe PreviewTrigger](https://react-aria.adobe.com/PreviewTrigger)、[W3C 悬停和聚焦内容](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)。

## 验证与停点

- 从[已验订单示例](../../../../../tests/fixtures/loop-examples.mjs)和[原始步骤讲解](../D051-loop-node-annotations/trial-input.json)建独立本地试读副本。用安装包打开成功例 `"04"`，在建单步读到「集合仍为空」，追加步才变为一条；换 `"4.5"` 看抛错步。核全图、带注释的校验步、无注释的建单步及同时展开的上下两块。另用含多段、列表、代码和链接的保存讲解实读，核短文、超长文与链接操作。
- 走一遍慢移进气泡、快速扫过、换节点、键盘进入和 Esc、点开源码再回来、拖节点和缩放。把节点放到上边缘和右栏旁，另让已有注释翻到上方，验证避让、尾尖指向及降级入口。看浅深主题、减少动态和实际圆角；按原生及后备绘制路径取证。选例操作和依赖图定向回归，核悬停期间没有布局写入。
- 按影响在 `tests/browser/` 和必要的 `tests/fixtures/` 增补检查。测试串行，使用空闲本地端口和 `.local/D055/<run-id>/` 的独立资料。保留 `4317` 的真实服务及既有试读资源，尤其是 `4359` 的 D054 试读。交付同一固定候选的入口及能判断淡入、停留、淡出的复现操作；单帧截图只用于看位置和轮廓。
- 若确需新增成品字段、改写既有资料或改变点击步骤的含义，附上具体读者场景交回主脑。其余问题按共同修复停点处理。
