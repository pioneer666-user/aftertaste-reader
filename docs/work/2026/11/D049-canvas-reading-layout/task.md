# D049 · 双图连线穿行、重排确认与居中分层

## 目标与批准依据

实现任务。读者打开文件依赖图或闭环图，能从左侧库图例、第一层文件或教学入口向右读；点中某张卡时，能追清它被其他卡遮住的直接连线。用户亲手排好的位置，只有在明确确认重排后才会被新排布替换。

2026-11-24，作者反馈「这些线直接穿过这些节点比较好，如果点这个节点，它的连线才能再节点的上面」，随后指定「先出第一单先去解决图里面的线问题」，并要求防误触确认、库图例在最左边、同层节点多时可占多列、先居中且层间距大于层内距。本单接续 [D048 回执](../D048-canvas-routing-alignment/handoff.md)。两张黑底参考图分别示意中间卡遮线及选中后线浮到前景，红圈标出重排入口。[遮线参考](edges-behind.png) · [前景参考](edges-in-front.png) · [重排按钮](rearrange-control.png)

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。遇到已不支持的旧文档格式，识别脚本只负责报错或警告，让使用产品 Skill 的 AI 知道哪个文件受影响、原因是什么。AI 按当前 Skill 的正常生成、校验流程改好或重做相应讲解、闭环，无需维护逐版迁移脚本或另写兼容指南。实际改写或删除作者资料仍按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

基线为回味仓库 `D:/project/SpecDev Harness/aftertaste-reader` 的 `dev@7c573d1`；沿用分支 `codex/feat-canvas-reading-layout`。批准提交见转交消息。两图分别保有关系数据、分组、视野和个人位置。[共用画布依据](../../../../../specs/001-first-release/04-reading-modes.md#shared-graph-canvas)

1. **默认从卡后穿过，选中后到前景。** 按两端位置走自然直线或平滑曲线，允许路径经过无关的第三张卡。以 A → C、中间挡着 B 为例，平时 B 遮住经过卡面的线段；悬停可临时提亮。点选 A 或 C 后，这条线沿原路径完整浮在 B 上方，移走鼠标仍可追踪。点选 B 改为显示 B 自己的直接关系，点空白解除固定。箭头只在真实目标处出现，中途经过 B 不产生端口。适用于文件、教学步骤和有用法的库卡；保留库虚线、密集端点错开、自环、回边、贴边箭头、键盘与触屏选择。前景线经过卡面时，下面的卡仍能从原入口点击、拖动，依赖图仍可在空白线段上选线读理由。点选、悬停或清除均不改路径、坐标和布局文件。
2. **确认后重新布局。** 点击工具栏或用键盘激活「重新布局」，先问「重新布局这张图？」。说明会替换当前卡片与图例的位置、复位视野，组名与成员会保留。提供「取消」和「重新布局」两个明确操作，默认焦点在取消。取消、Esc 或关闭时保留坐标、选中项和视野，本次操作不发保存请求。确认后仅对弹窗指明的当前图执行一次重排，沿现有保存、失败与重试流程反馈；中英文可用。程序初始化和打开已有布局沿正常读取流程。
3. **库图例单独排在最左。** 初次自动排布和确认重排时，当前可见的库都在第一层文件或步骤左侧。可把业务层记作 0、图例记作 −1；若图例较多需展开，它们的全部列仍在业务层之前。允许平移成方便显示的实际坐标。无可见图例时不预留空栏。闭环按实际步骤用法展示库，入口仍是第一个教学步骤。用法虚线、库可见性和业务层次分别沿现有语义，隐藏库已有的个人布局可恢复。
4. **沿共同的水平中线排列，宽层内部可分列。** 左到右先按关系定逻辑层，节点少的层紧凑居中，节点多的层可用几列较短的子列围绕同一中线展开；此规则也适用于第二层之外的拥挤层。层间横向留白按卡片边缘计算，应明显大于同层子列的横向净空，下一层从前一层的整个外框之后开始。子列的视觉顺序不增加依赖或教学先后。层内排序兼顾邻接关系，闭环沿用已有推荐次序。层高、换列阈值与具体间距由执行用下述大、小样例选定，并记录效果。初始和重排后的视野让人能从左侧开始阅读，库区或业务入口不会因为负坐标或垂直居中被整区裁出画面。

## 验证与停点

- **看得见遮挡与浮起。** 两图都用有 A → C、B 遮住中段且 B 自有另一条关系的合成画面，在同一位置对比普通、悬停、点选端点、指针移走、改选 B、点空白。核对实际可见像素和点击结果，并对照路径，避免把调亮当作提到前景。复核真端点箭头及卡片拖动、整组吸附。更新[原 D048 检查](../../../../../tests/browser/canvas-routing-alignment.mjs)中已被替代的第三方卡片避障断言。
- **重排不误触。** 先手摆一张库卡、移动一个组并缩放。两图各走「打开 → 取消」与「打开 → 确认 → 刷新」，比对布局内容、当前视野和本次保存请求。确认后组名与成员可读回，另一张图的布局保持原值。
- **看得懂密集层。** 用同一份仓内合成场景留布局前后对照。例如 3 个库、2 个入口、中间同层 18 个节点、最后 1 个汇合点，含一库多处使用。标出逻辑层边界，核图例全在左、18 个节点占多列、各层纵向中心、层内与层间实际净空、卡片无重叠，并确认初始画面能找到起点。再用小型分岔／汇合的闭环、无库图与含环数据复核层次稳定、初开与确认重排使用同一规则、旧布局重开可恢复。[布局单测](../../../../../tests/unit/canvas-layout.test.mjs)
- 继续使用仓库内合成资料，串行验证。候选另用空闲回环端口，优先检查 4320，给 4317、4318、4319 留出原用途。可再生成的证据放 `.local/D049/<run-id>/`。冻结候选后由执行调用独立审查子代理按 Ponytail Review 实查上述三组场景。回执给作者两图直达入口、可点的端点和可比较的密集层。
