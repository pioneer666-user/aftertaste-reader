# D054 · 跟一个例子看闭环路线，两图共用高亮

## 目标与批准依据

实现任务。读者在同一张闭环图上选一个具体例子，能沿箭头看出它经过哪些步骤、在哪里分岔、最后停在哪里。读者可以中途点开源码核对，回来仍能接着看刚选的例子。

2026-11-25，作者讨论教程所需的基础能力后，接受先做示例路线高亮，并要求「可以，你出任务吧，这个高亮依赖图里面也有，他们底层做成一样的吧，现有的高亮如果你觉得格式样式不合适，可以优化」。作者另询问是否需要黄、绿、蓝等高亮色。本单采用一次选一例、按主题给一种路线强调色的方案，边原有的语义色继续生效。小球移动和节点换卡留给后续讨论。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。遇到已不支持的旧文档格式，识别脚本只负责报错或警告，让使用产品 Skill 的 AI 知道哪个文件受影响、原因是什么。AI 按当前 Skill 的正常生成、校验流程改好或重做相应讲解、闭环，无需维护逐版迁移脚本或另写兼容指南。实际改写或删除作者资料仍按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

桌面是主要阅读和操作环境，交互与视觉细节优先在桌面打磨。手机默认只需能打开讲解或图，读到主要内容，需要时可滚动查看。新功能可以只在桌面提供，例如画布编排。手机专属布局、精细手势和逐项体验验收仅在当次明确需要时安排。

## 范围与材料

本地仓库 `D:/project/SpecDev Harness/aftertaste-reader`，基线 `dev@e865d8d`，任务分支 `codex/feat-loop-example-highlights`。批准提交由转交消息提供。

1. **讲解 AI 怎样写例子。** 闭环可选地保存多个具名示例。写清足以辨认该例的输入或情景、必要前提，按实际经过顺序引用本闭环已有步骤；每一对相邻步骤须有对应方向的教学边。同一节点可被不同例子共用，合法重访保留顺序。选一例只点亮列出的节点和实际走过的边。整图 `reading_order` 仍供读者按推荐顺序读完所有分支。示例依据闭环自己的固定源码；假设输入明确写为推演。该方式适用于各种语言和项目。
2. **在闭环图读一个例子。** 有示例才显示选择入口，初次打开先给普通全图。能用鼠标、键盘选择、切换和清除，随时看得到当前例子的名称或输入。一次选一例，换选后清掉上一例独有的强调；共享段保持准确，其他分支仍能查阅。读步骤、点线查理由、开合右栏和对照固定源码时保留本例。选例本身保持读者的视野、当前步骤和布局；切换到另一闭环时不能串例。
3. **与问句开关配合。** 路线经过被 D053 问句收起的步骤或边时，临时显出本例需要的成员。订单问句同时控制追加与抛错，选成功例时可以看见追加，抛错仍按读者原有开关显示。如果读者已主动展开两路，则两路都可见，只有本例的路线持续高亮。切换或清除示例撤掉相应的临时显示，保留读者实际做过的开关和拖放操作。选例、清例不写个人布局或问句开关，不移动、复制节点。
4. **两图怎样共用。** 两图把本图需要持续强调的节点和有向边交给同一处画布逻辑渲染。闭环图提供本例的步骤和边；依赖图选闭环时沿 [D042](../D042-loop-route-highlights/task.md) 提供经核实的参与文件，继续按版本、项目路径和文件存在性判定。它的真实依赖线照常可选，两份文件都参与闭环也不能据此推断调用经过了两者之间的边。依赖图保留现有的选择闭环、进入阅读、清除及后退体验。示例由闭环制作，文件依赖资料无需另写一份。
5. **高亮的视觉层次。** 复用现有画布、前景曲线、短标签和主题样式。允许优化原来的高亮格式，使普通浏览、持续路线、当前选中或键盘焦点容易辨认。路线除了颜色还要有清楚的节点和曲线形态，例如节点标记、适度加粗的实走边；D052 的红／绿语义色、库线虚线、箭头方向和键盘沿线焦点都要可读。短标签仍按空间避让。特别看选中分岔节点时，两条边即使同时可查，读者也能分辨哪条属于本例。本次颜色由共享主题样式负责，不增加逐例配色字段或读者调色操作。
6. **交付入口。** 从[现行 R16–R18](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)进入，增量维护[007 共用画布](../../../../../specs/007-dependency-canvas/spec.md)、[008 闭环制作](../../../../../specs/008-loop-authoring/spec.md)、[009 闭环阅读](../../../../../specs/009-loop-reader/spec.md)及受影响的模型、契约和验收。R18 关于跨版本的限制继续管依赖图投影，旧闭环可按自身固定依据阅读。按 [Spec Kit v1.4.0 增量约定](../../../../development/spec-kit.md#incremental-input)用 `speckit-specify`／`spec-template`、`speckit-plan`／`plan-template`、`speckit-tasks`／`tasks-template` 维护已有结构，编码前核契约变化的一致性。沿 `src/core/`、`src/application/` 的闭环制作、读回和现有 CLI，以及 `src/web/` 的共用画布、闭环阅读与主题入口实施。补齐[闭环制作指导](../../../../../skills/aftertaste-reader/references/loops.md)、[工具说明](../../../../../skills/aftertaste-reader/references/tools.md)及必要模板，让安装包 Skill 能通过 `create-loop` 正常制作，通过 `read-loop` 的 JSON 和 Markdown 读回示例、顺序与前提。

## 验证与停点

- **主试读。** 复用[订单原始讲解](../D051-loop-node-annotations/trial-input.json)和[带折叠结果的订单样例](../../../../../tests/fixtures/switch-legends.mjs)。两次各从空订单集合开始。选 `"04"` 点亮 `check → build → append`，读者可核对建单时集合仍为空、追加后才有一条；换 `"4.5"` 点亮 `check → reject`，整数校验抛错，写入走不到。验两条真实有向边或一条真实有向边的准确集合、原问句收起与已展开两种开局、快速切换、查源码后回来、清除后恢复。在有旁路连线的用例中，两个端点同在本例也不能把未走的捷径点亮。用固定提交说明示例结果的依据。
- **双图回归。** 在同一安装包上用真实页面选中依赖图的订单闭环、点文件或边、进入阅读再后退，再测不匹配版本的提示。对比两图的路线成员、局部焦点、短标签、库线和浅深主题；检查选例前后视野、拖好的坐标和已保存开关。可复用 [D042 浏览器检查](../../../../../tests/browser/loop-route-highlights.mjs)、[D052 边检查](../../../../../tests/browser/edge-labels.mjs)和 [D053 开关检查](../../../../../tests/browser/switch-legends.mjs)。
- **资料链路。** 用隔离项目及安装包走制作、校验、两种格式读回和实际阅读。核未写示例的旧闭环，以及无效步骤、跳边或逆向引用会指明输入文件、具体示例与出错位置，失败不发布半份成果。按影响在 `tests/unit/`、`tests/integration/`、`tests/browser/` 和 `tests/fixtures/` 补充断言。运行输出归 `.local/D054/<run-id>/`，本地检查串行，在独立资料副本与空闲回环端口试读；保留作者的 `4317` 和 `4351` 至 `4357` 既有资料与服务。
- 若须改写业务箭头、长期改动读者开关或扩大为教程播放与制作流程，带具体读者场景交回。其他问题沿共同修复停点。
