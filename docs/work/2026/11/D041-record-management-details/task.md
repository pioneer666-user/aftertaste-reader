# D041 · 书签与标注回读，三页详情对齐

## 目标与批准依据

实现任务。读者在书签、标注的左栏选中一条，紧邻列表就能看到自己的原话，再读几句它所指的当前讲解，决定是否回到原块。切到笔记，目光落在相同的正文起点，接着读笔记里的引用。

2026-11-22，作者在 D040 接回时指出两个管理页「有点空落落的」，要求连续圆角「能复用的还得复用」。主脑用作者已有的同块书签和疑问演示了新的[书签排版](bookmarks-reference.png)与[标注排版](marks-reference.png)。作者认可后补充「把笔记的管理页面**把详情移近**。这样统一。然后你出任务吧，把这些都做了」。[笔记版前截图](notes-before.png)是此次补充的依据。示意中的简化顶栏仅用于对照两个页面，正式产品沿用现有顶栏。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

仓库 `D:/project/SpecDev Harness/aftertaste-reader`。从 `dev@dda1564` 派单，任务分支 `codex/feat-record-management-details`，批准提交随转交消息给出。4342 是已合入 dev 的 D040 产品候选 `4653421`，使用作者正在试读的订单项目。[D040 回执、资料位置及换版依据](../D040-margin-record-editors/handoff.md)

1. **三页用一条正文起线。** 桌面展开左栏时，书签的理由、标注的疑问、笔记的标题和正文从同一处开始。详情靠近侧栏，长文保留行宽上限，右侧多余空间自然留白。笔记只调整详情位置，保留标签筛选、默认阅读、文内引用、编辑／预览和读写操作。桌面编辑仍有足够宽度左写右预览，窄窗选条目后读整宽详情；收栏、重新展开和返回均可继续读原来的条目。
2. **理由或批注放在详情第一眼。** 以小号「收藏理由」或灰 `○ 未标记`、绿 `✓ 已理解`、红 `? 不理解` 标明类型，完整展示读者原话及换行。状态用文字、符号和颜色同时辨认。空理由或空批注用可辨认的块标题带出记录，辅以一次「无备注」或「无批注」。下面的「当前讲解」显示同一块的标题、两三句可读原文、短来源和「回原文」。标题或首句已用作回退时只呈现一次。摘录取当前讲解，记录按块绑定，正文改写后看到该块当前内容。
3. **让左栏便于扫读和直接回访。** 列表标题旁显示当前条数。每行给理由或批注一至两行，下面用短文件名配实际行范围；纯讲解块用块定位，同名文件给足区分信息。原来的「回原文」从每行下方移到独立常显的行尾箭头。点行读详情；点箭头或详情里的文字入口，一步打开原块，书签聚焦所点的那一条，标注展开当时的批注。箭头在悬停和键盘聚焦时说明「回原文」，触屏有至少 44 × 44 CSS px 的独立命中区。标注筛选将已有的「全部／不理解」平铺，切换后能读出当前筛选、数量及空态。两页已有刷新、加载、读取失败与重试入口继续可达。
4. **来源能核对，缺失也能读回自己的话。** 默认收起「完整定位」，展开可查看、选取完整文档路径与块 ID。用项目内文档路径和块 ID 匹配讲解，书签的个人身份仍用书签 ID。快速选条目时，摘录、标题和行号只跟随当前选择；有讲解、缺源码的块仍能显示已有讲解。遇到缺文档、缺块或解析失败，在本条保留原话、完整定位、具体提示和重试。临时读取不改绑、不写回个人记录；加载摘录也不进入阅读历史。原文读不到时，详情第一行仍可读。
5. **复用连续圆角。** 沿用 [D029 连续圆角](../../../../../specs/006-file-reader/plan.md#d029-连续圆角)与 D040 的状态表达。控件用 9 px、列表选中行用 14 px、讲解摘录面板及两页「原文暂不可定位」提示用 21 px 档。复用 Firefox 现有绘制回退，保留清楚的键盘焦点及强制色轮廓。当前刷新、筛选和记录行已有相应基础样式，新的表面直接接入同一套。

**实施入口。** 产品依据为 [08 R13–R15](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)、[006 FR-020](../../../../../specs/006-file-reader/spec.md)，以及 [010 书签](../../../../../specs/010-block-bookmarks/spec.md)、[011 笔记](../../../../../specs/011-project-notes/spec.md)、[012 标注](../../../../../specs/012-understanding-marks/spec.md)各自的 FR-009／SC-005。执行按 [Spec Kit 增量流程](../../../../development/spec-kit.md#incremental-input)用 specify、plan、tasks 和生效模板维护受影响分册，三页共用布局放 006，阅读记录行为归各自分册；analyze 核对后按 implement 实施。按[项目技能适配](../../../../development/skills.md)使用 Ponytail full 与 Impeccable，更新[阅读器使用说明](../../../../usage/file-reader.md)中的实际步骤。

从 `src/web/RecordWorkbench.vue`、`style.css` 的 `.record-sheet`、`App.vue` 的项目书签、`ProjectMarks.vue` 和 `ProjectNotes.vue` 入手。复用当前文档读取、已解析块、`markdown.ts` 的块标签与 `reader-corners.ts`。已有 `GET /api/document` 可读讲解；优先按需复用同文档结果，列表可先显示可用的文件与块。异步预览与阅读器切篇、滚动、焦点分别处理。沿用个人记录格式及保存协议。

## 验证与停点

1. **同一窗口比较三页。** 派单时用 Edge 在 4342 打开现成记录，三页均已展开左栏。1705 × 919 CSS px 下，侧栏右缘为 340，选中记录正文左缘为 649.03，间距 **309.03 px**；1440 × 900 下三项分别为 331.19、512.13、**180.94 px**。全程零写请求。候选在相同两种桌面视口测侧栏右缘到正文首行的间距，以 **32–56 CSS px** 为目标，三页同窗差不超过 **1 CSS px**。同时实看长笔记行宽、双栏编辑、侧栏收展；390 × 844 验列表切整宽详情、窄窗编辑／预览与触控。回执给三页同尺寸实图和坐标。D038 笔记候选 `da10bbc` 在 4341 单独试读，两线共用上述详情容器。以最终布局规则在 D038 隔离页核一次笔记正文与引用的兼容性，标明验证组合；本单从已合并 D040 的 dev 实施，4341 留作 D038 验收。
2. **用同块的两种原话回读。** 在 `src/rules.mjs` 的 `x4y6az2y`，从书签读「这个边界例子讲得巧」，从「不理解」读「为什么要先校验数量？」，两边都看见当前块「数量规则承担转换与边界检查」的真实摘录及第 1–7 行。同块两条书签分别从行尾和详情回访，核对应的书签 ID；标注回访核原状态与疑问。两页后退均恢复原选中、筛选和左右滚动位置。笔记用《数量无效时，订单去哪了？》点第一处引用、后退、Tab 接第二处。另核空理由、无批注、仅有批注的未标记块、无行号纯讲解及无记录／无匹配，键盘和触屏都能区分选条与回访。
3. **用隔离副本验证容易读错的情形。** 同 ID 不同文件、同 ID 原块改写、快速切条且首个请求晚到、块暂缺后恢复。核摘录对应正确、原话完整、完整定位和重试可用；查看、筛选、展开定位、回访及后退均零个人资料写请求。Edge 主验，Firefox 核选中行、摘录面板和失效提示的实际连续轮廓，补键盘焦点、强制色与窄窗的行尾命中。沿用 `tests/browser/record-workbench.mjs`、`reader-history.mjs`、`bookmarks.mjs`、`understanding-marks.mjs` 中受影响的入口和断言，串行执行。已有 D040 保存与草稿证据用于行为未变部分。
