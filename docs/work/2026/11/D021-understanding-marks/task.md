# D021 · 块级理解标注与批注

## 目标与批准依据

读者在讲解块旁标出自己的理解状态。没读懂时可以写下卡在哪里，读懂后也可以写下自己的解释。下次打开项目，可从「标注」找到当时没懂的块，回到原处读批注、改标或补写。同一块还可以有书签，分别记下“我是怎么理解的”和“这里为什么值得回看”。

2026-11-19，作者接回 [D020](../D020-project-notes/handoff.md)，认可改成「已理解」或改回「未标记」都保留原话，由读者决定修改或清空。随后明确“标注旁边的叫批注，一般是给未理解用的，写上为什么没理解，也可以给已理解用啊，写上怎么理解的”，并说明书签更关注“讲解的巧妙，或者这里是重点”。作者指示“然后你出任务吧”。本单为实现任务，先提供可用的块内操作和简单列表。个人记录的整体查漏和管理页面优化按[阶段安排](../../../../product/backlog.md)接续。

| 场景 | 本单交付的读者行为 |
| --- | --- |
| 标出理解程度 | 正常的源码对照块和纯讲解块都提供「未标记／已理解／不理解」，默认未标记。读者可单独改状态、改回未标记，也可以跳过标注继续读文件或闭环。 |
| 写下理解上的批注 | 状态旁提供「批注」，可留空。「不理解」下能记原因，「已理解」下能写自己的理解。改标保留批注原文，由读者编辑或清空。只改批注保留当前状态。退回「未标记」仍可重开看到、修改或清空原批注。 |
| 找回当时卡住的位置 | 项目内提供简单的「标注」入口。列出当前标为「已理解」「不理解」的块，以及未标记但留有批注的块。可按「不理解」筛选，看到文件、块和原话，点回当前讲解的对应块。记录按文档路径＋块 ID 归属。列表按当前状态筛选，带旧问题的已理解或未标记块也按各自状态归类。 |
| 讲解时参考个人记录 | 状态和批注保存到本项目的个人资料，讲解 AI 按需只读。给 AI 的资料区分当前自评与批注原文。读者改为已理解后，即使原话还是问句，也应尊重当前自评。书签备注、全局笔记和理解批注可同时存在，各自由读者管理。 |

普通讲解改写或重排时，同路径同 ID 的标注与批注保留。拆分或合并产生的新 ID 从未标记开始，原批注保留原定位。目标暂时不可读时保留个人资料，回访如实提示。R15 规定，正式源码版本更新引起块内容变化时，保留原自评并提示读者重新确认。该提醒适用于三态。普通改写和编辑批注均不产生版本变更提醒。真实更新触发、确认和提醒保留由版本更新任务接入并联验。

## 验证与停点

1. **从没懂到读懂，再回看自己的原话。** 在隔离项目给一块标「不理解」，写“为什么要先校验数量？”，同时给该块加一个备注为“这个边界例子讲得巧”的书签。关页停服务，重开后从「标注」筛出不理解，跳回原块。改为「已理解」，核原问句仍在，且该条已退出不理解筛选。再把批注改成自己的解释，改回「未标记」，重开核当前状态和解释均正确。只清空批注，核书签备注仍在、项目笔记内容不受影响。
2. **核空批注和跨文件定位。** 用[两个文件含相同块 ID 的样例](../../../../../tests/fixtures/bookmark-project.mjs)分别标注对照块和纯讲解块。在一个块上直接标「已理解」并写自己的理解，另一个只标「不理解」并留空。逐一从列表回访，核文件、块、所选状态和焦点。再按上述身份规则检查同 ID 改写、新 ID 和暂时不可读，核正常阅读仍可继续。
3. **核读回与保存失败。** 从正式项目文件依照最终 Skill 说明读回状态和批注，覆盖一条保留旧问句的「已理解」记录及一条带批注的「未标记」记录。在隔离资料上制造实际保存失败，页面如实显示失败、保留输入供重试，旧文件保持完整。覆盖同一服务内两个页面修改同块的情形，避免陈旧写入静默覆盖已存批注。

在 `tests/` 沿现有单元、真实 HTTP、浏览器和受影响的 Skill 检查选取证据，按影响串行验证。Windows／Edge 主验，使用 `.local/D021/<run-id>/` 下的独立项目和构建。区分本次可验证的当前块行为与 A16 的正式版本更新部分。
