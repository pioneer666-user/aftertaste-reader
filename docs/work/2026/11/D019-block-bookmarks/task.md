# D019 · 块级注解书签与回访

## 目标与批准依据

读者在一块讲解旁加书签，可以只收藏，也可以写一句自己的注解。关掉阅读器，下次只需从本项目的书签列表选中这一条，就能回到原块，看到当时写的话。

2026-11-19，作者接续 [D018 交接](../D018-skill-validation/handoff.md) 后确认：“首版就先做块级注解书签。整篇讲解我经常翻看也是会选择只打一两个书签”，并说明“会给书签，标注，笔记都做管理页面。但是具体的页面等优化ui的时候再去做，现在能简单实现就简单实现。”本单为实现任务。首版主动收藏的单位定为块，本批提供可用的简单书签列表。正式管理页面留到 UI 优化阶段。全局笔记和理解标记分别派单。

## 验证与停点

1. **从收藏走到回访。** 在隔离项目的真实阅读页，给一个非首块留两条书签，其中一条写理由，另一条留空。再给另一篇文档中的纯讲解块留一条。关页、停服务，重新启动同一项目，从「书签」回到所选原块并读到对应备注。改一条、移除另一条，重开核磁盘与页面一致。用不同文档中相同的块 ID 检查跨文件定位。
2. **暂时失去目标，再找回来。** 用隔离样例改写讲解并保留块 ID，再让该文档暂时无法解析或读取。从列表查看同一条记录，核提示、原定位、备注与磁盘，恢复文档后再次回访。不能以手工移除样例文档充当正式更新已确认删除的证据。
3. **保存失败时保住文字。** 在隔离资料上使一次写入失败，核原记录仍完整、页面显示失败并保留输入，恢复后重试只产生预期结果。覆盖同一服务两个页面对书签的实际竞争，防止用旧列表覆盖其他已保存操作。用真实接口核项目写入边界。

复用[已有阅读样例](../../../../../tests/fixtures/reader-project.mjs)，在 `tests/` 沿现有单元、集成、浏览器用例补受影响检查。Windows／Edge 主验，按影响串行做兼容检查。运行材料归 `.local/D019/<run-id>/`，以本单隔离试读项目和构建提供体验入口。交回时分列本单已验场景和仍依赖版本更新的场景。
