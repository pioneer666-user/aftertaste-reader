# D016 · 在共用画布上阅读已保存的闭环

## 目标与批准依据

读者从本地阅读器选一条已保存的闭环，看懂它从哪里开始、在哪一步分支，能打开一个教学步骤对照当时的讲解与源码，也能摆放节点和图例，下次打开接着读。

2026-11-18，作者在 D015 合入本地 dev 后要求“然后出下一单吧，有需要讨论的吗？”。本单落实此前商定的第二步，承接 [D015 闭环成品](../D015-loop-authoring/handoff.md)。产品依据为 [04 两图共用画布](../../../../../specs/001-first-release/04-reading-modes.md#shared-graph-canvas)、04 U80／U95 和 [08 的 R16—R18、A17—A19](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md#graph-layout-acceptance)。本次交付已保存闭环的本地阅读与个人布局。依赖图上的路线高亮、闭环更新及历史、内容编辑、整页 UI／UX 打磨留给对应任务。

## 验证与停点

1. **在真实页面读完订单的两个结果。** 用 [D015 订单样例](../D015-loop-authoring/sample/order-quantity.md)及其正式创建工具重建成品。从阅读器选中它，从校验步骤分别追到追加订单与提前退出，核页面实际显示的关系及理由。将“服务先交出原始数量”和“规则返回后回到服务”分别摆放，确认两步指向同一块源码，却仍各有讲解和坐标。改写外部当前讲解后核旧闭环仍显示已保存内容；在隔离样例中让一处固定源码不可读，核其他步骤、原讲解和布局均可用。
2. **把不同图摆成不同样子。** 用适合的第二条路线经正式工具创建带库图例的闭环，复用 [D015 图例集成样例](../../../../../tests/integration/loops.test.mjs)。在该闭环与依赖图中对同 ID 图例分别编组、拖动、调整视野；在闭环中核移出、拖组仅带成员及保组重排。与订单闭环来回切换，关页、停服务，用新会话重开。对照真实磁盘，核三张图各自恢复，内容文件在布局操作前后字节一致。
3. **查一次容易串图的操作顺序。** 在闭环 A 有未完成的加载或保存时切到 B 并操作，让 A 的结果迟到。核页面当前显示、两份磁盘布局及保存状态各有正确归属。另核同图旧版本保存不能覆盖新排布、写失败能如实提示并保住草稿供重试。已有依赖图兼容性按共用代码的实际变化复验；闭环新增、删除步骤后的布局协调随闭环内容更新任务验收。

真实浏览器以 Windows／Edge 主验，Chrome、Firefox 串行做受影响的兼容检查。运行资料放 `.local/D016/<run-id>/`，使用独立试读项目、构建和端口。若实现必须覆盖已有布局、改变内容编辑权限或要求讲解 AI 重新生成 D015 成品才能阅读，带具体使用后果交回主脑。
