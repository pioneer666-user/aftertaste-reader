# D029 · 文件讲解页与共用顶栏的连续圆角

## 目标与批准依据

类型为实现。打开文件讲解，读者从顶栏、文件树看到源码，再选一段文字或展开一条批注，沿途有底色、边框或高亮的控件应呈现同一家族的连续圆角。紧凑控件干净利落，大面板的直边平滑转入四角，正文维持现有阅读密度。

2026-11-20，作者在 D028 验收后提出「先开一单把前面的文档页面的圆角统一」「把该改成连续圆角的都改了」「你出一单吧」。范围承接 [B006](../../../../product/backlog.md#b006--个人阅读记录做完后查漏再集中优化页面) 记录的顶栏页签、文件树与块目录选中项、源码面板等。排序先于闭环页优化。视觉参照取作者认可的 [D027 依赖图节点](../D027-dependency-canvas-polish/handoff.md)，顶栏布局及当前试读沿 [D028 验收版](../D028-reader-history-canvas-tools/handoff.md#作者验收与本地整合)。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

执行先沿现有入口盘点实际可见表面，包括仅在悬停、选中、展开、禁用、回访、键盘焦点或出错时显出的底色与边界。小按钮、整行选中底和大面板分档，检查紧凑和多行时的四角；填充、边线及焦点沿同一形状，边缘干净，留得住文字。顶栏与侧栏贴窗的一边、树的连接线、分隔线、图标笔画、原生菜单选项和滚动条各自遵循原形。纯讲解块、普通段落和表格格线沿用阅读排版。图及三个记录管理页的内部表面留给各自批次。

实现落在 `src/web/`。从 `style.css`、`App.vue`、`ReaderDocument.vue`、`BlockLocationControl.vue` 及块后记录组件核作用域。基础按钮和 Markdown 样式跨页使用，`.selection-float` 还用于图上分组；共享顶栏以外的改动限定在文件讲解的实际入口。用少量可复用的轮廓和尺寸定义，方便后续页面沿用。[节点现有轮廓](../../../../../src/web/DependencyCard.vue) 用同一条固定比例 SVG 路径描绘表面与焦点；[画布浮层](../../../../../src/web/canvas.css) 已有按支持情况启用连续角的做法，另有作者认可的圆头工具。可变宽高控件要以各自的真实尺寸成形。主验窗口须能看出直边平滑转入圆角；兼容引擎按实际绘制选用原生能力或等效轮廓，回执注明实测方法与差异。

既有产品依据为 [006 文件阅读](../../../../../specs/006-file-reader/spec.md#functional-requirements) 的 FR-007 至 FR-014。按 [Spec Kit 增量约定](../../../../development/spec-kit.md#incremental-input)，在 006 原位置用 specify、plan、tasks 对应技能及生效模板只维护受影响的视觉要求、方案和验收入口；现有尺寸、行为和通过证据直接引用。产品代码沿仓内 Ponytail 与 Impeccable 局部实图检查，独审沿 Ponytail Review。正式回归按影响复用 `tests/browser/`，运行产物归 `.local/D029/`。

## 验证与停点

构建后先用[共用试读订单项目](../../../../../tests/README.md#页面改版共用试读)的固定副本实际阅读，再补局部回归。对比基线和候选时固定文件、块、缩放、视口和控件状态，保留整页图看比例，配一组原尺寸局部看轮廓。用作者能重新打开的同一篇讲解观察以下路径。

1. 在桌面打开 `src/service.mjs`，选中目录项后跳到正文中段，看文件行、块目录和源码底板。打开项目资料浮窗，用键盘关闭，观察焦点落回项目名；再滚动到块尾及横移一行长源码，核底板停留、行号与首末字符。普通和窄窗、长源码采用 [006 已定试读场景 SC-009 至 SC-013](../../../../../specs/006-file-reader/spec.md#measurable-outcomes)。
2. 选一段讲解触发浮条，实际复制；在隔离输入上复用剪贴板拒绝路径，核手动文本框仍能选取。展开该块书签或批注，查看编辑或回访焦点。分别观察外壳和内部控件、光标靠近屏边时的操作、键盘描边是否完整。窄窗点开页签菜单，用键盘切页再回来，核当前项、触控热区和顶栏位置。
3. Edge、Chrome、Firefox 串行实看相同代表控件，记录真实显示与回退。首选用「小按钮焦点、整行选中、宽源码板」三种不同尺寸作前后对照；仅检查 CSS 属性或统一加大半径不足以判断外观。另看一次系统强制色下的键盘焦点。短访依赖图和一页记录管理，核共用顶栏，并对照已审图节点、图上分组浮条及管理页内控件的边界。

执行冻结候选与输入后，委派独立审查者按以上路径亲手走桌面、窄窗和一次非常规状态。派审时把每个场景与对应的前后图片及操作证据配对。修复后用原失败输入复验，补受影响路径。若某类可变尺寸轮廓影响原生选择、滚动、焦点或点击区域，先更换该类的绘制方式；确须改变既有阅读操作时将该项取舍交回主脑。
