## 验证与停点

1. **清单和读回来自同一棵树。** 在隔离样例准备提交 A 与文件集有明确差异的提交 B。对 A 启用本地 Git 对象替换，再单独在宿主环境指定另一个仓库。两种情况下照最终 Skill 操作，核完整的预期路径集合，确认 A 独有文件列出且读回 A 的内容、B 独有文件不会混入。覆盖根项目与带空格或中文的子项目，并让一个名称前缀相似的相邻目录保持在子项目范围之外。用普通 UTF-8 文件对照结果。
2. **大于默认缓冲的结果仍完整。** 通过正式 `pin → read` 和最终示例读取含换行、引号或反斜杠的 UTF-8 合成文本，使 JSON 超过 1 MiB。核解析结果、路径、提交和完整正文；记录字节数或摘要。说明接收策略如何覆盖 JSON 转义开销。用一次受控的调用失败核状态和诊断，结果与日志中避免泄露源码正文。用小样例验证即可。
3. 可复用既有 [Skill 测试](../../../../../tests/skills/) 和相同版本的取源回归；针对本单新增行为检查优先落在 `tests/skills/`，运行输出放 `.local/D017/<run-id>/`。至少一次按最终公开说明原样运行。仅检查提示词里出现了哪些选项，无法证明两项已修好。

若修复必须改变用户选文件的步骤、既有取源上限或源码保存方式，带具体输入与使用后果交回主脑。
