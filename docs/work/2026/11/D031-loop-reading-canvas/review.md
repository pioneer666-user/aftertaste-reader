### 已确认问题

#### 1. Must fix · 桌面固定源码后直接缩窗，内联面板仍保留桌面宽度并被裁切

- **位置**：`src/web/LoopReading.vue:103-121`，尤其是桌面写入 `panel.style.width/left/top/maxHeight` 后，内联分支在 `:113` 直接返回；`src/web/canvas.css:464-470`。
- **触发场景**：在 1440 × 900 CSS px 桌面窗口打开闭环步骤并固定源码，不关闭面板，直接把窗口缩到 390 × 844 CSS px。
- **独立预期**：按 009 FR-003 及任务单“窄窗或并排空间不足时，在当前步骤内展开”，面板应转为可用的窄窗内联布局，源码和关闭入口均留在视口内。
- **实际结果**：面板 class 已变为 `loop-source-inline`，但实际宽度仍为 520 px、x=33；关闭按钮 x=508，完全位于 390 px 视口外。文档宽度仍报告 390，是工作区裁切的结果，并不代表面板可用。直接以窄窗打开源码则正常，因此仅覆盖窄窗首次打开的既有测试没有暴露此路径。
- **原因与影响**：桌面定位写入的内联样式没有在进入内联模式时清除，`.loop-source-inline { width: 100% }` 无法覆盖内联 `width`。读者缩窗后无法看到完整源码，也无法用视口内的关闭按钮收起面板。
- **建议**：进入内联模式时清除桌面定位样式，并增加“桌面固定后直接缩窗”的回归，不只测试窄窗首次打开。
- **实测证据**：`.local/D031/review-edge-wxolhm`；关键几何数据已记录在本条。

#### 2. Must fix · 从长文底部直接点另一图节点，不会从新步骤开头接读

- **位置**：`src/web/LoopReading.vue:33-39` 的内部 `selectStep` 会重置阅读栏；图节点改走 `src/web/DependencyCanvas.vue:407-411` 的 `selectDetail`，只更新选中值。
- **触发场景**：打开内容较长的闭环步骤，把右侧阅读栏滚到底，再直接点击图中的另一节点；不要通过分支行、上一步或下一步按钮换步。
- **独立预期**：任务单“右栏读步骤”明确要求“长文和多条理由都能读到底，换步后能从新步骤开头接读”，该要求不区分换步入口。
- **实际结果**：换步前阅读栏 `scrollTop=326`（当时最大值 326）；点另一节点后变为 344，仍停在新步骤底部附近，而不是标题和正文开头。分支及上一步／下一步路径会归零，但直接点节点这条主要选步路径没有。
- **影响**：连续阅读会落在新步骤末尾，读者可能漏读标题、源码入口和开头讲解。
- **建议**：让图节点选择与阅读区换步共用重置及焦点策略，并用长内容补一条“阅读栏到底后直接点另一节点”的回归。
- **实测证据**：`.local/D031/review-edge-wxolhm`；关键滚动数据已记录在本条。

#### 3. Must fix · 所有闭环和依赖图共享同一个工具条开合状态

- **位置**：`src/web/App.vue:65` 定义单一 `canvasToolsOpen`；`:145-160` 的顶栏计算与切换直接读写该值；`:941-942`、`:961-962` 把同一值传给依赖图和所有已打开闭环。
- **触发场景**：在订单闭环用顶栏收起工具条，切换到路径工具闭环；在路径工具闭环展开工具条，再返回订单闭环。
- **独立预期**：`specs/009-loop-reader/data-model.md:8` 明写“每图工具条仍由顶栏控制，状态不归其他图”；FR-008 也要求“闭环和依赖图各自管理选择、工具及保存布局”。顶栏应控制当前图，而不是把开合状态传播给其他图。
- **实际结果**：订单闭环收起后，路径工具闭环也已收起；在路径工具闭环展开后，返回订单闭环会看到它同样被展开。
- **影响**：不同图的界面状态相互污染，切换图后不能保留各自的阅读／操作布局；本次未发现该问题写入布局文件，后果限于页面工具状态。
- **建议**：按图实例或图 ID 保存工具条开合状态，顶栏只读写当前活动图；用至少两条闭环及依赖图交叉切换做回归。
- **实测证据**：`.local/D031/review-edge-wxolhm`；上述双向切换结果来自真实页面操作。
