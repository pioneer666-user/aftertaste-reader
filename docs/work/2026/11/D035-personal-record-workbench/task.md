# D035 · 个人记录工作台与笔记读写

## 目标与批准依据

类型为实现。让读者从左栏找回个人记录，在中间读原话，打开引用后还能接着原处读。第一单统一笔记、书签、标注三个页面的骨架，把笔记的查找、阅读和编辑走通。

2026-11-22，作者在主脑会话要求「首先统一这三个页面都是左侧边栏加中间显示详细数据的标准后台工作台形式」「点开一个笔记后，应该默认就是看笔记」「编辑的时候我觉得换成左编辑右预览的形式比较好」，并提出按标签搜索和筛选。主脑说明过工作台首次选择、书签与标注一步回原文、笔记桌面并排及窄窗切换。作者随后确认「行，可以，我们先出一单……你出一些合适的。不用一单全部出完」。主脑据此分批。顶栏全局新建、讲解选区图标浮条和讲解块焦点外观排在本单之后，入口方向记在[项目待办 B006](../../../../product/backlog.md#b006--个人阅读记录做完后查漏再集中优化页面)。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

仓库 `D:/project/SpecDev Harness/aftertaste-reader`，产品基线 `dev@3ba3f18a5149f65ec157f73897db25f2f352a8a8`，任务分支 `codex/feat-personal-record-workbench`。批准提交由派单消息给出。旧主脑交接在 `b87cd8d` 的 D034 回执，原分支保留；本单从 dev 起步。4341 的订单试读和副本用法见[试读资料说明](../../../../../tests/README.md#页面改版共用试读)。

- **共用工作台。** 顶栏下左侧是当前页面的记录列表和已有筛选，中间展示所选记录。三页接入现有顶栏侧栏开关，桌面可收起列表专心阅读，窄窗能打开列表、选一条并回到整宽详情。沿用现有视觉系统及连续圆角。首次进入有记录时，展示第一条；切筛选后优先保留仍可见的选中项，否则显示首条匹配，零条时交代空态并可清除筛选。站内后退优先恢复当时选中项、筛选和列表／详情各自的阅读位置。单纯查看、筛选或返回不会写个人记录。
- **笔记先找、再读。** 左栏支持输入部分标签文字查找已有标签。输入「回」能找到「回访」，选定后按完整标签筛笔记，清除可看全部。已有笔记直接排版显示正文、标签和可点击的引用，编辑入口容易发现。读完一个引用按站内后退，原句回到视野，键盘也能从该引用接着走到下一处。
- **要写时再编辑。** 在笔记页点现有「新建笔记」直接开写，已有笔记点「编辑」进入。正文区域在桌面左写 Markdown、右看实时预览；窄窗在「编辑／预览」间切换，保留正在输入的内容。标签增删在编辑时操作。「完成」回阅读态，沿用正文与标签的自动保存、撤销及冲突／失败反馈，保存中的输入和失败后可重试的草稿都要可找回。讲解页现有选文入口仍能新建带引用的笔记或明确选择一篇后追加；默认展示首条不能变成自动追加。
- **书签和标注。** 左栏选条目时中间分别突出完整的收藏理由、当前理解状态与批注原话，能辨认文件和块。列表内另有一步「回原文」操作，详情也能回原文。同一块的两条书签可分辨、定位到指定那条；无备注也能找回。标注沿用「不理解」筛选。管理页使用已有阅读与回访能力，本单重点在看清这条记录和找回原处。

**实施入口。** 依据 [08 现行规格](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)、[011 笔记](../../../../../specs/011-project-notes/spec.md)、[010 书签](../../../../../specs/010-block-bookmarks/spec.md)、[012 标注](../../../../../specs/012-understanding-marks/spec.md)及 [006 侧栏与站内历史 FR-011、015、016](../../../../../specs/006-file-reader/spec.md)。按[Spec Kit 增量流程](../../../../development/spec-kit.md#incremental-input)，用 specify、plan、tasks 及生效模板在既有分册维护各自受影响的场景、方案和任务，以 011 为笔记读写主定义。编码前用 analyze 核对覆盖，再按 implement 执行。沿用个人记录格式与存取接口。界面从 `src/web/ProjectNotes.vue`、`ProjectMarks.vue`、`App.vue` 的书签与历史、现有笔记编辑器、样式与双语文案接入。按[项目技能适配](../../../../development/skills.md)使用 Ponytail full、Impeccable 的主要交互重设流程，沿用已定取舍。用户说明更新[阅读器说明](../../../../usage/file-reader.md)，正式回归归 `tests/browser/`，可重建证据归 `.local/D035/<run-id>/`。

## 验证与停点

1. **从一句话接着读。** 现版 4341 在 1440 × 900 下，订单笔记两条引用都能打开，第一条返回后仍选中「回访」和原笔记；可点击的句子位于视口约 730 px 处，上方是编辑框。候选上搜「回」选「回访」，阅读《数量无效时，订单去哪了？》，开第一处到规则文件，后退接着点第二处到服务文件。另在隔离副本用必须滚动的长笔记，从视口中段点引用后返回，实际核可见原句、键盘续读和侧栏位置。查无匹配、空笔记、链接失效时的提示与恢复。
2. **从读切到写。** 桌面和窄窗各走一次编辑、预览、完成、读回；隔离副本验证新建、改正文与标签、自动保存后撤销、切条目以及一次真实保存失败后的恢复。检验旧选文入口追加到已有笔记和从选文新建均可用，原文和原有标签能读回。复用[笔记测试](../../../../../tests/browser/notes.mjs)与[站内历史测试](../../../../../tests/browser/reader-history.mjs)的有效覆盖。
3. **同块，两种回访理由。** 在书签列表找到「这个边界例子讲得巧」，从「不理解」标注找到「为什么要先校验数量？」。各自在详情读原话，再实点列表的一步回原文，核规则块 `x4y6az2y` 中目标书签或批注及返回后的条目、筛选和位置。在副本覆盖同块多书签和改标后原批注保留。三页实际操作侧栏开合，核窄窗、键盘和中英文下的读写与导航。沿[书签](../../../../../tests/browser/bookmarks.mjs)和[标注](../../../../../tests/browser/understanding-marks.mjs)测试维护受影响的预期。

共用试读项目在 `.local/2026-11-19-page-preview/project`，保留作者当时实际笔记、书签、批注和布局。新建、追加、改标、删除、失败注入及长文造例只在隔离副本操作。自测以真实浏览器串行走上述场景。冻结提交、构建和输入后，执行调用独立审查子代理，用另一份副本实走长文返回、编辑保存和同块两种回访。修复后复走原失败路径。若需改写作者资料方能实现，先交回影响。
