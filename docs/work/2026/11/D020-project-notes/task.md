# D020 · 项目内全局笔记与跨文件回访

## 目标与批准依据

读者可以随手记下一个问题。读到有关联的两处讲解时，把两段选文分别加入同一篇笔记。下次打开项目，按标签找到这篇笔记，点其中任一段就能回到对应讲解块。

2026-11-19，作者接回 [D019 块级书签](../D019-block-bookmarks/handoff.md) 后，主脑提议“读到一句值得记的讲解，选中文字后点「加入笔记」，能选一篇已有笔记，也能当场新建；插进去的文字可以点回原块”。作者答复“可以，你出任务吧”。本单为实现任务。沿用作者对个人记录阶段的安排，先提供简单可用的笔记入口、列表和编辑界面。正式管理页面留到集中 UI 优化，块级理解标记另行派单。

## 验证与停点

1. **从问题读回两处依据。** 用[现成的同块 ID 双文件样例](../../../../../tests/fixtures/bookmark-project.mjs)，先在「笔记」独立新建一条无来源记录。再从第一篇选一段讲解，当场新建含链接的笔记。到第二篇选另一段，加入刚才的笔记，补上自己的问题和两个标签。等待已保存，关页停服务，重开同项目后按标签找回。逐一点击两段选文，核实际文件、滚动位置及焦点。至少有一个目标块从未被收藏。删除一条记录后再开，另一条的文字、链接和标签仍齐全。
2. **等到已保存，再撤销。** 在真实浏览器里输入两次可区分的内容，等一次自动保存完成后按 Ctrl+Z。核编辑器允许撤销，撤销后的结果再次自动保存，刷新后与磁盘一致。覆盖连续输入时较早请求迟到的情况，核最新正文及保存状态。用隔离项目制造一次实际写失败，确认旧文件完整、草稿可继续编辑，恢复后重试无重复。沿本机服务已有约定检查两页操作不会静默覆盖已保存的修改。
3. **一个链接失效时，仍能读其余内容。** 在隔离样例中保留块 ID 改写讲解，再使其中一处目标暂缺或无法解析，观察同一笔记中的两条链接。还原后点击原链接能再次回访。核原选文、笔记及其他链接均保留，未顺带新建或修改书签。真实版本更新后的诊断在回执中与本次样例证据分列。

在 `tests/` 沿用单元、真实 HTTP 及浏览器用例的现有落点，按影响串行验证。Windows／Edge 主验，运行材料放 `.local/D020/<run-id>/`。给作者的试读使用本单构建和隔离项目，保留 D019 的试读资料。若方案需要改变笔记的数据去向、让 AI 写用户正文或依赖整套版本更新才能记笔记，先带具体使用后果交回主脑。
