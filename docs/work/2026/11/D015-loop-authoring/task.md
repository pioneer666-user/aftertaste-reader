# D015 · 生成并保存一条跨文件闭环讲解

## 目标与批准依据

让读者从已有逐文件讲解中挑一个想弄懂的业务过程，由讲解 AI 对照固定源码把它串起来，保存后能重读这一版。作者于 2026-11-18 接回 D014 后授权“就是这个闭环，没有就可以出任务，有就先讨论”。沿上一轮讨论的两单安排，本单交付选路线、串讲、保存和读回。闭环阅读页面、共用画布交互和依赖图高亮由后续任务接入。

依据为 [04 的 U47、U80、U81、U95](../../../../../specs/001-first-release/04-reading-modes.md) 与 [08 的 U101、R17 和 A19](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)。U95 确认闭环有针对本次目标的独立讲解，U101 确认只持久保存源码引用。本单验收 A19 的闭环 `current` 部分。跨版本更新、历史、重做，以及学习记录的写入方式留待各自任务。

## 验证与停点

1. **走完一条有成功和失败结果的路线。** 用[现有订单样例](../../../../../tests/fixtures/dependency-canvas.mjs)重建固定提交、文件图和[两篇原讲解](../D010-generation-skill/sample/README.md)。从调用 `createOrder` 开始，读者选择“数量校验怎样决定集合会不会改变”。用真实 Skill 与工具生成可读成果，沿服务 → 数量规则 → 服务说明合法数量怎样使订单加入集合并返回，无效数量在哪一步退出。由执行核源码和讲解，交回一份作者能直接阅读的结果。只登记了节点而没有逐块讲解的接口文件，可用于检查资料不足时的说明。另以合适的输入核所用图例能独立保存，不给订单示例强塞无关库。
2. **换会话后重读。** 在隔离项目中保存闭环后改写原逐文件讲解，改变当前工作区源码或 HEAD，再从新进程读同一闭环。对照之前保存的讲解、边、推荐顺序及源码引用，核实讲解仍为原文、源码来自原提交。让隔离样例的一条 Git 引用暂时不可读，确认讲解仍在、诊断能指出具体来源。核本次新增的持久资料没有复制所引用的源码。
3. **检查失败写入。** 用失效块引用或悬空连线尝试创建；再核针对已有闭环的重复创建与一次保存中断后的重试。核最终磁盘内容，确认有效闭环保持完整，未完成的成果不会被当成可读成品。结构校验交给工具；“这条线是否把因果讲清”由作者读交付样例判断。

若必须改动用户选路线的时机、放宽“已有讲解才能成线”的前提、保存源码副本或改写已有闭环，先说明具体使用后果并交回。技术协议、文件字段和必要校验由执行负责。
