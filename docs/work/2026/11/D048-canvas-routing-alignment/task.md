# D048 · 双图连线与卡片、整组拖动对齐

## 目标与批准依据

实现任务。读者在文件依赖图里能沿一条线追清谁使用谁，在闭环图里能沿一个出口读到下一步。手动整理两张图时，靠近其他卡片或分组即可对齐，放手后的布局可在下次打开时接着用。

2026-11-24，作者反馈实际阅读时「总感觉这样连线有问题」。从截图能看到，多条依赖线汇成长横线，近邻库线绕回。作者随后提供两张参考图并提出「做一个虚线对齐的功能」，讨论了平滑直达、密集来线可追踪，以及拖动时出现虚线并轻吸附。作者补充「还有组的对齐，也可以做」「然后出任务吧」。[对齐参考图](alignment-reference.jpg) · [连线参考图](routing-reference.png)

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。遇到已不支持的旧文档格式，识别脚本只负责报错或警告，让使用产品 Skill 的 AI 知道哪个文件受影响、原因是什么。AI 按当前 Skill 的正常生成、校验流程改好或重做相应讲解、闭环，无需维护逐版迁移脚本或另写兼容指南。实际改写或删除作者资料仍按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

本地基线 `dev@96a69e5`，仓库 `D:/project/SpecDev Harness/aftertaste-reader`，沿用派单分支 `codex/feat-canvas-routing-alignment`。批准版本见转交消息。两图共用的产品依据见 [08 R16](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)、[007 文件依赖图](../../../../../specs/007-dependency-canvas/spec.md)和 [009 闭环图](../../../../../specs/009-loop-reader/spec.md)。

- **沿线读关系。** 同排且中间畅通时可以直连，上下错开时顺势弯入目标。近邻的入口与出口横向错开一点时，优先找短且清楚的路线；中间有其他卡片时，绕开卡面。多条边指向同一张卡时，按来向有序错开落点，尽量减少长段重叠与交叉。允许在密集目标附近短暂汇拢，各来源仍要可追到目标。自环、回边和真正的业务分支要一眼能区分。文件图的箭头继续从被依赖方指向使用方；闭环箭头表示教学步骤的去向；库用法继续用带箭头的虚线。保留现有淡线、悬停或聚焦看直接关系、查看关系理由的入口。
- **拖卡片对齐。** 文件卡、步骤卡和库卡可与邻近卡片或组框对齐。接近左右边缘、上下边缘或水平／垂直中心时，在对应对象之间显示临时细虚线，沿命中方向轻吸附。读者继续拖就能脱离，也能停在任意位置。缩放后按屏幕上的距离判断接近程度。只显示与这次摆放有关的参考线，视觉上与库用法虚线可区分。
- **拖整组对齐。** 从既有组名拖动入口移动，以整个可见组框的边缘和中心对齐另一组或外部卡片，组内所有显式成员应用同一个位移。拖组时排除自身和随行成员作为吸附目标；单独拖成员时，避开由该成员撑开的自身组框，仍可向其他卡片对齐。组名、成员归属与组内间距沿用已有布局。松手或拖动中断后收起辅助线；重开只恢复实际摆放结果。两张图的个人布局分别保存。
- **实现落点。** 从共用的 [画布拖动](../../../../../src/web/DependencyCanvas.vue)、[路径绘制](../../../../../src/web/DependencyEdge.vue)、[画布样式](../../../../../src/web/canvas.css)和[组框几何](../../../../../src/core/canvas-layout.ts)入手。走线随拖动更新，读旧布局时沿用读者已有坐标。技术选型由执行负责。按 Spec Kit v1.4.0 的 `speckit-specify`／`spec-template` 和 `speckit-plan`／`plan-template` 在 007、009 增量维护受影响的规格与方案。007 FR-014 的「左右端口居直边中点」和 FR-015 的曲线要求按本单更新为实际可读落点和走线；同步修订依赖旧几何的检查，保留箭头在真实目标边缘、关系能追读的要求。

## 验证与停点

1. **依赖图。** 在仓库内的合成项目摆出作者遇到的三种位置：一个库靠近使用方且端口稍有错位、多个文件从上下两侧汇入同一文件、直达路上有第三张卡。先从库追到使用方，再从密集目标反查指定来源；实际画面中可辨箭头、短线与落点，近邻关系不会被读成自环。拖动中间卡或目标后重看，并验证真正的回边和自环。对照[旧浏览器检查](../../../../../tests/browser/dependency-canvas-polish.mjs)中写死三次曲线和左侧中点的断言，按新的读图结果检查。
2. **闭环图。** 用有分岔和汇合的合成路线，从入口分别沿两条出口走到各自的下一步，再找到真正的汇合步骤。库虚线和教学箭头可区分，悬停分支点时看得清两条出口。用两图候选页面留同一布局改前、改后的可复核对照，重点看近邻绕圈与密集重叠是否改善。
3. **卡片和组。** 在两图的真实浏览器中覆盖卡对卡、卡对组、组对卡、组对组。至少在一个有多个成员的组上，实际从组名拖动，验证对齐边缘与中心、继续拖离、松手、刷新重开；核成员位移一致、外部对象停在原位、组归属与个人布局读回一致。换一个缩放倍率，复核辅助线与实际边界重合；平移画布、框选和组菜单仍按原入口操作。复用[依赖图样例](../../../../../tests/fixtures/dependency-canvas-polish.mjs)和[闭环画布检查](../../../../../tests/browser/loop-canvas-interactions.mjs)。
4. 使用回味仓库内的合成资料。候选另择空闲回环端口，避开 4317、4318；优先检查 4319。串行验证，运行证据放 `.local/D048/<run-id>/`。冻结候选后由执行调用独立审查子代理，按 Ponytail Review 实查两图的密集连线、整组吸附和布局读回。回执给两个可直接打开的试读入口，标出可追的线和可拖到一起的两组。
