# D056 · 本地阅读服务凭启动令牌访问

## 目标与批准依据

实现任务。只有持有本次启动令牌、或已用它取得本次会话授权的读者，才能访问这个阅读服务。源码、AI 据此写成的讲解和个人资料享受同样保护。拿到普通阅读地址的人只能看到不含项目信息的拒绝提示。

2026-11-26，作者在 D055 收尾后明确「讲解也是AI根据源码生成的，这个也不能泄露」「没有token的直接什么都不能访问」「如果用户以后真的要分享，只能靠我们以后出的导出的功能」，要求先派安全实现单。范围为本机阅读服务。产品对外分享留给已排后的[离线导出](../../../../product/backlog.md#offline-export)。alpha.2 的升级、打包发布和其他重构另行安排。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。遇到已不支持的旧文档格式，识别脚本只负责报错或警告，让使用产品 Skill 的 AI 知道哪个文件受影响、原因是什么。AI 按当前 Skill 的正常生成、校验流程改好或重做相应讲解、闭环，无需维护逐版迁移脚本或另写兼容指南。实际改写或删除作者资料仍按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

桌面是主要阅读和操作环境，交互与视觉细节优先在桌面打磨。手机默认只需能打开讲解或图，读到主要内容，需要时可滚动查看。新功能可以只在桌面提供，例如画布编排。手机专属布局、精细手势和逐项体验验收仅在当次明确需要时安排。

## 范围与材料

在回味仓库根目录接单。基线 `dev@adc7493`，任务分支 `codex/feat-reader-session-access`。批准提交由作者转交消息提供。

1. **从终端进入。** `serve` 每次启动产生密码学安全的随机令牌，在现有终端 `ready.url` 给出本次私密入口。打开有效入口后转到干净阅读地址。已授权浏览器可以刷新、打开同一实例的普通文件或闭环深链；新浏览器只拿到普通地址时收到简短提示，知道应回启动终端。服务停止即结束授权，即使下一次沿用项目和端口，旧启动链接和旧会话也均失效。
2. **服务入口统一拒绝未授权访问。** 在服务端先检查来源及会话，再分发页面、静态资源和项目读写。唯一授权入口只接受有效凭据来建立会话。缺失、错误、过期、其他实例的凭据都只能得到最小拒绝响应。首页、JS、CSS、字体等随包资源，以及讲解、源码、图、布局、示例、笔记、书签、自评等所有 API 均在此边界内。未知路径、错误参数和不支持的方法也不得提前返回资源清单、项目路径、文件名、正文、诊断上下文或凭据。未授权写入对磁盘无影响。新路由默认受保护，产品没有匿名预览、分享链接或免鉴权开关。
3. **同机多个项目各自授权。** 只监听回环地址，保留已有 Host、Origin、浏览器来源检查、写入限制、禁缓存与内容安全策略。项目 A 的授权只能用于它所属的服务实例。即使浏览器访问同机另一个端口，那个服务也不能收到可用来访问 A 的凭据。浏览器 Cookie 按主机发送，单靠端口签名或不同 Cookie 名不足以证明后一点。实现方式由执行选定并在 006 方案说明。保护范围是通过回味读写资料的通道；已有操作系统文件读取权限仍由系统管理。
4. **启动链接只交给启动者。** 授权完成后，从地址栏复制位置、打开外链或复制页面诊断时都不携带秘密。除私有终端交付入口外，产品日志、项目资料、浏览器可分享链接、测试报告、截图和 Git 归档均不得含可用凭据；失败响应不回显输入。产品 Skill 若代为启动，只向使用者说明如何在自己的终端获取入口。回执给本地启动说明和脱敏样例。
5. **落点与契约。** 从[现行规格](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)和 [006 文件阅读](../../../../../specs/006-file-reader/spec.md) FR-006 开始。按 [Spec Kit 增量流程](../../../../development/spec-kit.md#incremental-input)使用 `speckit-specify`、`speckit-plan`、`speckit-tasks` 和对应实际模板，更新 006 的行为、方案、清单及 [CLI/HTTP 契约](../../../../../specs/006-file-reader/contracts/cli-http.md)。实现沿[服务入口](../../../../../src/server/reader.ts)、[CLI 启动](../../../../../src/cli/main.ts)和必要的浏览器接入，集中维护授权策略。核对 `startReader` 和 `ready.url` 的现有调用方，更新 [README](../../../../../README.md)、[读者说明](../../../../usage/file-reader.md)及[随包工具指引](../../../../../skills/aftertaste-reader/references/tools.md)。本批沿用已有项目资料，示例及试读服务使用独立副本。

## 验证与停点

- 用独立合成项目设置可识别的源码、讲解和私有笔记。从安装包启动，用未授权客户端核实际注册的读写接口、首页和真实构建资源；覆盖错误、过期及未知路径，记录状态、响应中无资料、写入前后文件相同。已授权时，原有来源拒绝、参数诊断、写入检查继续有效。沿[集成测试](../../../../../tests/integration/file-reader.test.mjs)与 `tests/browser/` 增补覆盖；测试客户端也从正式入口取得授权。
- 用两个带不同内容的本地项目在各自空闲端口做一次隔离验证。同一浏览器只授权 A，核 B 仍拒绝、B 端收不到 A 的可重用凭据；再分别授权，核读写各自资料。停止 A 并在原端口重启，旧链接及旧会话失效，B 仍能读。仅记录判断结果及脱敏信息。
- 从干净安装的候选包实走「启动链接进入 → 刷新 → 用普通深链进入指定闭环 → 读固定提交源码 → 保存并读回笔记」。用独立浏览器配置打开相同普通链接，只读到通用提示。类型检查、构建、全仓单元与集成测试串行；Edge 主验，Chrome、Firefox 核与凭据传递相关的浏览器行为。输出放 `.local/D056/<run-id>/`，保留 `4317` 和既有试读服务及资料。旧进程的保护取决于实际运行版本，回执区分候选与仍在运行的旧版本。
- 独审绑定固定候选，核入口覆盖、跨实例凭据隔离、重启失效、资料与凭据泄露、原有来源保护及安装包实测。需要改变普通深链、引入账户、放开网络监听或留匿名资源口才能实现时，交回具体影响和选择；不得用测试专用通道代替交付。
