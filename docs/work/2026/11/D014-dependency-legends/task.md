# D014 · 依赖图中的库图例

## 目标与批准依据

实现依赖图中的库图例。读者选中一个库，就能看懂它提供什么能力、哪些文件用它、各自为什么用；也能把它摆到相关文件旁边，下次打开接着读。

2026-11-18（上海时间），主脑提出由讲解 AI 按教学需要挑选库，通过工具维护介绍和使用关联，读者在当前图查看和自由摆放。作者确认：“首版先不允许用户改图例，只能自由摆放图例和查看。你出任务吧”。首版两类图都遵循这项内容权限，本单交付本地依赖图。闭环接入、路线高亮和整页 UI／UX 打磨留给各自的任务。

## 验证与停点

1. **走完一次真实阅读。** 从已保存位置、组和视野的纯文件项目开始。用正式工具登记一个 `node:path` 图例，从图例分别连向两个使用文件，每条连线给出不同理由。用浏览器查看介绍，将图例与一个文件编组，拖组并等页面确认保存。再用工具只改介绍。关页、停服务、重启，用新浏览器会话核对新介绍、两条关联、坐标、成员和视野，对照实际落盘。另覆盖第三方库的呈现及含图例的保组重排。
2. **核对谁能改什么。** 比对页面摆放前后的内容文件，确认介绍和关联未被改写；通过真实布局接口尝试提交内容改动，也不能改写它们。用同显示名的文件与图例核对选中、分组及文件阅读入口各指向正确对象。用现有图工具查询、更新文件关系，检查图例及原文件核对语义。
3. **追到最后一次写入。** 在隔离样例中对照图例资料暂缺后恢复、正式移除图例后旧页再保存两种顺序，核对实际存下的文件与页面结果。若所选方案一次发布多个文件，覆盖一次中途失败及正常重试。复用 [D013 回执](../D013-canvas-fixes/handoff.md)中未变行为的证据，共用布局或存储契约有变化的部分在本候选复验。

用 `tests/` 的图工具、布局和浏览器样例重建上述场景，运行输出归 `.local/D014/<run-id>/`，使用独立项目与端口，保护此前试读资料。作者体验看“能否从图例读懂两个文件各自的用途，重开后能否接着自己的排布读”。若方案需要丢弃旧布局、迁移时无法保护用户资料或改变已确认的使用权限，带具体影响交回主脑。
