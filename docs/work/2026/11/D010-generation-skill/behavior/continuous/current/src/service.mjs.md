## 两个项目依赖各自提供什么

订单创建依赖数量解析与辅助记录。数量解析的输入转换和整数范围已在 [数量规则讲解](rules.mjs.md) 的块 5557y2e4 说明。这里直接使用它返回的数字。

辅助记录来自范围外的 support/audit.mjs。核对这个固定提交后，可以确认该函数只把收到的事件和编号拼成字符串返回。当前订单创建调用没有使用这个返回值，因此本次调用链可见的状态变化要从下面的数组追加步骤理解。该模块作为依赖登记在图中。

## 一次创建怎样改变调用者的数组

函数接收输入对象和订单数组。它先读取输入的数量并调用数量解析，成功后才构造订单。订单编号取当前数组长度加一，数量保存解析后的数字。随后把新对象追加进传入的数组，调用辅助记录，最后返回这个订单对象。数组内保存的对象与返回值是同一个对象。

用独立情景走一遍，假设数组已有两笔订单，传入数量字符串“3”。解析后得到数字 3，新订单编号为 3，追加后数组有三笔，调用者拿到新订单。如果数量改成 12，解析步骤抛出异常，本次创建还没有追加数组。输入为 null 时，读取数量属性就会失败，同样到不了追加步骤。

编号来自数组当前长度，调用者需要理解这个约束。若数组中的已有编号与长度不一致，或者先删掉项目，这种编号方法可能复用已有编号。固定源码中的存储效果是修改调用者提供的内存数组。函数把异常继续交给上层，也没有额外的回滚步骤。下一篇会说明接口如何包装它的返回值与异常。
