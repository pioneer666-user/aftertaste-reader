## 接口使用订单创建能力

本文件依赖订单创建函数，数量转换、编号与数组追加沿用 [订单创建讲解](service.mjs.md) 中的行为。接口把收到的正文和订单数组传入这条调用链，再把结果包装为响应描述对象。依赖方向从数量规则和辅助记录汇入订单创建，再到这里。

## 成功与异常怎样成为响应

成功路径先执行订单创建，再构造状态码为 201 的对象，响应正文就是返回的新订单。创建过程对订单数组的修改已经发生，响应正文与数组中的新订单共享同一个对象。

以独立输入情景为例，空订单数组加上数量字符串“5”，会完成数值转换，创建编号为 1、数量为 5 的订单，数组随之增加一项，接口返回 201 与该订单。若数量为 0，数量规则在数组追加前抛出异常，接口进入异常分支，返回 400 与固定错误信息。

异常捕获覆盖创建调用抛出的所有同步异常，因此数量越界、正文为 null 导致属性读取失败，以及订单数组参数不符合调用要求导致的异常，都会汇入相同的 400 响应。捕获处没有按异常类别分支，也没有保存原异常信息。调用者从返回对象只能读到这个统一结果。

贯通三篇后，可以沿“接口接收参数 → 订单创建 → 数量解析 → 数组追加 → 包装响应”理解一次成功调用。失败发生在哪一步，决定了本次调用是否已推进到数组变更。这里输出的是普通 JavaScript 对象，当前文件展示的是响应描述的构造。
