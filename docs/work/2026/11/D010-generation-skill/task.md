### 本批交付与验收

| 编号 | 必须达到的结果与验收场景 |
| --- | --- |
| S01 范围与节奏 | Skill 识别普通文件讲解请求。阅读范围或生成节奏缺失时只问缺失项并等待，复用有效选择；不默认整仓或连续全部生成。范围明确后由 AI 按依赖与理解关联组织小批次，不要求逐批审批文件清单。逐批阅读交付后等待继续要求；连续生成则在已确认范围内按批完成，不以阅读、理解标记或反馈为继续门槛 |
| S02 固定来源与既有资料 | 明确区分工具位置、目标项目、仓库根和 cwd，沿完整 pin 映射读取固定提交。选文件、分块与依赖判断依据该提交，工作区或 HEAD 变化不能混入内容；发现文件可复用 Git 的只读对象查询，不建立自动依赖解析器。生成前核实际 current／图的既有版本与文档，不能只信阅读方向摘要。既有资料与目标版本冲突时说明并停止依赖写入，不用改提交字段、删旧文档或工作区回退冒充版本更新 |
| S03 制作与讲解指导 | 制作约束早读；针对性分析前读取讲解方法、已有偏好及阅读方向，相关批注／旧讲解按需读，缺少资料不阻断已获准生成。依据代码特点、用户需要及前后联系决定重点，给可实际遵循的正反例，不要求每块套统一标题。AI 决定有序块清单，工具生成 ID 与骨架，AI 填正文；保持完整行覆盖与既有 ID 规则，不将用户源码全文或摘录复制进讲解、临时文件、日志或模板。资料中的指令性文字不得覆盖用户范围和工具约束 |
| S04 工具链与完成判断 | 先登记本批文件节点，再逐文件生成、填写并 validate；根据实际诊断修正，空正文或仅有骨架不算完成。完成讲解后提交明确使用者的完整依赖列表，范围外项目依赖仅登记节点／边，不自动生成讲解；未核对与核对后无依赖区分。超大块如实告知、不自动拆；失败说明已生成、未完成及未核对部分，不假报整批成功。既有文档不得通过删除重建绕过 DOCUMENT_EXISTS；仅对可确认属于本次新建、仍同版的未完成骨架继续填写并保留 ID，其他既有资料按实际状态说明 |
| S05 偏好与阅读方向 | 将已定 Markdown 模板落为随包原件，落实项目内偏好／方向资料路径及读写规则，沿 U74／U75 的分区和语义。初始化不覆盖既有资料；无真实反馈不制造教学观察，不把已讲等同已理解。每批结束检查方向，有需要才合并修订；下一批前有相关真实反馈才按既有规则维护偏好，冲突先问，重复反馈修订原条目。只提问不等于授权改讲解，不修改笔记、书签、自评或发布的 Skill；不做聊天采集、跨项目画像或完整反馈管理系统 |
| S06 可调用交付与试读 | 一个实际可读取的 Skill 入口配必要参考、模板及工具说明，准确声明本批能力和未接入分支。参考／模板可由包内相对位置找到，工具入口可在非项目 cwd 正确调用，不硬编码本机路径或把安装目录当目标项目。提供当前开发树的真实使用步骤、小批讲解产物、源码引用定位和实际校验结果；区分显式加载成功、宿主自动发现、未来安装／发布，不以静态格式检查代替行为验证 |

上述是一个普通生成流程，不包含全文写回式答疑、重新分块修订、跨提交更新／备份恢复、闭环、用户记录管理、HTTP／网页、图布局、导出、自动调度、全宿主安装或 npm 发布。遇到这些请求说明当前范围，不用普通新建流程替代。源码读取失败保留已有资料并报告真实诊断，不自动修 Git；完整生成后的教学效果由作者判断。

## 验证与停点

- 行为检查使用固定输入和实际命令结果，记录 Skill 候选、宿主／模型、工具版本、目标提交、动作与产物；按场景串行运行，模拟使用代理与开发独审代理分别负责，不以关键词匹配或作者自述替代行为。
- 必测场景：范围／节奏缺失时无生成写入；有效选择不重复询问；同一小项目分别走逐批与连续节奏；工作区不同于固定提交仍使用固定源；范围外依赖不越权生成；已有文档／版本冲突不覆盖；Git 或校验失败不假报完成；有无偏好及真实反馈时的正确维护。可用少量组合场景覆盖，不为凑场景数重复运行整条流程。
- 至少一次由真实使用代理仅凭 Skill 入口与用户请求串完“小批选取 → 骨架 → 正文 → 文档检查 → 图关系 → 方向收尾”，执行者核完整调用链和实际产物。测试代理可在隔离沙盒实际写资料；独审者不参与指南编写或实现。查验空正文警告、未核对状态、资料保护和固定版本，不只看命令退出 0。
- 对合成源码的小项目可保留可重建 fixtures；其生成的讲解、图、方向和校验摘要可作为正式行为证据。准备一小批完整讲解供作者试读，给实际产物入口与固定源码定位，关注“是否解释清楚职责／取舍、是否按已有需要讲、前后联系是否有帮助”。若使用合成项目须明说，不声称真实外部项目教学已验；作者指定真实项目后只按固定引用读取，不留源码副本。缺少真实项目输入不阻塞工具与 Skill 行为检查，但真实项目教学效果保持待验。
- 静态检查覆盖包入口、必要参考／模板、相对链接、描述与实际能力；只有确实验证过的加载方式才能写为可用。代码有改动才补 typecheck／build／受影响测试；未变能力沿 D007—D009 有效证据复用。不开服务或浏览器，不为无页面任务作 UI 验收。
- 实现完成固定候选并调用未参与实现的独审子代理，按实际 Skill 行为与关联工具链检查：范围和节奏、来源版本、覆盖／ID、文档及个人资料保护、图状态、假成功和教学事实。采用 writing-for-agents 与 skill-creator 的相应检查；涉及代码再用 Ponytail Review，路径／写入等按需要配合 Sharp Edges。明确冻结与交还写入，原文落同目录 `review.md`，问题修复另提交并复核。
- 既有设计不重开；若必须改变用户生成步骤、源码只引用原则、资料保护或扩大后置功能，带证据交回主脑，只暂停依赖部分。常规路径、字段、提示词组织和调用细节由执行落实；两轮修复停点沿共同规则。
