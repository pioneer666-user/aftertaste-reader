# D059 · 验证 alpha.2 安装包，用实机截图介绍回味

## 目标与批准依据

实现任务，交付一份本地可发布的 `0.1.0-alpha.2` 候选。第一次看到项目的人能从 README 看懂回味如何帮他读代码，照着说明安装，并在同一份安装包中完成一次真实阅读。作者最终收到可预览的首页、已验的包、校验值和发布建议。

2026-11-26，作者同意上一轮提出的本地候选和上线验收，并要求「顺手优化一下README.md，里面放一点宣传，截图之类的」「看看哪些比较火的项目是怎么做的」。作者特别推荐一张简约的闭环图，「只有4，5个节点，然后两种图例，有节点说明，能悬浮预览」「画面不能乱，这些也可以我来摆放位置」。本次授权在本地准备版本和验证，公开发布另行确认。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。遇到已不支持的旧文档格式，识别脚本只负责报错或警告，让使用产品 Skill 的 AI 知道哪个文件受影响、原因是什么。AI 按当前 Skill 的正常生成、校验流程改好或重做相应讲解、闭环，无需维护逐版迁移脚本或另写兼容指南。实际改写或删除作者资料仍按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

桌面是主要阅读和操作环境，交互与视觉细节优先在桌面打磨。手机默认只需能打开讲解或图，读到主要内容，需要时可滚动查看。新功能可以只在桌面提供，例如画布编排。手机专属布局、精细手势和逐项体验验收仅在当次明确需要时安排。

### 让第一次来的人看到真实阅读效果

- 根 [README](../../../../../README.md) 用中文面向「能写基本功能，想读懂真实项目」的读者。首屏用一句话讲清用途，放容易找到的获取安装包与快速开始入口。用一个具体问题串起两张同一版本的桌面实机截图。可从「同一个收藏请求提交两次，还会再写一次数据库吗？」开始。**首图是简约闭环图**，第二张聚焦图中那个判断，让读者读得到固定提交的关键源码及对应讲解。图注说清这一眼该看哪里，结论以样例源码为准。
- **首图的构图。** 在隔离副本中做一张可实际操作的小闭环，画面只呈现 4～5 个教学步骤，两种图例各一处：一个该路径实际用到的库图例，一个可展开细节的文字问句图例。让主线和一次分岔自然可循，节点下展开一条简短说明，在另一节点上真实悬停，截到上方气泡与正文。给气泡、图例和线留空，避免挡字、叠线；在 README 正文宽度也能辨认分岔与两种图例。推荐首图使用全图默认状态，靠排布说清路径；只有一条示例路线显著更清楚时才用高亮。两种状态可在试读画布切换，无需为比较增加一张公开配图。[闭环图例与选例](../../../../../specs/009-loop-reader/spec.md) · [悬浮预览](../D055-loop-node-hover-preview/task.md)
- 执行先给出完整可用的排布和首图，保留独立试读项目、布局和可重开的画布入口。作者愿意亲自摆放时，可拖动节点、图例并调整视野。执行从作者保存的位置恢复悬浮、重拍并更新 README。等作者看图时可继续其他技术验证，手动摆放由作者自选。
- 优先用本地已有的 [Apache Answer 收藏请求](../D045-alpha-first-run/handoff.md)资料和其固定提交，在可公开的隔离副本中用本版截图。若原资料不可用，可改用同样能解释一个真实判断的公开样例或项目自有订单样例，并准确标明来源。使用带有内容的实际页面，裁到 GitHub 正常正文宽度仍能辨认文字；图片提供替代文本与仓内相对路径，成品放 `docs/usage/assets/`。检查截图、说明和文件元数据，避开用户私有项目、私密入口、个人记录及本机身份信息。核对第三方示例的来源、归属及适用许可。
- 主脑已查两个官方首页：[Mermaid](https://github.com/mermaid-js/mermaid#readme) 把输入、产出和试用入口放在开头；[Difftastic](https://github.com/Wilfred/difftastic#examples) 用每张截图旁的一句话指出可观察的差异。回味借这个写法，用自己的文字和实机画面。保留首次安装命令、可复制的首次讲解请求、打开与停止、适用环境、许可和维护者入口。宣传以可验行为为准，区分阅读服务的本机运行与用户选择的讲解 AI 如何处理源码。先在本地预览 GitHub Markdown，检查图片、标题跳转与安装链接。公开前可用 [GitHub Releases 列表](https://github.com/pioneer666-user/aftertaste-reader/releases)，避免向读者承诺尚未上传的附件。

### 准备一份可以原样上传的候选

- 在本地同步 `package.json`、锁文件根版本及必要的安装说明，保留现行 GitHub 预发行渠道。按实际包清单核 CLI、预构建网页、Skill、许可声明和资源；确认无项目私有资料、凭据或日志混入。输出 `aftertaste-reader-0.1.0-alpha.2.tgz` 和可用于校验该文件的 `SHA256SUMS.txt`，放 `.local/D059/<run-id>/`。回执记候选提交、最终包名、SHA-256 和可取得的本地位置。README 或其他随包文件变更后，按最终定稿重打并核对适用证据。为 GitHub 预发行准备简短中文发行说明，可直接放回执，写明相对 alpha.1 的读者可见变化与已知限制。
- 维护者按仓库锁构建。在空的隔离工具目录，以 README 的读者方式对**该最终包**运行联网的 `npm install --omit=dev`，让 npm 自行解析运行依赖。对照实际安装版本与仓库锁的差别，并核随网页一起交付的组件；筛查适用安全公告，记录检查日期、来源、版本和处置依据。检查第三方公告时只需公开包名与版本。仅开发工具的告警、未命中和已知影响实际交付的告警要据实解释。D058 的离线锁定安装与上轮扫描可以用来对照。[D058 安装与复核](../D058-reader-launch/handoff.md#依据与验证)

## 验证与停点

1. **把上次没跑完的回归跑完。** 在固定候选完成类型检查、构建及现有全部单元和集成测试，按仓库约定串行运行，记录总数、失败或跳过情况。相关宿主与浏览器采用同版本可复用证据，再补安装流程所需的端到端验证。实际失败与环境中断分别定位，保留原结果。
2. **照着新的 README 完成一次试读。** 从干净安装显式加载随包 Skill，在独立 Git 项目生成一小批讲解并等用户完成 Git 可见性选择，检查固定提交的源码对照。由 AI 打开新讲解或已读回的闭环，从顶栏复制入口到第二浏览器并到达同一位置；保存笔记、关停重开、读回笔记，核未授权普通地址和重启前的私密入口。优先实测作者日常的本机 Codex 桌面入口。宿主能力受限则注明具体入口、验证到哪一步及读者可用的终端或复制路径。[访问保护](../D056-reader-session-access/handoff.md) · [资料隐私](../D057-project-data-privacy/handoff.md) · [AI 启动的已知边界](../D058-reader-launch/handoff.md#限制与修复记录)
3. **绑定公开材料与证据。** 核 README 中的每个主要对外承诺能在候选包找到对应行为，两张图片在本地渲染预览中可读、相对链接可由仓库解析。交回作者可点开的 README 预览或 README 与图片直达入口、发行说明、校验文件及安装验证结果。隔离运行、使用空闲端口，保留真实服务和原试读资源。与本单直接相关的安装说明、截图和打包疏漏可修后重验；实际影响源码隐私、数据完整性或正常安装阅读的产品缺陷应列为发布阻断，给出证据、影响和处理建议。Windows Git 定位等已单列议题按现有决定，不借本单扩为通用重构。
