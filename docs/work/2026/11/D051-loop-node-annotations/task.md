# D051 · 闭环图节点旁可收展的 Markdown 注释

## 目标与批准依据

实现任务。讲解 AI 可以给闭环里值得停下来读的步骤写一段 Markdown。读者在节点旁就能读到这段说明，收起后点节点可以再次展开，必要时能对照该步的固定版本源码。

2026-11-24，作者认可主脑展示的收藏请求示例，明确「能收起来，用户点一下节点还能展开」「样式完全参考你做的例子」「我们给闭环图加功能，依赖图不需要这些，依赖图还是以展示文件间的依赖为主」。[认可的原示例](style-reference.html)随本单保存。制作深度和其他展示能力按[后续方向](../../../../product/backlog.md#loop-depth)分批安排。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。遇到已不支持的旧文档格式，识别脚本只负责报错或警告，让使用产品 Skill 的 AI 知道哪个文件受影响、原因是什么。AI 按当前 Skill 的正常生成、校验流程改好或重做相应讲解、闭环，无需维护逐版迁移脚本或另写兼容指南。实际改写或删除作者资料仍按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

基线为 `D:/project/SpecDev Harness/aftertaste-reader` 的本地 `dev@4b30f2d`，分支 `codex/feat-loop-node-annotations`，派单提交见转交消息。

- **谁写、放在哪一步。** AI 在正常制作闭环时为选定的教学步骤写可选短注，用一句话或一小段点出影响本条路线的条件、来源或结果。注释随闭环步骤身份保存和读回，同一源码块在不同步骤可以有各自的注释。沿用回味 Markdown 对段落、强调、列表、行内代码等的渲染规则。缺注释的步骤及已有闭环照常阅读；右栏的步骤讲解、提示和读者自己的笔记保持原有用途。文件依赖图的文件节点、库卡和依赖线维持原有职责。
- **样式以原示例为准。** 注释放在步骤卡下方，与卡片左缘对齐，由一小段无箭头细线挂在卡底。紧凑的纸色底、左侧强调线、可收展的「节点说明」、正文及有依据时的源码入口均参照示例。保留左右连线端口。颜色随阅读器主题适配，界面控件沿用现有中英文机制，AI 写的正文保持原文。示例中的 GitHub 链接用于核对设计内容，产品使用本地已有的固定提交源码对照，显示实际对应的文件和行范围；缺源沿用诊断，纯讲解步不显示虚构定位。
- **收展与选步。** 空间充足时有注释的步骤默认展示短注；点「节点说明」收起，留下可识别的入口。点收起的入口或直接点该步骤卡，均在画布上展开注释，包括重复点已选中的同一节点。点步骤继续触发现有选步、来路／出口及关联线反馈，读者收起的右栏保持其开合选择。点注释的收展控件、选中文字或打开源码时，各动作只触发一次。支持鼠标、键盘和触屏；较长 Markdown 可进原有阅读栏看全。
- **布局与手摆。** 初始化和确认重排为可见短注留出空间，核节点、图例、组和重要分支线的可读性。注释随所属节点拖动、随组移动并随画布平移缩放。密图、窄窗或已有手摆位置放不下时先显示收起入口，用户点节点仍能就近读到注释。收展属于本次阅读，不改写节点坐标、组或视野，不触发全图重排。
- **交付链。** 沿[闭环制作](../../../../../specs/008-loop-authoring/spec.md)、[闭环阅读](../../../../../specs/009-loop-reader/spec.md)和[现行规格 R01、R16、R17](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)接入。覆盖[讲解 AI 的闭环指南](../../../../../skills/aftertaste-reader/references/loops.md)、`create-loop` 的输入和校验、保存与 `read-loop` 读回、阅读服务及画布。复用 `src/core/loops.ts`、`src/application/` 的闭环流程、`src/web/` 的画布和 Markdown 渲染及对应现有测试。在 008、009 增量维护受影响的规格、方案、模型和契约；按 [Spec Kit v1.4.0](../../../../development/spec-kit.md) 用 `speckit-specify`／`spec-template`、`speckit-plan`／`plan-template`，涉及正式清单时沿 `speckit-tasks`／`tasks-template`。共用画布的改动限于接通闭环所需部分。

## 验证与停点

1. **从制作走到读回。** 用仓内合成 Git 项目让安装后的候选 Skill 实际制作一条有分支的闭环，包含一个需要说明的判断和一个无注释的步骤。经正常命令保存、校验，再用 `read-loop` 和阅读页核同一注释的内容、步骤归属、Markdown 和固定源码定位；同块复用或切换闭环时不串注释。用原有无注释成品验证直接重读。
2. **按原示例验收操作和观感。** 在稀疏图对照原样式核展开、收起两态。收起后分别点同一已选节点、换步后点回、用键盘或触屏展开；核收展入口和节点点击各自生效、右栏状态与关系条符合原行为。打开源码核固定提交与行，查看长文，再返回这一步。回执留候选的展开／收起对照和节点直达入口。
3. **用手摆密图验摆放边界。** 复用[已有密图样例](../../../../../tests/fixtures/canvas-reading-layout.mjs)，包含分支、图例和分组。在桌面与窄窗核留位、空间不足时的打开方式、拖节点／整组、缩放及确认重排；比对单纯收展前后的布局和保存请求。切到同项目文件依赖图，实际点选文件、查看依赖理由，核页面上没有节点注释或占位，也没有为闭环短注改变依赖图的排布。
4. 检查与试读串行，在 `.local/D051/<run-id>/` 保留隔离资料。候选另用空闲回环端口，保留作者占用的 4317 及现有试读服务。用实际安装包和浏览器验证；若实现需要改变已有手摆布局、读者数据或扩展到依赖图，携具体场景交回主脑决定。
