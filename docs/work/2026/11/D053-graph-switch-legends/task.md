# D053 · 双图可拖动的文字开关图例

## 目标与批准依据

实现任务。读者打开图时先看懂主线，遇到自己关心的问句，点一下就在原图展开相关步骤或关系。图例离目标很远时，读者能知道内容出现在哪个方向，并自己决定是否移过去。

2026-11-25，作者要求图例「单独放的」「用户能自己移动」，可用于闭环图和文件依赖图。对照实际问句截图，作者提出「根据不同的图例用不同的渲染」「就像真的问题冒出来一样」「不要边框，然后图例节点背景特别淡」。作者确认[两图可操作的样式示例](floating-question-legend.html)，并批准「可以，就这样样式了，你出任务吧。我们先增加这个图例，未来还会增加别的图例的，也要利好未来扩展。」示例固定了问句、计数、方向提示和回到原视野的体验，测试数据和屏幕坐标只供演示。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。遇到已不支持的旧文档格式，识别脚本只负责报错或警告，让使用产品 Skill 的 AI 知道哪个文件受影响、原因是什么。AI 按当前 Skill 的正常生成、校验流程改好或重做相应讲解、闭环，无需维护逐版迁移脚本或另写兼容指南。实际改写或删除作者资料仍按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

桌面是主要阅读和操作环境，交互与视觉细节优先在桌面打磨。手机默认只需能打开讲解或图，读到主要内容，需要时可滚动查看。新功能可以只在桌面提供，例如画布编排。手机专属布局、精细手势和逐项体验验收仅在当次明确需要时安排。

## 范围与材料

本地基线 `dev@161e69a`，工作目录 `D:/project/SpecDev Harness/aftertaste-reader`，任务分支 `codex/feat-graph-switch-legends`。批准版本以转交消息里的派单提交为准。

- **资料和渲染按类型区分。** 现有库图例展示库名、来源和用法。新增开关图例有本图独立身份、读者可点击的普通文字和受控目标，可控制一组节点及关系，或单独控制关系。库的「标准库／第三方库」仍表示库来源。两图共用图例类型的识别和渲染入口，以及实例身份、拖动、分组和布局保存。以后新增类型时可以补该类型的内容校验、呈现和交互，无须改写每个库卡或另做一套画布。本次只实现已认可的开关图例，按真实两种类型组织代码即可。
- **画布上的问句。** 使用示例中的无边框、极淡底色和点状下划线，保留足够文字对比与清楚的键盘焦点。问句独立摆放，可直接拖动，短按文字或用键盘激活才切换。问句末尾留一点空隙，用次要文字显示「展开 2 步」或「收起 2 步」。文件节点用「个文件」，只控线用「条关系」。涉及节点时以节点计数，附随的连线不重复计入。问句与目标的控制关系不画成图里的业务箭头。
- **读者先选展开，再选定位。** 新开关初次收起。展开或收起保留当前视野、缩放和坐标。在可读画布内的新增目标就地短暂强调；屏外目标按实际方向在对应边缘汇总，只报该方向仍在屏外的数量。例如同时展开两步，眼前一步、右边一步，只在右缘提示「右侧还有 1 步 →」。点提示才定位到相应内容，可以返回操作前的原视野。节点或关系都在眼前时免去定位提示。提示随平移、缩放、窗口与阅读栏遮挡、收起而更新，键盘可完成定位和返回。
- **显隐和布局。** 文件依赖图与各闭环分别记住读者的开关状态、图例位置。收起只改变可见内容及相关命中、标签、高亮与小地图，布局仍保存全部真实成员；原有组、手摆坐标和真实关系均可恢复。未列入任何开关的节点照常可见；一个目标被多个开关引用时，任一打开即可显示，两端可见才显示关系。切换和计数按实际显隐变化去重。普通库图例的用法详情及连线继续可读。已有读回入口指向收起的步骤时，仍能到原步骤并读其讲解和固定源码。单纯点问句时保留正在读的讲解上下文。
- **讲解 AI 能正常制作。** AI 按问题挑选确有阅读价值的细节，自拟文字，引用本图现有的稳定节点／关系身份。闭环可直接定义自己的开关，随本次闭环成果独立读回。依赖图可只收起少数次要关系。其余资料照常生成，开关为选用。贯通制作、局部更新、校验和查询，包括依赖图的 `apply-graph`、`validate-graph`、`query-legends` 及闭环的 `create-loop`、`read-loop`。错类型、悬空或跨图引用给出资料路径与原因，不能静默变成空库卡；读者拖放与展开只写个人状态。按实际影响更新 `skills/aftertaste-reader/references/` 的生成、闭环及工具指导，给讲解 AI 一例展开步骤、一例只展开关系。
- **规格与落点。** 从[现行 R08、R16–R18 和 A17–A19](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)进入，在[依赖图资料](../../../../../specs/004-dependency-graph/spec.md)、[共用画布](../../../../../specs/007-dependency-canvas/spec.md)、[闭环制作](../../../../../specs/008-loop-authoring/spec.md)、[闭环阅读](../../../../../specs/009-loop-reader/spec.md)增量维护受影响的要求、模型、读写契约与验收场景。沿 [Spec Kit v1.4.0](../../../../development/spec-kit.md) 使用 `speckit-specify`／`spec-template`、`speckit-plan`／`plan-template`、`speckit-tasks`／`tasks-template`，按契约变化核跨材料一致性。产品实现沿 `src/core/`、`src/application/`、现有读写入口和 `src/web/` 共用画布。后续其他图例、缩放自动收组、教学动画和换卡玩法另议。

## 验证与停点

1. **闭环实读。** 在本地固定源码样例上制作一个有两个可展开步骤的真实闭环。把问句挪远，一步在屏内、一步在屏外。鼠标和键盘各走一次「展开 → 点边缘 → 回到原视野 → 收起」。观察数量、方向、落点、返回前后的缩放与位置。将目标置于不同方向、拖动问句、打开阅读栏，再核提示与命中。复查已固定源码和进入被收起步骤的原有深链。
2. **依赖图实读。** 从[现有带库和审计依赖的样例](../../../../../tests/fixtures/edge-labels.mjs)起，制作一个只控制一条关系的开关。切换时文件全在原位；关系出现后仍能按 D052 选线、读理由。把问句和库卡一起拖动、分组后保存，关页重开；切到另一张图，确认排布和开关状态分别恢复。覆盖两个开关共用目标、收起期间保存布局、增删真实成员与无开关的原图。浅深主题细看问句、边缘提示及焦点，窄窗或手机只验基本可读。
3. **从资料到页面。** 用打包 Skill 和正常 CLI 生成、校验、读回两图，图例可选、类型正确，错误引用有定位，重复操作不制造重复实例。固定候选后跑受影响的模型、集成和浏览器检查，复用 `tests/fixtures/`、`tests/unit/`、`tests/integration/`、`tests/browser/` 里的现有样例。提供可直接打开的两图入口，让作者试真实阅读页。
4. 运行输出归 `.local/D053/<run-id>/`，本地检查串行。作者真实服务 `4317`、D052 试读 `4353` 及其他已有服务和资料均保留，在独立样例目录和空闲回环端口试读。若必须改变真实关系语义、覆盖个人布局或要求读者多走制作步骤，先交回具体影响；其余沿共同修复停点。
