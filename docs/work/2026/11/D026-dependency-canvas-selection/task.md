# D026 · 文件依赖图首屏与框选分组

## 目标与批准依据

类型为实现。读者从左上切到依赖图，第一眼看见文件、库和它们的关系。需要整理时，框住几个对象就能在鼠标附近把它们编成一组，回到图上继续读。

2026-11-19，作者在主脑会话确认「我确定好要这样放了，你不用做局部草图，质感就是我给你的截图那样」「首先是页面上的内容先收一收」「框选一片，然后鼠标上做出和文档页面里面同款悬浮按钮」「你可以搜一下comfyui是哪个快捷键，咱们用一样的」。截图一以桌面应用左上菜单为顶栏参照，截图二划去了画布内重复的大标题、常驻保存成功文字、刷新按钮及右侧常驻说明。作者指定「下一单专门优化图的质感和操作上的东西，比如连线用曲线」。以下文字可直接转交执行。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

工作目录为本仓库。基线 `dev@6ca44d8`，派单分支 `codex/feat-dependency-canvas-selection`，批准提交随转交消息提供。

- **切页。** 顶栏左上按截图采用轻量横排文字入口，紧邻阅读页原有的侧栏开关。使用回味的实际页面名称「文件讲解、文件依赖图、闭环阅读、书签、标注、笔记」，当前页有柔和底色及可识别的当前状态。悬停、键盘焦点和当前页可区分。全站沿用同一顺序，右侧留给刷新资料、语言等已有工具。窄窗可收纳放不下的入口，仍看得出身处哪页。由图打开讲解后仍能明确返回刚才的图。这项确认替换 [006 FR-011](../../../../../specs/006-file-reader/spec.md) 中旧的左右位置约定。
- **读图。** 正常初次打开就把空间给画布。图名由顶栏当前页承担，给主要区域保留可访问名称。收起正常保存提示、常驻操作说明和全量分组表单。保留截图中的「重新布局」与缩放，将「刷新图和布局」、简短手势提示和按需编辑分组放进可发现的次级入口。选中文件或库才打开对应详情，可关闭并恢复画布空间。文件关系、逐条原因、库用途及「阅读讲解」沿现有入口。加载、缺图、保存失败、冲突和未保存的操作仍能当场识别并处理。
- **框选。** Windows 依照 ComfyUI 的两个独立动作。按住 Ctrl 在画布空白处按下左键并拖动，框住所需文件及库节点。普通拖空白平移，拖节点移动节点，拖组名仍只移动本组显式成员。在组框背景内也能起框，组框和边不作为候选。以完全落入框内的节点为成员，反向拖动、平移缩放后的命中规则一致。松手时保留选中反馈，空选不出现按钮。两处依据见 [ComfyUI 框选约定](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/src/lib/litegraph/API.md#selecting-multiple-items)与 [ComfyUI 选中节点成组](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/README.md#qol-changes)。
- **成组。** 有选区时在松手位置旁显示单个「分组」按钮，样式、避让窗口边缘与键盘操作参考讲解页选文浮条。点按钮或按 Ctrl+G 都进入同一处就近命名，看到所选数量，Enter 确认，Esc 放弃此次操作。只框选、取消或切页都不写布局。有对象已属别组时，命名前告知确认后会移组，沿用一对象一组及空组消失的规则。快捷键仅在当前依赖图有有效选区且焦点适用时接管，输入组名、读讲解或操作闭环时不拦截。保留无需组合键或拖框也能完成的入口，可创建、改名、增减成员或解散组。试读可直接观察是否能从松手处顺势点到按钮，以及选中、编辑与落盘是否各自清楚。

沿[现行规格 R16／A17—A18](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md#graph-layout-acceptance)与[007 文件依赖图规格](../../../../../specs/007-dependency-canvas/spec.md)增量维护本批画布要求。共用顶栏的主定义放 006，框选分组的主定义放 007，涉及尺寸与交互的验收预期各写一处，其余引用。执行按 [Spec Kit 增量入口](../../../../development/spec-kit.md#incremental-input)使用对应 specify、plan、tasks 技能及生效模板，再按要求 analyze、implement。沿仓内技能适配使用 Ponytail、Impeccable 的布局与交互检查，独审用 Ponytail Review。

主要落点为 `src/web/App.vue`、`src/web/DependencyCanvas.vue`、对应样式与中英文文案，原分组与保存逻辑按需复用。正式测试在 `tests/browser/` 及直接受影响的现有测试，使用说明随实际入口更新。依赖图和闭环共用画布组件，各图内容、布局与已有阅读语义独立。本批调整跨页顶栏和依赖图内操作。图中曲线、节点质感、连线动效与进一步的图操作列入后续讨论，五色切换和个人记录管理页按 B006 接续。

## 验证与停点

构建后先在[共用试读资料](../../../../../tests/README.md#页面改版共用试读)的隔离副本走真实操作，实际框选和写盘均用副本。证据放 `.local/D026/`。

| 操作 | 核实结果 |
| --- | --- |
| 从讲解顶栏进图，点 `src/api.mjs`，沿直接关系选 `src/service.mjs`，打开讲解后返回 | 首屏完整让给图，能读到「调用 createOrder 处理订单。」及有关文件。返回后仍是原节点、原视野。实看中文桌面、英文顶栏临界宽度和窄窗，各页入口、当前页提示和侧栏开关可用 |
| 在现有「订单处理」组框的空白处开始，分别用浮钮和 Ctrl+G 将文件与 `node:path` 编组；换个缩放比例、反向拖到窗口边缘再做一次 | 命中对象与可见选区一致，浮钮可达。命名后拖组再重开，成员、坐标与视野正确；组框覆盖的非成员保持原位。对已有成员分别试取消与确认，实际旧组归属符合所提示的结果 |
| 空选、Esc、输入组名时按快捷键、切页、从键盘入口编辑已存在的组，在副本触发保存失败并恢复 | 待确认选区不写盘，浮钮和快捷键不跨页生效；失败原因和重试入口可见，待保存排布可恢复。用同一项目的闭环实点步骤、核个人布局，补受影响的共用控件与回访回归 |

使用同一输入对照初入画布、选中文件、框选松手、命名与异常时的实际页面。执行自测后冻结候选，委派独立审查者实操，优先核组框内框选、窗口边缘落点、旧组成员转移与保存重开。证据入口与场景配对；修改后在新固定候选上复验原失败输入和受影响路径。若实现需要改写作者试读资料或改变分组归属规则，带实际影响交回主脑。
