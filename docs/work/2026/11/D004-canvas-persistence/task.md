# D004 · 图画布自由布局与持久恢复验证

## 目标与批准依据

- 类型：探索，验证实现方案；产品目标已确定。
- 目标：用最小可操作画布，验证自由摆放、分组移动及本地持久保存，关闭页面和服务后重新打开恢复原布局；确认选定组件怎样满足要求，交付可复现证据与后续实现建议。
- 批准：2026-11-16（Asia/Shanghai），当前作者与主脑会话。作者在主脑提出资料／工具协议设计后，要求本次优先验证图画布，并约束实验投入：

> 行，你出下一单吧，去验证，然后你不必为了尽早让我体验就要去做那些其实没必要做的实验，因为既然我们花了很长时机去设计了，花了很长时间去思考了，那么我们就努力把它做好，我们也搜过资料，也有人做和我们相似的东西，但是我都不满意，所以想自己做，所以不用去做那些没必要的实验，只去验证那些最核心的东西，比如图画布，能不能自由布局还能保存，下次打开和上次退出的一样，这个是核心，这个验证通过，别的基本没问题了，很多东西靠现有技术的能力就能知道能行，不要为了做实验而做实验。

作者随后补充实验目的：

> 我们不可能因为验证什么东西实验失败了就不去做，实验的目的是为了验证可行，既然这样不行就想别的架构，而不是说做实验验证项目还有没有做的必要

本单据此替代主脑上一轮尚未落仓的 D004 协议设计建议。实验判断的是技术方案能否满足既定要求；组件不适配时寻找其他实现或架构，不将失败解释为取消功能、降低要求或放弃项目。其余能力在实施中做必要验证，不把 08 第 8.3 节机械转成一套必须先完成的独立实验，不以尽早展示为由增加实验。本单通过也不等于其他产品能力已经验证。

### 最小实验与落点

1. 先核现有环境及 Vue Flow 官方文档／适用接口，再固定兼容版本。沿已选 TypeScript、Vue 3、Vite、Node.js 24、Fastify、Vue Flow 建最小实验；只安装本实验必要依赖，包清单和锁文件留在实验目录，不改全局工具或建立根产品工程。
2. 使用一份小型合成图，含有连线的节点、具名分组及位于组背景范围内的非成员。提供拖节点、拖组、命名及调整组成员所需的最小交互；分组是背景，边界随成员位置计算。用少量控件或固定输入触发图内容／边变更和确定的节点增删，不实现 AI 生成或完整图编辑器。
3. 通过实验本地服务将布局保存到隔离目录的 JSON 文件，页面从该文件恢复。拖动结束及组信息改变后自动保存，显示待保存／已保存／失败；“已保存”必须对应服务确认落盘。节点坐标、组名、显式成员，以及本实验的平移／缩放视图纳入保存恢复；视图恢复是对本次“下次打开和上次退出一样”的实验细化，正式字段仍由后续协议设计确定。不能只保留浏览器内存或 localStorage，也不依赖页面退出时才写入。
4. 复用这套画布验证 A17，并在同一实验内判断 A18 重排保组的实现成本。采用足以判断行为的简单默认排布，不做美观优化、复杂避让、嵌套组或大图性能竞赛。

## 验证与停点

### 必须取得的证据

| 场景 | 通过条件 |
| --- | --- |
| 自由布局与组移动（A17） | 鼠标拖动节点到非默认位置；命名分组并拖组，全部成员保持相对位置，非成员即使处于背景框内也不跟随；成员变化后背景范围正确。 |
| 关闭并恢复（A17 核心） | 布局／组／视图保存成功后，记录文件及画面依据，关闭页面、停止服务，再启动并重新打开；节点位置、组名、成员、平移和缩放恢复，无初始化重排覆盖。核对保存数据和实际渲染，不能只用刷新、截图或一次 JSON 序列化代替整条链路。 |
| 图更新保留布局（A17） | 更改存续节点文案或边不重排旧节点；新增节点放在既有排布旁边；确定删除节点不移动其他节点，空组消失。再次重开结果保持。只对完整有效输入执行增删处理，读取失败不能当作空图清理布局。 |
| 保存失败 | 在隔离实验注入一次可控写入失败：界面不假报已保存，旧文件保持可读、未保存操作留在当前页面；恢复写入后重试并重开能得到新布局。正常保存与失败检查复用同一实现。 |
| 重新布局（A18） | 按 U93 尝试简单重排，记录是否能低成本保留组名／成员及实际结果；不得因追求更好看扩大算法。若保组代价高，给出证据和建议处理方式，保留既有用户分组，不静默删除；交主脑落实条件性取舍。 |

- 先完成类型／构建及直接相关的最小行为检查，再完成真实浏览器操作，测试串行。Windows／Edge 主验，Chrome、Firefox 只对本次拖动与恢复路径做适用兼容检查；缺环境如实列明，不将其扩成浏览器安装或环境改造任务。
- 浏览器工具优先使用现有能力；若需 CUA，先说明仅操作本实验新页面完成拖动、关闭重开和结果核对，按 computer-use 技能执行，避开用户其他页面。不开多套并行服务、不做负载测试。
- 实验 README 和 handoff 记录候选提交、固定输入、实际库／运行时／浏览器版本、启动关闭命令、保存位置、操作步骤及逐项结果。明确哪些由组件提供、哪些需少量应用代码、哪些仍未验证。
- 作者体验入口只用于确认拖动、分组和恢复是否符合预期；AI 先做完技术检查，不把功能验证交给作者。不验收完整阅读器的视觉、教学、导出或安装体验。

### 方案不适配时

- 首先区分实验实现错误、组件限制和证据不足；能在授权技术范围内修正的局部实现由执行处理。官方说明只能支持判断，不能替代核心操作证据。

- 同一问题两轮“修复并验证”仍失败，依共同规则暂停该问题的写入式修复；继续可做的只读定位并交证据与替代方向。换组件、会话或子代理不重置轮次。此停点用于调整技术路径，产品目标继续有效。

### 独立审查

执行须调用未参与实现的审查子代理，按审查角色及 Ponytail Review 绑定候选提交。重点核保存是否真的落盘、重开是否从落盘恢复、组成员与坐标是否一致、图更新是否保护旧布局、失败是否误报成功，以及结论是否超出证据。有效浏览器证据可复用，发现具体缺口再补，不机械重复全套实验。
