# D008 · 单篇讲解文档骨架与校验

## 目标与批准依据

- 类型：实现。交付一条完整的单文件制作工具链：AI 提供有序分块清单，程序读取固定源码、生成带 ID 的 Markdown 骨架；AI 填写正文后，程序解析并检查结构、定位和覆盖，返回可供后续阅读页复用的结果。
- 批准：2026-11-17（Asia/Shanghai），本会话。作者交回 D007 后要求依据现有设计继续安排开发；主脑提出“一单完成生成单篇讲解骨架 → AI 填正文 → 工具解析与校验，复用固定提交取源，暂不包含网页和自动讲解”，作者明确回复：“按这个范围派单”。本文件与派单提交共同固定批准范围，原文冻结；实际范围调整另记 amendments。
- 同次作者补充：“每一单范围就是做一类事情，把任务做好，不做范围太大。保证能验收，这样质量高。”本单以单篇文档的制作与检查作为完整交付，生成、解析、校验沿同一格式联动；M06 的完整使用路径是验收入口，不扩入后置功能。
- 产品目标与分工已经在首版设计确定；本单落实这一段可运行能力，不重新设计全产品，也不单开可行性实验。

### 本批交付

下表定义本批验收结果；正式 `tasks.md` 按其依赖拆实施步骤，不另复制一份要求。

| 编号 | 必须达到的结果 |
| --- | --- |
| M01 文档定位 | 文件讲解按 `docs/aftertaste/current/<源码相对路径>.md` 镜像，保留源码扩展名，文档头记录完整提交。源码路径由镜像推导，不另维护重复的源码路径字段。文档与源码明确落在指定项目边界，使用已有仓库／项目前缀映射；不以 cwd 或安装目录猜项目 |
| M02 骨架生成 | 接收已固定源码引用及 AI 提供的有序块清单，支持对照块和穿插的纯讲解块。程序校验范围并生成同篇唯一的 8 位随机小写字母数字 ID 和成对标记，处理生成时碰撞；不替 AI 猜语义分块、不抄源码。提供真实 CLI 将新骨架写入 M01 的位置；已有文档不得被创建命令覆盖，失败不能截断或破坏已有文件 |
| M03 解析 | 沿 06 的顶层成对 HTML 注释语法解析，保留正文 Markdown、块 ID、顺序和定位。正确区分顶层标记与围栏代码、缩进代码、列表／引用中的示例；标题不产生块。非法或重复字段、坏 ID、坏范围、嵌套、缺少配对等有明确诊断，不能把错误的 lines 当成纯讲解块 |
| M04 机械校验 | 非空源码的每一行按顺序恰好覆盖一次，包括空行和注释；检查漏行、重叠、逆序、越界和重复 ID。纯讲解块不占源码范围。从文档头的固定提交取源，工作区或 HEAD 改动不能改变依据；源码不可读时准确报告未完成源码校验，不假报通过 |
| M05 警告和结果 | 源码 60/61 行、讲解 1,200/1,201 个非空白 Unicode 码点按 06 分别判断，超过才警告，不自动拆块、不因此判为结构失败。结构问题返回稳定问题码、文档／块／行等定位及修复线索，保留可供普通 Markdown 展示的原文；后续页面能够据此区分有效对照、警告与降级，CLI 退出状态和输出协议相符 |
| M06 可用入口 | 共用用例和真实 CLI 支持创建骨架、校验已有单篇文档。以合成 Git 项目完整走通“固定 A → 创建 → 填写合成讲解 → 校验 → 修改工作区后再校验”，并提供可重跑使用示例。骨架生成、机械合法与讲解完成明确区分；机器不声称判断了教学质量 |

本单创建命令只承担新建单篇文档；修改正文由 AI 按既定分工进行，校验命令只读。普通改写与校验保留已有 ID，检测到重复 ID 不自行改写。重分块的新 ID 原则继续有效，但本单不做拆分合并编辑器、历史差异或个人记录迁移。

执行在既有技术授权内定稿文档头、命令输入输出、空文件／文件末尾换行的物理行口径、块外内容和无有效块时的诊断，以及新建写入的防覆盖方式；写进本功能的模型与契约并测真实边界。空文件不能虚构第 1 行。骨架正文未填写的表达不得冒充讲解完成。文件系统路径、现有符号链接／junction 及错误输入须守住项目与资料目录边界，失败不落完整或摘录源码副本。

本单仅定义单篇文档与调用上下文，不创建整套更新状态／发布事务或全项目资料注册表。历史读取继续保留 D007 在当前子项目目录缺失时可读原 Git 的能力；初次在项目中写骨架所需的现存目录检查不能反向加回历史取源入口。

## 验证与停点

- 正式单测覆盖两类块混排、真正顶层与多种代码／容器上下文中的标记、错误结构及非法 ID／范围。覆盖空文件、空白／注释行、LF／CRLF、末尾有无换行；Unicode 码点与 White_Space 按 06 计数，测试边界而非只用中文长度样例。
- 对范围连续覆盖、生成后解析、ID 唯一及正文保真等适用性质，按 property-based-testing 方法选择独立可判断的性质；保留具体反例，不以与实现相同的算法作为测试预期。不为调用技能机械增加测试库。
- 集成及真实 CLI 验证 M01／M02／M06：不同目录同名和不同扩展名不冲突；固定版本与子项目映射正确；读取失败不退到工作区；重复创建保护旧文档，越界或链接绕界被拒绝，写入失败没有成功假象及源码落盘。校验不改文档及已有 ID。
- 串行完成 typecheck、build、本批测试和受影响的既有取源回归。按影响选择检查，最终候选形成后复用相同版本证据；没有新增变化或未决风险不重复整套测试，不另建演示实验或性能负载。
- 执行用固定提交交未参与实现的子代理独审，按 Ponytail Review 追共用用例、CLI、解析器和写入调用链；Sharp Edges 重点核 Markdown 上下文、路径／写入边界、失败结果和源码泄漏。结论绑定候选，原文归本单 `review.md`。
- 作者页面／教学体验本单不适用；作者无需代跑机械测试。源码与结构测试不能冒称完整 A01—A05 页面验收。若必须改变块格式、源码只引用或其他已确认用户结果，暂停依赖部分交主脑；通常字段与实现细节自主处理。
