# D046 · 从左往右读懂后端请求：两图分层、紧凑文件树与讲解深度

## 目标与批准依据

实现任务。读者打开 Apache Answer 的收藏闭环，能从左侧入口顺着同一次请求看到分支和汇合，点开关键步骤就读懂进来的数据、谁决定写库、返回了什么。转到文件依赖图能沿直接引用逐层读，转到文档能在紧凑的目录树里找到相应文件。

2026-11-23，作者在 [D045 试读](../D045-alpha-first-run/handoff.md)后反馈“文件树有点大”“闭环图如果没使用图例为什么要加图例？那图例都没连节点”“没有讲解偏好，所以讲的很不详细”，要求“先修我说的这些，然后再考虑去发布”。作者确认“默认从左往右排就够了”，补充“程序识别没有位置，就自动给他从左到右一层层排好，如果识别到用户自己有改动就用用户自己的。重新布局也是改成从左到右一层层的”。三张原图分别是[文件树外观参考](tree-reference.png)、[依赖图现状](dependency-before.png)、[闭环图现状](loop-before.png)。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

本地开发仓库 `D:/project/SpecDev Harness/aftertaste-reader`，从 `dev@1fa27a2`（D045 合并 `5d1149f` 后的回执提交）开始，任务分支 `codex/fix-alpha-reading-layout`。本单的批准版本由派单消息提供。真实输入沿用 [D045 实验入口](../../../../../experiments/D045-alpha-first-run/README.md)的 Apache Answer `3f1ed50f6776452c11b6ffdbdc767cd1887d629b` 及收藏请求。作者的试读服务、安装和项目在仓外，用独立副本做本单的写入、重排和试讲。

**双图排布。** AI 负责在图 JSON 里提供节点及有依据的关系，闭环另有入口和推荐阅读顺序。程序根据实际有向边计算坐标，读取教学数据无需 AI 提供位置。现有 [默认布局及重排](../../../../../src/core/canvas-layout.ts)只收 ID，每三项换行。[服务读取](../../../../../src/application/canvas-layout.ts)与[页面重排](../../../../../src/web/DependencyCanvas.vue)应复用同一分层规则。

- 闭环从 `entry` 起按教学边向右推进，分支上下分开，汇合点置于来路之后。推荐顺序仍用于阅读和同层稳定排序。回边和自环保留箭头与理由。在作者这条长路线中，首屏能读入口及下一步，平移便可沿箭头继续，连线端点和文字清晰。
- 文件图继续按“被依赖文件 → 使用它的文件”排。例如 B 引用 A，图上 A 在左、B 在右。多个根、互不相连的子图、循环引用和孤立文件都要能读。循环内部允许回边，组件间仍按层前进；未核对项保留状态。库用法与闭环高亮沿既有语义，选择闭环不重排文件。
- 首开无布局时自动排。重开和刷新恢复读者摆过的位置、分组和视野。已有布局新增节点时固定旧节点，只给新增项安排位置，参考它们的关系在原排布旁分层、避开重叠。旧图可能只有一份完整的坐标快照，缺少手动标记时保护已存位置。两图现有「重新布局」均按当前关系重新分层、保留组名与成员，并沿既有机制保存。仅平移／缩放、展开详情或导航不得触发整图重排。教学 JSON 与个人布局各自存放。

**闭环库图例。** D045 的 Gin 对应两个参与文件，XORM 对应三个；成品记录的是文件用法，闭环画布却把库卡放在全部步骤之后，且只画步骤之间的教学边。[008 成品结构](../../../../../specs/008-loop-authoring/data-model.md) · [009 原设计依据](../../../../../specs/009-loop-reader/research.md)

- AI 只在解释某一步确实用到该库时采用图例，并用固定源码核清具体步骤及用途。画到图上的库须看得出服务哪一步，用与流程箭头可分辨的辅助关系表达，能查用法。它不参加业务层级、来路／出口或推荐顺序。无相关库的路线直接读步骤。
- 已有成品只记录文件用法时，保留在阅读详情中可找到的库介绍和文件用法，画布省去不能可靠绑定步骤的孤卡。同文件里可能既有用库步骤也有普通判断，不能给每一步猜连线。旧个人分组和位置在读旧图时须能正常恢复、保存；处理显示范围时防止悄悄擦除隐藏项的个人布局。新成品如需扩充步骤关联，复用既有图例 ID、用法与校验，同步制作、读取、布局和相关契约。

**文档文件树。** 按第一张参考图做单行紧凑的桌面目录，目录有展开箭头和文件夹图标，文件有小图标，层级靠适量缩进，当前行有整行底色。长名省略时能查完整名及路径。当前桌面侧栏宽 264 px，树行至少 36 px，名字可折行；在相同窗口以 14 篇真实讲解及其多级目录对比行数、宽度和正文空间。实现从 [ReaderFileTree.vue](../../../../../src/web/ReaderFileTree.vue) 与其作用域样式入手。只列已有讲解，保留自动展开当前路径、目录折叠、同名定位、切篇反馈、下方块目录及可调分隔线。窄屏点击和键盘焦点可用，颜色沿五主题语义 token。

**无偏好时也讲清楚。** D045 的 `preferences.md` 是空模板，读者首句却已经指出想追前端字段、谁决定写库、如何返回。已核原稿有两次事务和响应差别，服务接口怎样落到具体仓储的解释在提示里。改进[共用教法](../../../../../skills/aftertaste-reader/references/teaching.md)及[闭环制作](../../../../../skills/aftertaste-reader/references/loops.md)，同时覆盖普通文件正文和闭环串讲。当次问题足以决定重点就开始；有明确的简述要求也要遵从。沿用[偏好规则](../../../../../skills/aftertaste-reader/references/feedback.md)，一次读题不会自动变成长期偏好。

同一条后端请求用一组标明为假设的输入，追到各层实际拿到或改变的值、决定写入的条件、仓储接口怎样接到具体实现、ORM 的写入和最终响应。重要因果放在对应步骤正文，读者可沿首次收藏与重复提交两支看到差别。具体结果须据固定源码核对。文件声明、框架常识按读者问题取舍，验收看能否说清过程，不按字数或节点数计分。

**落点。** 复用 `src/core/`、`src/application/`、`src/web/` 和既有 Skill 指南及验证入口，受影响的解析、CLI、服务契约沿原职责维护。需求增量按 Spec Kit v1.4.0 `speckit-specify` 与实际 `spec-template` 维护 [005](../../../../../specs/005-generation-skill/spec.md)、[006](../../../../../specs/006-file-reader/spec.md)、[007](../../../../../specs/007-dependency-canvas/spec.md)、[008](../../../../../specs/008-loop-authoring/spec.md)、[009](../../../../../specs/009-loop-reader/spec.md) 中受影响部分。数据模型、契约与既有方案的变化按 `speckit-plan`／`plan-template` 增量同步，特别是 009 的旧默认排法。沿用 [08 现行规格](../../../../../specs/001-first-release/08-current-spec-and-acceptance.md)及既有共用画布规则。若需更新正式实施清单，按 `speckit-tasks`／`tasks-template` 只更新对应部分。本单是协作派单。

## 验证与停点

1. **实际双图。** 用同版收藏副本分别验无布局首开、拖动并分组后关页重开、在有旧位置的图增加节点、主动重排再重开。闭环从第一个节点向右，在原样本的 `choose-branch` 分出首次写入和重复提前返回，于 `send-http` 汇合。文件图用实际 54 个文件、85 条直接边和 2 个库检验密度及首屏；补小图验多根、菱形汇合、环、自环及输入顺序变化。保留坐标／组／视野、图数据摘要及实际浏览器画面的前后证据。确认高亮后「阅读此闭环」及步骤深链接仍可用。
2. **图例与树。** 分别读有准确步骤用法、仅文件用法和无图例的闭环，证明有用途的能追到步骤、同文件无关步骤没有虚线索、没有悬空库卡，文件依赖图上的既有库用法仍可查。在相同桌面视口比较树的可见行数与完整路径，复走多级折叠、同名或长名、键盘切篇和窄窗操作。
3. **实际试讲。** 用候选包里的 Skill，在独立项目副本以 D045 的原始读者问题和空白偏好重新生成受影响的代表性文件讲解与完整收藏闭环。可复用同提交已校验的其他文件讲解；给讲解 AI 的是读者问题和源码，核对答案放在验证侧。对比原文，指出读者现在能在哪些正文找到客户端字段与身份来源、默认组与实际写入字段、两个事务的先后、重复请求跳过的写入及两种响应。核空偏好能完成、有简述偏好时能尊重，分别记录源码可证事实和假设数据。在候选阅读器实际打开新版，提供文件、依赖图和直达闭环的链接与重开方式。保留 4357 原版作为对照。
4. 执行自测后冻结候选，请独立审查者用 Ponytail Review 在自己的副本验证上述阅读路径、布局保存、旧图例和新试讲，核教学事实与固定提交一致。正式浏览器和测试串行，运行证据放 `.local/D046/<run-id>/`，回执记录关键可复核结果。作者只需对比文件树是否顺手、两图是否读得出关系、读完能否解释同一请求的两种结果。
