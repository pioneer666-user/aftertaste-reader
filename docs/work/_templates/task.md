# D编号 · 主题

## 目标与批准依据

- 类型：探索／设计／实现／规范。
- 目标：一项完整、可判断的结果。
- 批准：日期、来源、关键原话与范围；批准后原文冻结。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。需要实际改写或删除作者资料时，按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

## 范围与材料

- 工作目录、按创建年月确定的任务资料路径、dev 基线、任务分支；任务批准提交由派单消息提供，避免自引用提交号。
- 相关规格路径及版本、本批要求／排除项、预期文件落点。
- 额外材料按“触发动作 → 文件／章节”列出；不重复根 AGENTS 的通用读取表，不把所有规范列为启动必读。
- 涉及正式需求／架构／实施清单时，指定 Spec Kit 技能与模板、完整流程或增量维护；前置缺口及偏离的已告知／决定依据。
- 按目录规范列本批源码／指南／测试位置；有实验则指定同 D 编号 experiments 目录，运行输出指定 .local 的独占位置。涉及搬移时说明旧文件去向与引用更新。
- 必要前提与已有可复用证据；无需重复公共纪律。

## 验证与停点

- 验收场景引用及必要检查；需要作者体验的入口与观察目标。
- 独审：需要／免审及理由；范围与重点。
- 超界或技术前提不成立时的返回条件；其余沿共同停点。

## 责任与交回

- 执行会话、Git 负责人；审查由执行调用独立子代理。
- Git 收尾：写清本单获准提交还是合 dev，发布授权另列。合并前的试读资源及候选单列；合并后的分支处置按 [Git 收尾](../../development/git.md#整合与收束)，确需继续保留分支名才注明依据及解除条件。
- 交回同目录 handoff，引用必要 review 和有效调整。
