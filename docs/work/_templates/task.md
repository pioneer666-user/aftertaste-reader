# D编号 · 主题

## 目标与批准依据

- 类型：探索／设计／实现／规范。
- 目标：一项完整、可判断的结果。
- 批准：日期、来源、关键原话与范围；批准后原文冻结。

## 每单沿用的产品原则

回味以当前版本为准，可以重做旧代码、变更数据格式，无需兼容旧代码或旧数据。格式变更时说清哪些资料受影响。遇到已不支持的旧文档格式，识别脚本只负责报错或警告，让使用产品 Skill 的 AI 知道哪个文件受影响、原因是什么。AI 按当前 Skill 的正常生成、校验流程改好或重做相应讲解、闭环，无需维护逐版迁移脚本或另写兼容指南。实际改写或删除作者资料仍按本单授权处理。

回味在本机运行，页面可以充分尝试质感、动效和高级交互。读者大部分时间在看讲解，优先打磨文字、布局和操作。涉及界面时，用本地试读资料走通这次改变的场景，细看真实内容和窗口边界下的阅读与操作效果。

桌面是主要阅读和操作环境，交互与视觉细节优先在桌面打磨。手机默认只需能打开讲解或图，读到主要内容，需要时可滚动查看。新功能可以只在桌面提供，例如画布编排。手机专属布局、精细手势和逐项体验验收仅在当次明确需要时安排。

## 范围与材料

- 工作目录、按创建年月确定的任务资料路径、dev 基线、任务分支；任务批准提交由派单消息提供，避免自引用提交号。
- 相关规格路径及版本、本批要求／排除项、预期文件落点。
- 额外材料按“触发动作 → 文件／章节”列出；不重复根 AGENTS 的通用读取表，不把所有规范列为启动必读。
- 涉及正式需求／架构／实施清单时，指定 Spec Kit 技能与模板、完整流程或增量维护；前置缺口及偏离的已告知／决定依据。
- 按目录规范列本批源码／指南／测试位置；有实验则指定同 D 编号 experiments 目录，运行输出指定 .local 的独占位置。涉及搬移时说明旧文件去向与引用更新。
- 必要前提与已有可复用证据；无需重复公共纪律。

## 验证与停点

- 验收场景引用及必要检查；需要作者体验的入口与观察目标。
- 独审：需要／免审及理由；范围与重点。
- 超界或技术前提不成立时的返回条件；其余沿共同停点。

## 责任与交回

- 执行会话、Git 负责人；审查由执行调用独立子代理。
- Git 收尾按[提交与候选](../../development/git.md#提交与候选)写明本单是否需要作者先试读。需试读的写清入口与待判断事项，无需作者验收的在自检及独审通过后直接合入本地 dev。推送与发布授权另列。合并后按 [Git 收尾](../../development/git.md#整合与收束)处置任务分支。
- 交回同目录 handoff，引用必要 review 和有效调整。
