# D编号 · 回执

## 当前结论与入口

顶部是唯一当前状态；候选、验收和 Git 状态变化时就地更新，无关项省略。实例化到年月任务目录时重算本模板的相对链接。

- 实际完成范围、可用入口与限制；成果候选／比较基线，自检与独审各自的版本、结论和下文证据入口。
- 作者接受的版本／范围、尚未亲验的改动、待验入口及关注点；不适用说明理由，不记成产品验收通过。
- 当前分支与工作区、dev 整合、master／main、推送／发布；运行服务、已安装 Skill 或构建与源码不同时分别说明。分支保留时写理由及解除条件。
- 下一步、负责人及待决定事项；停点按[验证规则](../../development/verification.md#stop-rule)短写影响、恢复方式和建议，区分缺陷状态与阶段接受。不自动开始下一单。

## 依据与验证

- 批准任务／直接维护指令、有效调整入口及版本；正式要求／验收编号、基线、行为候选和修复提交。纯归档提交与成果候选分开，不循环补写本回执 SHA。
- 实际命令、输入／样例、环境、独立预期与实际结果、证据位置和可复核状态；复用已有证明，不复制完整日志。
- 涉及正式文档时，写实际使用的 Spec Kit 技能／模板、完整流程或增量维护、前置缺口和偏离的告知／决定依据；其他任务省略。
- 独审候选、原文链接、发现与处理／复核结果、写入交还状态；未审如实说明，原文仅存 review。
- 作者验收保留日期、来源、关键原话及版本／范围；新变化只复核受影响项。
- 必要失败保留日期、候选、累计轮次、假设／改动、结果与原件入口；普通旧状态由 Git 追溯，不在下文再维护一份“当前”。

## 资源与交回（适用时）

- 主脑会话交接或作者要求直接维护而不另编号时，按[任务流程](../../development/workflow.md)与[维护约定](../../development/maintenance.md)记录必要依据；历史原话和审查原文不改写。
