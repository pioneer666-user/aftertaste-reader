# 目录职责与文件落点

本页是回甘工程目录的唯一主定义。2026-11-16 按 [D002](../work/D002-directory-layout/task.md) 建立，供主脑派单、执行新增文件和审查核对。产品数据的具体协议仍在 `specs/` 定义，不用目录说明替代协议设计。

## 三种根目录先分清

| 根目录 | 放什么 | 谁维护 |
| --- | --- | --- |
| 回甘开发仓库 | 产品源码、产品 Skill 原件、开发规范、测试与实验 | 回甘开发角色 |
| 安装后的产品包／Skill 目录 | 编译程序、预构建页面、打包的 Skill 及其参考和模板 | 构建／安装流程生成；用户使用时不回写通用指导 |
| 被讲解的目标项目 | 固定 Git 引用及该项目的讲解、图、历史、个人记录 | 产品工具、讲解 AI 和用户按规格分工 |

目标项目可以与回甘开发仓库不同。运行时须显式解析目标项目根和 Git 根，不能把命令当前目录或 Skill 安装目录当作用户资料根。开发自测使用隔离样例；本次不在回甘仓库根创建 `docs/aftertaste/`。

## 开发仓库的大块落点

| 路径 | 职责 | 不放什么 |
| --- | --- | --- |
| `skills/aftertaste-reader/` | 随产品交付的 Skill 原件；入口、讲解 AI 指南、模板 | 开发角色规范、实际用户偏好和讲解成品 |
| `src/` | TypeScript／Vue 产品实现，内部职责见下表 | 临时实验、任务回执、用户资料 |
| `tests/` | 正式行为测试、Skill 行为用例、受控固定样例 | 临时日志、真实用户源码副本、实验草稿 |
| `scripts/` | 构建、打包、开发维护等仓库级辅助脚本 | 面向讲解 AI 的产品业务命令、重复的业务规则 |
| `specs/<功能>/` | 已确认需求、方案、数据模型、接口协议与验收依据 | 执行流水、实际测试输出、可安装 Skill |
| `docs/development/`、`docs/roles/` | 工程协作规范与角色入口 | 产品使用说明、面向讲解 AI 的通用教学正文 |
| `docs/work/D编号-主题/` | 一项任务的批准、调整、回执、独审原文与证据摘要 | 正式产品代码、重复的规格和实施清单 |
| `docs/usage/` | 面向使用者的安装、启动、操作和排错说明 | 未实现能力的使用承诺、讲解 AI 操作流程的第二份正文 |
| `experiments/D编号-主题/` | 与任务绑定的实验代码、固定输入、配置、重建说明及结论依据 | 未经正式任务接纳的产品实现 |
| `.local/D编号/<run-id>/` | 普通任务可再生成的日志、截图、包与沙盒 | 唯一输入、唯一证据、长期个人资料 |
| `.agents/` | 开发技能固定来源、必要配套和来源核验 | 回甘产品 Skill、运行时用户数据 |
| `.specify/` | 官方 Spec Kit 共享模板／脚本、安装 manifest、workflow；memory 中的项目原则 | 产品实现、用户资料、手改的官方模板副本 |
| `dist/` | 构建生成的发布暂存内容 | 手写源文件、用户导出 HTML |

根目录只保留工程入口与必要工具配置，例如 README、AGENTS、包清单、单一锁文件、TypeScript／Vite 配置；由相关任务在需要时创建。任务草稿、报告、截图、压缩包不散放根目录。

## 产品 Skill 与讲解 AI 指南

先采用一个 `skills/aftertaste-reader/` 产品包位置，后续实际 Skill 任务编写入口；本次没有生成可调用的 `SKILL.md`。同一 Skill 按任务读取多份指导，目录拆分不等于增加用户功能。

| 后续文件落点 | 唯一职责 |
| --- | --- |
| `SKILL.md` | 识别生成、答疑、更新、闭环和反馈任务；路由到必要指导与工具 |
| `references/authoring.md` | 文档制作：块结构、覆盖、ID、骨架与机械检查的使用要求 |
| `references/teaching.md` | 共用讲解方法：结合代码特点、用户偏好、阅读方向及相关反馈组织解释 |
| `references/generation.md` | 普通文件讲解的分批生成与收尾流程 |
| `references/qa.md` | 仅提问与明确写回的区分、定位和局部修订 |
| `references/updates.md` | 固定版本更新、备份、中断续接、完成和简单文档恢复 |
| `references/loops.md` | 闭环路线选择、生成、版本适配及从头重做 |
| `references/feedback.md` | 偏好与阅读方向的读取、来源区分和维护规则 |
| `references/tools.md` | 已实现命令如何调用、诊断含义及查看工具源码的实际入口 |
| `assets/templates/` | 随包的偏好、阅读方向、更新说明等产物结构模板 |

这些是本次确定的文件职责和后续落点，不是已完成指南清单。执行按当前任务只创建需要的文件；确有职责调整时同步本页与入口引用。

- 通用指南是产品资产；目标项目的真实偏好、阅读方向、笔记等是用户资料，不能写回模板或用反馈自动修改发布的 Skill。
- 模板说明产物结构，指南说明何时用、怎样判断和填写；同一模板不在多个指南复制维护。
- 结构解析／机械校验的实现归 `src/core/`，产品命令归 `src/cli/`，业务用例归 `src/application/`；不在 Skill 下再写一套更新和备份程序。
- 指南示例使用合成内容或固定引用，不抄入真实用户源码。随包资源必须能相对包根定位；发布包不依赖开发仓库绝对路径。
- Skill 安装目录的宿主差异及 npm 打包清单由交付任务落实；不得把这份源码目录约定说成已验证安装入口。

## 产品代码内部边界

采用一个产品源码根 `src/`，不预设多个独立 npm 包。先建立根说明，子目录随对应实现创建。

| 子目录 | 职责与依赖 |
| --- | --- |
| `src/core/` | 领域类型、文档解析、结构／范围校验、比较等共用纯规则；不依赖 Vue、Fastify、文件系统或进程 |
| `src/application/` | 生成骨架、查询、更新、备份恢复、记录保存、导出准备等用例编排；定义所需的 Git／存储等端口，复用 core |
| `src/adapters/` | Git、文件系统等外部能力的实现；实现 application 需要的端口，不反向调用 CLI 或网页 |
| `src/cli/` | 面向 AI 的命令入口、参数与退出状态；组装适配器并调用 application |
| `src/server/` | Fastify 启动、HTTP 接口和预构建页面提供；组装适配器并调用 application |
| `src/web/` | Vue 阅读界面、可共享阅读组件、页面状态、图及静态资源；通过明确接口消费数据，不直接读 Node 文件系统 |
| `src/export/` | 单 HTML 的资源内嵌／组装及独立入口；复用 web 阅读组件和共用数据契约，不复制阅读器 |

导出用例及数据选择仍归 application；export 的 Node 组装侧与浏览器入口在实现时分开文件，浏览器代码不能引入 Node 适配器。共用类型和规则放 core，接口边界由对应协议定义；不提前造含混的根 `utils/` 或第二个 `shared/` 汇集任意代码。

运行所需样式／图标等归 `src/web/`，产品默认 Markdown 模板归 Skill 的 assets；构建从唯一原件复制到 dist，不手改 dist。具体文件名、内部模块和导入规则由实现任务细化，必要时由主脑维护本表。

## 测试、实验与任务编号

- `tests/unit/`：纯规则测试；`tests/integration/`：Git／磁盘／命令／HTTP／导出组合测试；`tests/e2e/`：真实浏览器用户路径；`tests/skills/`：产品 Skill 的请求、预期行为与评测说明。
- `tests/fixtures/`：正式测试共享的合成源码、Markdown／JSON 样例或生成样例仓库的脚本；真实 Git 仓库在忽略的沙盒中按脚本建立，不提交嵌套 `.git`。
- 一项实验与派单使用同一 D 编号：`docs/work/D003-主题/` 管批准与回执，`experiments/D003-主题/` 管实验材料。多个实验分支放同任务子目录，不另起 E 编号或第二套任务单。
- 实验从 [experiments 入口](../../experiments/README.md) 建立最小 README；说明目标、规格／任务依据、输入、环境、命令、判定条件和结果，不提前伪造结论。
- 实验输出放该实验 `.local/<run-id>/`；普通实现输出放根 `.local/D编号/<run-id>/`。同一输出只选一个位置；回执引用位置与摘要。
- 实验成功后由获批正式实现任务将需要的代码整理到 src／skills、稳定用例纳入 tests，保留实验记录与来源关系；产品不能 import experiments 或依赖其依赖目录。
- 原始输入和不可重建证据按任务授权保全；忽略规则不是备份。真实项目教学试用仍按固定 Git 引用读源码，不把源码、源码 diff 或包含源码的日志落进实验资料；合成测试样例不冒充用户资料。
