# 工程约定

适用于产品实现与技术设计。技术基线引用 [03 U102](../../specs/001-first-release/03-web-delivery.md)，产品边界引用 [08](../../specs/001-first-release/08-current-spec-and-acceptance.md)；本页规定如何保持实现一致，不重写业务规则。

## 职责与依赖

- TypeScript 承载共用规则、命令、服务和 Vue 页面；底层解析／规则不依赖 Vue、Fastify 或特定 AI 宿主。
- 命令和 HTTP 接口调用同一套用例与校验；入口只处理参数、传输和展示。相同输入的业务判定与失败含义一致。
- Git、文件系统和进程访问集中在可替换的适配边界；Git 使用参数数组，不拼接 shell 命令。明确仓库根、资料根与当前工作目录的区别。
- AI 负责教学语义、分块和影响判断；程序承担提取、结构、ID、备份与机械校验。校验成功不宣称解释正确。
- 产品 Skill 与开发技能分开；产品包不得隐含依赖巧格路径、开发者主目录或本机忽略文件。首个工程任务再确定实际源码／产品 Skill 目录，不预建空框架。

## 代码与接口

- 开启 TypeScript 严格检查；来自命令、HTTP、磁盘和 Git 的输入在边界做运行时校验，静态类型不能代替它。
- 核心数据模型、解析和诊断定义一处；文件格式与命令契约变化同时更新生产者、消费者、样例及相关检查。
- 诊断包含实际失败类别、必要定位和可执行的下一步；稳定标识供程序判断，中文说明供 AI／用户理解。退出码、输出格式和成功条件在接口方案中定稿，不临时由每个命令各自发明。
- 日志与诊断遵守源码只引用规则；测试数据用明确的隔离样例。运行时读源码和向页面返回源码不等于获准持久保存。
- 写入前校验目标归属、路径边界和允许覆盖内容；包含 Windows 路径、符号链接／junction 等实际绕界风险。恢复仅处理获批备份文档，个人资产按规格保护。
- 文件写入失败、重复调用和中断后的结果要可解释；根据实际用例选择必要保护，不为简单恢复添加事务引擎或另建状态平台。
- 本地服务限定项目读写能力；接口设计核本机监听、来源访问和路径边界。Markdown／HTML 渲染与单 HTML 导出检查不可信内容、转义及资源嵌入。
- “最小实现”以完整、易读和便于修改为准，不以最短 diff 为指标。不为未来需求加抽象、数据库、适配层或配置项。

## 依赖、构建与交付

- 首次工程搭建确定一个包管理器、锁文件和明确的检查／构建命令；后续沿用，不并存多套锁文件。具体版本在落地时核兼容性并固定。
- 新依赖说明实际用途、已有能力为何不足及运行／构建归属；安装在任务范围内进行，不自动升级全局环境。
- 发布包包含预构建命令和页面，用户无需编译 Vue；依赖 Node.js 与 Git 的既定安装方向不变。Python 仅可作为独立开发辅助，不进入产品必需链路。
- 本地阅读与独立导出分别验证；导出不能依赖仍在运行的服务、开发目录或 CDN。npm 包名、发布和版本升级另有明确任务后执行。
- API／格式变更写清兼容影响；已有用户数据迁移必须有对应范围、备份与验证，不能随代码清理顺带迁移。
