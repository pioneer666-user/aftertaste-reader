# 验证与验收

按本次影响选择，预期来自已确认规格；[08 的 A01—A25](../../specs/001-first-release/08-current-spec-and-acceptance.md) 是当前产品验收入口，均不能因为规范落地而勾成完成。

## 三种正确性

| 对象 | 必要证据 | 不能据此声称 |
| --- | --- | --- |
| 程序规则 | 类型／构建检查、受影响行为测试、真实命令或服务路径 | 讲解正确、用户已理解 |
| 产品 Skill | 实际场景的调用、产物、状态与范围；独立行为检查 | 仅文件格式通过就能稳定工作 |
| 阅读与教学 | 真实页面操作、失败恢复与实际试讲；作者体验 | 静态检查或审查代替作者验收 |

## 按影响选检查

先完成必要构建，再尽早跑最能决定本批是否可交付的真实操作。比如块内保存改动可先走受影响的 HTTP 与 Edge 回访，再按影响串行跑关联或全量回归。具体顺序随任务依赖调整。

- 规范／文档：链接、来源、现行与历史冲突、角色及交接场景；不为纯文档新增产品测试。
- 解析／定位：合法与畸形结构、代码围栏、重复 ID、空输入、边界行、Unicode。可表达独立性质时用 property-based-testing，不为覆盖率堆相似用例。
- 固定源码／更新／恢复：工作区与提交不同、Git 读取失败、重复准备、中断、首次备份不覆盖、恢复范围和用户资产保护；全部使用隔离样例，不破坏真实仓库。
- 命令／服务：相同用例在两个入口的语义一致、失败状态与诊断真实、路径越界和错误参数；不只测试内部函数。
- 数据保存：写入失败、重复调用与实际竞争情形，核原资料和未保存输入；按风险设计失败注入，不对真实个人笔记做破坏测试。
- 页面：长／空内容、键盘操作、状态转换、错误可见、重新打开后的持久结果；作者体验前由 AI 完成可做的功能检查。
- 设备范围沿用派单模板的[每单产品原则](../work/_templates/task.md#每单沿用的产品原则)。桌面分屏、键盘操作仍按本次改动核验。改到手机主要阅读路径时，用一个常见手机宽度走通受影响内容即可。以往某单的触屏操作、机型或多尺寸用例只作对应场景的证据。
- 导出：各选项的数据确实包含／排除、真实版本与更新状态、停服务并移走项目后打开、覆盖失败；隐藏 DOM 不等于移除未选资料。
- 安装／发布任务：在干净隔离目录验证真实打包产物和入口，区分首次安装、日常启动与离线阅读；不拿开发服务器成功替代产品包可用。

## Skill 行为验证

- 选受影响的真实请求及固定样例，检查实际行为和产物，不匹配固定措辞。
- 重点场景：首次范围未答、只提问与明确写回、Git 失败、更新中断与恢复、用户偏好冲突、旧闭环、更新中导出；按变更选取。
- 区分“开发审查子代理”和“模拟使用产品 Skill 的测试代理”；审查者未参与实现，行为试用遵守任务限定的资料和写入范围。
- 行为改进需要比较时固定输入，对比旧版／无 Skill 基线；记录实际模型、宿主与技能版本，不由单次成功推断所有模型可用。
- 讲解正确性核固定源码，教学是否有帮助由作者实际阅读判断；保留失败例子，下一次改进复用。
- Anthropic 评测流程目前只是候选参考，未接入或运行；不会因此产生额外产品运行依赖。

<a id="author-acceptance"></a>
## 作者验收

- 改变正式页面、图解、交互或讲解行为且需判断观感、理解与操作感受时，AI 完成必要客观检查及独审，给作者当前候选入口和最多三个体验关注点，询问试读意见。纯规范等无产品体验的工作在回执中说明验收不适用，按[本地合并规则](git.md#提交与候选)收尾。
- 记录日期、来源、关键原话及接受的版本／范围，列明本次改动中尚未亲验的部分；局部认可不能扩成全部通过。相关呈现或行为再改，只补受影响验收；同任务收到通过后继续收束，不必另开一单。
- 适用验收未完成时保留候选，按[Git 门槛](git.md#整合与收束)等待；作者明确允许阶段接受时按下方停点记录，不能把接受合并记成产品体验通过。
- 仅改名称／文字而不改布局、交互或业务含义，核替换范围、语义及必要静态／构建检查即可，不专为此操作浏览器。权限含义、默认行为、风险提示或按钮作用变化不适用此例外。

<a id="resources"></a>
## 环境、资源与证据

- 首版按已定 Windows／Edge 主验；Chrome、Firefox 对受影响浏览器能力做适用兼容检查，记录实际 OS／浏览器版本。未测平台明确写未测。
- 浏览器检查优先已有测试工具或可复用证据；AI 不默认开展多浏览器并行或 CUA。确需 CUA 时先说明用途与范围，按当次授权使用；作者体验不替代技术检查。
- 相关测试一次一个文件串行执行，全套获准也串行。负载、批量服务、再次复现崩溃等先与作者确认；同版本成功检查不机械重复。
- 启动前核端口、地址、进程和数据目录，复用已知合适环境。自建服务、浏览器和沙盒记录归属、用途、标识、关闭方式；结束只清理本次创建、可重建且不再需要的资源，不终止未知进程。待验需保留的资源写明版本、入口、重启方式及清理条件。
- 证据绑定相关源码、依赖／配置、构建或安装包、Skill 与宿主版本，以及输入、环境、动作、预期和实际结果。相关输入或环境改变时重判复用范围；代码已合并不证明服务、已安装 Skill 或导出文件已更新。
- 动态问题检查真实过程与最终结果；先确认触发前提成立，再判断成功。截图只证明瞬间呈现，静态阅读或构建不能证明连续操作、失败恢复和保存后的结果；真实命令／页面路径与内部函数证据分开。
- 关键摘要与独审落仓；大日志截图按[目录职责](directories.md#测试实验与任务编号)放隔离 `.local`，注明不随克隆恢复。未独立编号的直接维护使用有日期的主题目录，不因此补造 D 编号。
- 保留必要失败、修复、跳过和限制；清理前确认唯一输入、仍需复核的原件及作者资产已保护。已删除或不能重跑的产物不能单独支撑结论；保留可复核的样例、命令与摘要，必要原件记录实际位置。包含用户源码的日志或快照遵守产品限制。

<a id="author-operations"></a>
## 重要操作与作者命令

- 安装／升级、停服务、恢复／删除、发布等改变运行状态的动作，或交作者亲手执行命令时，先在聊天讲清目的、设备／终端、目标路径、影响、必要口令及完成信号。是否需要新批准按[决策边界](../roles/主脑.md#decision-boundary)，已有批准内的说明不变成重复审批；无依据的耗时不承诺。
- 作者操作一次给一个有结束点的步骤；可复制命令单独代码块，不混终端提示符、预期输出、待填占位符或秘密。预期与需回传的非秘密结果另列。先核目标系统、终端、路径／编码与依赖，可等价验证的先由 AI 验证。
- 执行后报“完成／失败／待核”及实际变化。异常或超时先保留现场、查实际状态再给下一步，不能把结果未知当未执行而盲目重试；输入口令只完成认证，不扩大授权。

<a id="stop-rule"></a>
## 修复停点

- 同一问题累计两轮“明确修复＋验证”仍失败即停写。按未满足的同一要求和操作链判断，换原因、文件、代理或会话不重置；无关缺陷分开计数。只读定位、日志与审查不算修复轮次。
- 每次写入式修复前，在原失败记录补失败动作／断言、目标动作是否实际触发及依据、本轮要验证的假设；验证后补改动、结果和累计轮次。测试定位／前提错误、环境问题与产品失败分开记录；只修测试不算产品已修，测试或环境本身连续修复失败也受两轮停点约束。原因未明保留证据，不靠改预期或改分类清零。
- 停点交回四项：受影响路径；数据／权限／核心能力影响及证据边界；已验证可用范围与恢复方式；推荐继续修复、阶段接受或阻断交付及理由。主脑先核证据给推荐，不让作者替 AI 判断根因。
- 阶段接受需作者知情批准，绑定候选、未修缺陷、影响、恢复限制与后续条件；“缺陷未修”与“本阶段接受”分列，原失败结论保留。未获接受时只交回已完成范围与待决项；一条停点不抹掉其他有效成果，也不证明整单可交付。
- 停写期间可继续只读定位和已批准的无依赖工作；获得明确继续授权或调整方向后再行动，保留此前累计记录，不自动开启下一业务。
