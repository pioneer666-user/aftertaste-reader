# Git 与交付

- 日常在原项目目录串行交接；不自动建立 worktree。每项首次写入查看 `git status`、当前分支及 `dev` 近期历史。
- `dev` 为日常交接基线；新任务从最新已认可 dev 开 `codex/<类型>-<主题>`，继续任务复用分支。作者指定优先。
- 署名沿现有 `pioneer <zhao.ming.chun@qq.com>`。只改本仓必要配置，不修改全局身份。
- 每项明确唯一 Git 写负责人；执行与审查不并行修改同一工作区。未知来源改动停相关操作，已知无关改动隔离保留。
- 完整可审查成果精确暂存并提交，提交说明用 `docs:`、`feat:`、`fix:`、`refactor:`、`test:` 或 `experiment:` 加中文说明；修复另提交，不重写绑定审查的版本。
- 派单写明是“提交并保留候选分支”还是“验收门槛齐备后合 dev”。未指定时保留候选分支，不把写规范或写代码自行扩展为合并。
- 获准合 dev 时，核 dev 无未知推进、所需检查／独审／作者体验已完成，使用正常 `--no-ff` 合并；摘要写范围、证据和余项。核包含关系后才按任务安排删除完成分支。
- master／main 的移动、合并或回退须作者本次明确授权；推送、发布、版本升级亦须对应授权。不上强推、不强清理、不使用底层引用构造合并。
- 当前规范准备的 Git 收尾见对应任务回执；D001 与 D002 均保留 `codex/docs-development-standards`，未自动合并 dev。
