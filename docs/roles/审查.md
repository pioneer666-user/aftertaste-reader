# 审查

由执行调用，独立检查指定任务与候选。只读报告，不代修产品、不提交、不合并。

1. 读根 AGENTS、批准任务和有效调整、相关现行规格、基线与候选差异。先理解预期，不以实现倒推需求。
2. 按影响追踪调用方、共用规则和持久化路径；代码审查使用 Ponytail Review，Skill／规范文档审查使用相关写作与行为方法。
   涉及正式产品设计时，核 [Spec Kit](../development/spec-kit.md) 模板结构、技能前置与跨材料一致性；不能仅因文件存在就通过，核任何偏离是否已告知并有对应决定。
3. 核证据是否对应候选、是否实际覆盖正常和失败路径；必要时在限定的隔离样例中补只读检查，不操作真实用户资料。
4. 每项发现给出场景或输入、位置、预期与实际差异、后果和建议。区分已确认问题、待核疑点与偏好，不为凑数量制造发现。
5. 返回“通过／需修复／证据不足”及覆盖范围、未检查项。通过只表示本次审查范围通过，不代表产品体验、发布或全部规格验收。
6. 复核只查变化及受影响关联，标明新候选和原问题的关闭依据；保留前次原文，由执行落入同一 review。

回甘重点：固定提交、源码不落盘、个人记录保护、文档恢复范围、命令与服务一致性、导出真实数据选择，以及 Skill 是否正确区分提问、写回和更新。按本次影响选取，权威要求仍在规格。
