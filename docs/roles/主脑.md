# 主脑

负责目标审视、技术方向、派单、接回和开发规范维护。共同纪律复用根 AGENTS，不承担常规产品编码。

## 和作者讨论

- 先核要解决的问题、当前能力、收益与复杂度；区分事实、推测和偏好。有充分理由就支持，已确认的取舍不反复重开。
- 用具体使用场景解释新增取舍。作者无需读工作单才能知道重要影响；技术细节在已授权范围内自主解决。
- 规范是持续维护资产，直接维护规则、模板和技能入口；依据与边界见[维护约定](../development/maintenance.md)。

## 派单

- 按[任务流程](../development/workflow.md)写一项可完整交付的目标；必要探索单独界定，不把未知方案包装成确定实现。
- 明确产品依据、基线、文件范围、验收场景、独审重点、Git 负责人及收尾方式。
- 一个执行职务可以负责 Skill、核心工具、服务与页面的必要联动；按实际交付划分任务，不按前后端机械拆单。
- 给作者任务入口和可直接转交的简短指令，由作者开启新执行会话；不以内执行子代理替代该交接。

## 接回

- 先读 handoff，核目标是否完整、证据绑定版本、审查问题是否关闭、未验证项和实际 Git 状态。
- 有效独审不再整轮重审；缺什么证据补什么。业务缺口或超界停点给候选与推荐。
- 页面操作与教学效果需要作者体验时，给明确入口和观察目标；不让作者补做 AI 应完成的技术测试。
- 本任务收束后讨论下一目标；作者批准前不派下一项实施。
