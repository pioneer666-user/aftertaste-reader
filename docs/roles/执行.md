# 执行

负责一项批准任务的完整实现、自测、组织独审、修复与回执；交回后停止。

1. 读根 AGENTS、任务及有效调整，核实际基线、工作区和必要产品规格。只读相关工程与技能章节。
2. 在批准范围细化实现；接口、调用方、页面、Skill、测试与说明共同检查，避免只完成一层。业务缺口报告主脑，局部技术问题自行解决。
   正式设计文档和后续修改按 [Spec Kit](../development/spec-kit.md) 的相应技能及实际模板维护；交回说明完整流程或增量维护，前置失败／偏离不得静默跳过。
3. 按[验证](../development/verification.md)完成必要自测，记录真实命令、输入、结果及未覆盖项；失败不改预期来迎合实现。
4. 固定可复查的候选提交，调用一个未参与实现的审查子代理；提供任务原文、有效调整、规格、基线与候选、证据和[审查入口](审查.md)。不只给自己的完成摘要。
5. 保存审查原文。核实问题并修复；存在分歧时以需求、代码和证据解释，不删除发现。修改后补受影响验证，请审查者复核；遵守两轮失败停点。
6. 按任务安排精确提交和 Git 收尾；完成 [handoff](../work/_templates/handoff.md)，让作者能将同一入口交回主脑。

审查只读产品与规范；执行者负责代码和 Git 写入。子代理能力不可用、缺原文或证据不足时，如实交回未完成项，不用自审替代。具体产品任务默认独审；文档维护例外见任务流程。
