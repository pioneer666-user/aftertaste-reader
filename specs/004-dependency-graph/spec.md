# Feature Specification: 固定版本文件依赖图维护

**Feature Branch**: `codex/feat-dependency-graph`

**Created**: 2026-11-17

**Status**: Ready for planning

**Input**: User description: D009 [task.md](../../docs/work/2026/11/D009-dependency-graph/task.md) @ `c4010db` 的 G01—G05。已有固定取源及单篇讲解工具，证据为 D008 handoff；本批只落实同一提交内文件图工具。允许新增本目录与任务指定调用链，不改首版裁决。产品依据为 08 R01/R06/R08/R09/U101、A08/A09 工具部分及 04 U82—U86/U88。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登记本批文件并查询状态 (Priority: P1)

AI 在确认的固定提交内登记本批真实文件，随后查看文件依赖与使用者，避免把未分析误认为没有依赖。

**Why this priority**: 建图需要稳定文件身份及真实分析状态。

**Independent Test**: 在合成仓库登记文件，重复登记并查询；缺图时查询不创建资料。

**Acceptance Scenarios**:

1. **Given** 图不存在，**When** 明确登记本批文件，**Then** 创建固定版本图，新节点均未核对；重复登记不丢边、不降级状态。
2. **Given** 未核对、已核对无依赖、未登记文件，**When** 按路径查询，**Then** 三者可区分，含实际固定提交、依赖及使用者。
3. **Given** 空图或空登记，**When** 提供失配固定引用，**Then** 拒绝写入，不能借无文件绕过版本核验。

---

### User Story 2 - 提交完整依赖 (Priority: P1)

AI 以小份输入提交明确核对完的使用者及完整直接依赖，程序只替换这些使用者的关系。

**Why this priority**: 小批维护必须保留未提交文件的成果。

**Independent Test**: service 的依赖由 schema/old_repo 改为 schema/new_repo，router 使用 service 的边不变；重复提交幂等。

**Acceptance Scenarios**:

1. **Given** 多个使用者，**When** 仅提交 service，**Then** 只替换指向 service 的边，service 已核对，新引用文件未核对。
2. **Given** 未核对 service，**When** 明确提交已核对且依赖为空，**Then** 表达无依赖；缺完成声明或列表则失败。
3. **Given** 循环及未讲解项目文件，**When** 提交真实路径和原因，**Then** 允许环，不生成讲解或递归分析。

---

### User Story 3 - 明确删除节点 (Priority: P2)

AI 只在明确指定时移除图节点，获得被移除关系和仍存续的受影响文件。

**Why this priority**: 局部纠正不能被解释为删除其他资料或完成新分析。

**Independent Test**: 删除 schema 后其关联边消失，失去依赖的 service 回到未核对，router 和个人资料保留。

**Acceptance Scenarios**:

1. **Given** schema 被 service 使用，**When** 明确删除 schema，**Then** 移除关联边并报告，service 未核对；未指定节点不删。
2. **Given** 已完成一次删除，**When** 重复删除，**Then** 不产生额外修改；源码、讲解、笔记、闭环和历史保持。

---

### User Story 4 - 检查与安全保存 (Priority: P1)

AI 可直接编辑图后独立检查；程序在完整候选通过检查后保存，错误时保留原图和输入。

**Why this priority**: 诊断与旧资料保护是每次维护的前提。

**Independent Test**: 对损坏资料、非法路径、重复边、缺对象及保存失败操作，检查诊断和落盘原文。

**Acceptance Scenarios**:

1. **Given** 手编图有重复节点/悬空边/错误字段，**When** 检查，**Then** 定位字段/节点/关系，不假报通过。
2. **Given** 对象不可用但图可读，**When** 查询，**Then** 返回已保存关系；**When** 核查源码，**Then** 明确未完成，不切换 HEAD/工作区。
3. **Given** 旧图损坏/不可读/版本不同，**When** 应用，**Then** 拒绝覆盖；发布前失败保留原图和输入，不发布部分结果。
4. **Given** 普通大小写别名或链接绕界，**When** 读写，**Then** 前者可用，后者拒绝；源码身份保留 Git 大小写。

### Edge Cases

- 仓库子项目、其他 cwd、HEAD/工作区变化；空图、空登记、显式空依赖、自环与循环。
- 非法 JSON/编码/字段、重复节点/边/使用者、悬空引用、非法或提交中不存在的路径。
- 缺对象、形似完整提交的分支、映射失配、只读缺图。
- 临时碰撞、写入/发布/清理失败、symlink/junction 与大小写别名。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (G01)**: 系统 MUST 仅用完整固定引用登记真实项目文件，保留既定图位置；空图也核验提交身份与映射。
- **FR-002 (G01)**: 系统 MUST 仅明确写操作初始化图，新节点未核对，重复登记保留状态及关系；只读不建图。
- **FR-003 (G02)**: 系统 MUST 按明确核对使用者替换完整依赖；未提交者不变，重复幂等，显式空列表与未完成分开。
- **FR-004 (G02)**: 系统 MUST 保存被依赖方→使用者的直接关系及 AI 原因，允许环；新引用文件未核对，不递归分析。
- **FR-005 (G03)**: 系统 MUST 查询依赖、使用者、状态和保存的提交，区分未登记/未核对/已核对无依赖；对象不可用不丢关系。
- **FR-006 (G03)**: 系统 MUST 共用检查结构、字段、重复、引用、路径与固定版本真实文件；不可核验时明确未完成，诊断定位且不含源码。
- **FR-007 (G04)**: 系统 MUST 仅明确删除节点及关联边，返回移除边和受影响存续使用者；被动失边者恢复未核对，不动图外资料。
- **FR-008 (G05)**: 系统 MUST 完整校验候选再安全发布；损坏/不可读/版本不同的旧图不能当空图覆盖，失败保留输入与旧图，准确报告是否已发布。
- **FR-009 (G01—G05)**: 图 MUST 只存源码引用、分析状态和关系说明；不保存源码/缓存、不跨版本同步或扩展外部仓库/库节点。
- **FR-010 (G03/G05)**: 命令 MUST 明确目标、固定依据与意图，使用稳定诊断和定位；机械通过不证明语义完整、解释正确或用户理解。

### Key Entities *(include if feature involves data)*

- **文件图**: 单一固定提交的节点与关系，保存在项目既定资料位置。
- **文件节点**: 项目相对 Git 路径和未核对/已核对状态，不表示讲解或理解进度。
- **直接关系**: 被依赖方、使用者和原因；同文件对唯一，允许环。
- **局部提交**: 登记清单、明确核对者完整依赖、明确删除清单；未出现文件保持。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: G01—G05 全部场景有可重跑输入与确定结果。
- **SC-002**: 重复提交后节点、关系及状态一致，未提交者关系全部保留。
- **SC-003**: 所有已测发布前失败中旧图逐字节不变，输入及无关资料保留；发布后异常可识别已更新事实。
- **SC-004**: 查询区分三类分析状态，检查失败可定位或说明未完成，无源码回退或正文持久化。

## Assumptions

- AI 判断依赖与原因；范围外文件指同一项目，仍需固定版本真实路径。
- 复用 D008 固定取源与路径保护，新增替换发布另测。
- 沿 task 授权细化协议；不含自动解析、Skill 教学、调度、HTTP/网页、图例/画布/闭环、跨版本同步或恢复。
- 无页面或教学呈现，作者体验验收不适用，A08/A09 仅工具部分。
