# Phase 0 Research

## 项目资料与写入

**Decision**：采用 `docs/aftertaste/bookmarks.json`。复用 `dataDirectory` 和布局存储的同目录排他暂存、同步、复核原件、替换路径做法。

**Rationale**：书签可随项目再次打开。旧资料损坏、被占用或变更时中止保存，已有字节仍可恢复使用。

**Alternatives considered**：浏览器存储无法稳定随项目划分。直接覆写会让失败暴露部分结果，数据库和跨进程锁超出本地单服务范围。

## 逐条操作与两页并发

**Decision**：沿用 Host、Origin、Sec-Fetch 检查，写入要求专用页面标识及 JSON。不接收整表覆盖。服务串行读改写，添加用客户端生成的 UUID 保持同请求可重试，编辑和移除按记录的预期备注保护并发修改。

**Rationale**：两个页面修改不同记录会保留各自的变化。编辑相同记录时可先看最新备注，再确认自己的修改。

**Alternatives considered**：整表覆盖会丢失已保存操作，整表版本则会让修改无关记录的两页产生不必要的冲突。

## 阅读定位与状态

**Decision**：复用当前文档读取及顺序保护，以文档路径＋块 ID 定位。等待 Vue 渲染后滚动到并聚焦所选记录。失败留在列表并显示条目详情，直到重试恢复。

**Rationale**：同一块 ID 可出现在两个文件，同块可有多个书签。当前讲解重新读取才能识别暂时失效或恢复。

**Alternatives considered**：散列锚点无法处理跨文档、异步渲染和同块多记录。保存行号会在块重排后指向错误位置。

调研核了现有布局存储、阅读服务、块解析与页面导航。实际文件锁验证复用仓内浏览器测试的 Windows 文件共享机制。
