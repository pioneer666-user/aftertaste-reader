# 依赖画布数据模型

## Graph

D009 图协议定义内容、身份及更新方式。路径在该图内唯一且大小写敏感。画布用图原文摘要标记读取快照。每个文件额外提供当前讲解列表中实际匹配的镜像入口。

## CanvasLayout

`docs/aftertaste/dependency-layout.json` 为 UTF-8 JSON。布局文档只含 `format`（`aftertaste-canvas-layout/v1`）、`graph`（`dependency`）、`revision`（已落盘保存尝试的 UUID）、`layout`。

- layout.positions 是以对象 ID 为自有键的坐标表。依赖图用 D009 路径。
- layout.groups 为 `{ id, name, members }` 数组。ID 为 UUID，名字为去除首尾空白的 1—160 字符（按 UTF-16 计），允许重名。每个 ID 最多属一个组，加入另一组时转移归属，组至少有一名成员。
- layout.viewport 为 `{ x, y, zoom }`，画布坐标和视野位移为绝对值不超过十亿的有限数，缩放范围 0.25—2，保存保留原精度。
- 组框由成员坐标及实测节点尺寸加留白获得。不保存框位置或画布尺寸。拖组使用画布位移，每次从起点快照计算，重排保留组身份、名称和成员。

## 图与布局协调

图内容按 D009 的结构和引用校验读取。节点缺失时，持久清理还需图工具记录的明确移除凭据。图工具在成功发布完整图时，将已明确移除的路径记入 `docs/aftertaste/dependency-graph-removals.json`，绑定图原文及实际文件身份和修改时间。后续正常工具更新保留仍缺席的已确认路径。凭据缺失、损坏、失配或缺少路径时，页面提供当前结构合法的图预览，暂停布局保存并保全磁盘坐标和组。结构损坏、读不到图时同样停止协调。手改图完成后可由 AI 用 `apply-graph` 的 `remove` 明确确认路径已移除；重复确认支持路径已不在图中的场景。

图中身份存续时保留坐标和归属，新节点优先从旧节点最右边以外排列，受坐标范围限制时选择有空间的一侧。四侧均已到极限时使用画布中央一列未占用的格位。确认移除的坐标和成员从保存结果去掉，空组消失。读取本身只返回预览，已有布局发生名单协调时，页面经同一保存入口提交协调结果，空图亦可清理确认删除。保存时再次核对图版本和移除凭据。
