# 依赖画布数据模型

## Graph

D009 图协议定义内容、身份及更新方式。路径在该图内唯一且大小写敏感。画布用图原文摘要标记读取快照。每个文件额外提供当前讲解列表中实际匹配的镜像入口。

## CanvasLayout

`docs/aftertaste/dependency-layout.json` 为 UTF-8 JSON。布局文档只含 `format`（`aftertaste-canvas-layout/v1`）、`graph`（`dependency`）、`revision`（服务生成的 UUID）、`layout`。

- layout.positions 是以对象 ID 为自有键的坐标表。依赖图用 D009 路径。
- layout.groups 为 `{ id, name, members }` 数组。ID 为 UUID，名字为去除首尾空白的 1—160 字符（按 UTF-16 计），允许重名。每个 ID 最多属一个组，加入另一组时转移归属，组至少有一名成员。
- layout.viewport 为 `{ x, y, zoom }`，画布坐标和视野位移为绝对值不超过十亿的有限数，缩放范围 0.25—2，保存保留原精度。
- 组框由成员坐标及实测节点尺寸加留白获得。不保存框位置或画布尺寸。拖组使用画布位移，每次从起点快照计算，重排保留组身份、名称和成员。

## 图与布局协调

完整图有效性按 D009 结构和引用校验。应用协议中的局部输入、缺失字段、坏编码、悬空边与读不到文件均不能触发清理。来自正式图工具的完整快照是节点名单，包括明确删光后的空名单。直接在磁盘替换结构合法的完整快照等价于发布；本协议无法辨认手写完整快照的编辑意图，维护请使用 D009 工具。

图中身份存续时保留坐标和归属，新节点从旧节点最右边以外开始排列。已移除身份的坐标与成员从协调结果去掉，删去因此变空的组。读取本身只返回预览，已有布局发生名单协调时，页面经同一保存入口提交协调结果，空图亦可清理确认删除。Graph 或布局读取出错时暂停提交。
