## User Scenarios & Testing

### User Story 1 - 沿关系进入逐文件讲解 (Priority: P1)

读者从项目阅读器打开依赖图，选中文件阅读其直接关系、核对状态和讲解状态。

**Why this priority**: 读者需要先辨认文件间的分工，再决定读哪篇讲解。

**Independent Test**: 使用两条边汇入 service 的 D010 样例，选中 service，打开讲解后返回，再选 audit。

**Acceptance Scenarios**:

1. **Given** 两条直接依赖边，**When** 单击 service，**Then** 留在画布，可识别被依赖方、使用者、原因和核对状态。
2. **Given** service 有讲解而 audit 无讲解，**When** 分别选中，**Then** service 提供显式入口且返回恢复原节点和视野，audit 显示无讲解。
3. **Given** 已核对且无入边的文件、未核对文件或自环／环，**When** 查看其关系，**Then** 这些状态分别可辨。
4. **Given** 初始文件清单响应暂扣，期间新增讲解并从图打开，**When** 旧清单返回，**Then** 标题和正文继续显示刚打开的讲解，可返回原视野，后续刷新及切篇照常（F4）。

### User Story 2 - 自由摆放并恢复 (Priority: P1)

读者拖动文件和整组，整理多个显式分组，再次打开时继续阅读。

**Why this priority**: 排布是读者自己的阅读线索。

**Independent Test**: 建两个组，在组框内放置独立文件，缩放后拖组，关闭页面与服务并重开。

**Acceptance Scenarios**:

1. **Given** 两个组和框内的非成员，**When** 拖动一个组，**Then** 仅其成员等量移动，边界随成员范围更新。
2. **Given** 已命名的多个组，**When** 重排或移走某组最后一员，**Then** 重排保组，空组消失。
3. **Given** 最新布局完成保存，**When** 关闭页面和服务并重新打开同一项目，**Then** 坐标、组和视野恢复。另一项目独立保存。
4. **Given** 已有布局，图包含根目录普通文件 `__proto__` 和相邻文件，**When** 分别移动两者并保存，**Then** 重开恢复两者各自坐标（F3）。

### User Story 3 - 图变化和失败时保全排布 (Priority: P1)

读者在重新核对依赖、增删节点或遇到写入问题后继续使用现有排布。

**Why this priority**: 图维护、临时错误或旧标签页均可能发生在用户排布之后。

**Independent Test**: 使用正式图工具更改样例，比较存续节点及组。制造真实写入失败和旧修订请求，比较文件及页面状态。

**Acceptance Scenarios**:

1. **Given** 已保存的排布，**When** 完整图更新关系或增删对象，**Then** 存续坐标原样保留，新增相邻文件按关系补位，孤立新节点安排在空闲位置，确认移除的成员引用消失。
2. **Given** 图暂时缺失、结构不完整或读取失败，**When** 打开或更新画布，**Then** 保留最后有效排布并展示可辨状态。
3. **Given** 磁盘写入失败、布局损坏或旧标签页竞争，**When** 打开或保存，**Then** 保留磁盘原件和本页未保存动作，显示原因及可行的恢复路径。
4. **Given** 已保存的图经正式工具删空，**When** 新会话打开，**Then** 页面完成清理并恢复刷新能力。再次登记后可在同页刷新、摆放并保存（F1）。
5. **Given** 正式移除后重加同路径，**When** 比较中途保存和一直关页两种时序，**Then** 新节点均按同一新节点规则放置，旧成员与空组消失，其余节点与视野保留。跨越删除的旧页面保存不能恢复旧成员。临时缺席恢复后保有原布局（F2）。
6. **Given** 读者已在重加节点上拖动并建立新组，**When** 另一个文件暂时缺席又恢复并选择“刷新图并保留本页布局”，**Then** 保存和重开后保有刚摆的位置和分组。编辑或撤销一条无关依赖说明后，删除前的旧页仍无法写回原排布（F2）。

### User Story 4 - 读懂一个库在本项目里的用途 (Priority: P1)

讲解 AI 按本批教学需要维护库图例。读者选中图例可读库的能力和每个文件的使用理由，也可把它与文件摆在一起，以后接着读。

**Why this priority**: 在图中看到多个文件共用的库，可以结合每个文件理解它解决的具体问题。

**Independent Test**: 在已有组、位置和视野的文件图登记一个标准库图例，连接两个使用文件。选择并阅读，将它与文件编组并拖组保存，再修改介绍、重启、重开核对。

**Acceptance Scenarios**:

1. **Given** 待讲解的库和已登记文件，**When** AI 用工具提交、查询及校验图例，**Then** 一份介绍可关联多个文件，各自保留理由，重放提交不会重复。文件关系和核对状态保持原有语义。
2. **Given** 标准库、第三方库及同显示名的文件，**When** 读者选中对象或切换语言，**Then** 正确显示对象和库类别，介绍及理由保留原文。文件选中仍可进入已有讲解。
3. **Given** 已保存的文件图，**When** AI 增加图例或只更新现有图例正文，**Then** 用户已有对象原位保留。图例可与文件一起拖动、分组、移出、重排并恢复，读者的写入仅涉及布局。
4. **Given** 已保存的混合布局，**When** 图例暂缺或数据损坏，**Then** 提示原因并保留磁盘排布，资料恢复后继续使用。
5. **Given** 图例连向多个文件，**When** 工具正式移除一个使用文件或图例，**Then** 失效关系消失，正式移除的布局成员及空组被清理，存续坐标和视野保留，旧标签页的保存无法恢复已删除成员。

### User Story 5 - 在图上就近编组 (Priority: P1)

读者以画布为首屏，选中所需对象后可以在松手处附近直接将它们编组。

**Why this priority** 阅读者进入图后先观察关系，整理时可在原处完成操作并接着读图。

**Independent Test** 从共用试读资料的「订单处理」组背景内开始框选，将文件与 `node:path` 编组，使用浮钮和快捷键各试一次，移动组、重开并核原有组的变化。

**Acceptance Scenarios**

1. **Given** 正常进入依赖图，**When** 查看初始图、选中一个文件或库、再关闭详情，**Then** 详情按需打开和关闭。缩放仍在小地图工具区，重排、刷新、简短手势提示和分组管理从左浮条找到。
2. **Given** 画布已平移或缩放，**When** 用选择工具从空白处或组框背景左键拖动，**Then** 只选中完全落入框内的文件和库，任一拖动方向命中一致。松手后保留选中反馈，非空选区在指针附近出现可达的「分组」按钮。
3. **Given** 有有效选区，**When** 点击浮钮或按 Ctrl+G，**Then** 在同一处看到所选数量并可输入名称。已有成员会在命名前提示哪些对象将移组。Enter 确认生效，Esc 取消。焦点在输入控件或其他页面时保留该处的快捷键行为。
4. **Given** 空选、取消或切页，**When** 检查布局与快捷键，**Then** 选区没有进入布局保存，浮钮及成组快捷键只在当前依赖图的有效选区中可用。可经左浮条用键盘创建、改名、调整成员或解散已有组。
5. **Given** 分组保存写入失败，**When** 查看原因并恢复写入后重试，**Then** 可看见待保存状态，重试保留刚才的布局操作。冲突和缺图沿现有恢复路径呈现。

### User Story 6 - 在已有排布中追踪关系、定位和成组 (Priority: P1)

读者打开自己排好的订单图，从空白滑到订单服务，看清文件和直接关系，去小地图定位远处的文件，然后选择一批文件成组。

**Why this priority** 文件名、箭头与视野决定能否沿关系继续读讲解。组刚画出来时，读者还需要知道它是否已保存。

**Independent Test** 在同一份 79% 订单图副本分别执行 SC-014、015、016。保留同视野的前后画面及保存反馈的连续帧，按服务响应和重新打开的结果判断何时成组成功。

**Acceptance Scenarios**

1. **Given** 订单处理组已在画面中，**When** 从空白滑到 `service.mjs` 并点选，**Then** 进入节点时点阵平复，文件名及三条直接关系清楚可循。可拖节点、查看原因并从讲解返回原处。
2. **Given** 工具已固定，**When** 按住 Ctrl 反转工具并在拖动途中先松开 Ctrl，**Then** 这一拖完成原先的动作，下一拖恢复固定工具。用小地图定位和缩放后重开，保留读者实际改变的视野。
3. **Given** 刚确认新组，**When** 延迟或拒绝这次保存，随后成功或重试成功，**Then** 等待中和失败时均无涟漪。仍在依赖图且允许动态效果时，成功后新组边缘向外传一圈。

### User Story 7 - 在同一视野内查关系并打开讲解 (Priority: P1)

读者在画布内就近读节点关系和库用法，点连线读原因，点图例读用法。

**Why this priority** 点选对象后继续沿图追读时，原视野和小地图仍可用。

**Independent Test** 在共用试读图选 `api.mjs` 和 `node:path`，点线读理由，核仍能定位、追关系和操作图工具。

**Acceptance Scenarios**

1. **Given** 依赖图已打开，**When** 开合闭环目录、选择文件或连线，**Then** 当前视野与画布边界保持，左下小地图和工具区原位可用。
2. **Given** 选中的文件有直接依赖或库使用，**When** 阅读底部摘要和完整关系，**Then** 可见分类、路径、核对状态与逐条原因。已有讲解可一步打开，相关文件可点选继续追图。
3. **Given** 选中库或窄窗空间有限，**When** 查库类别、介绍和逐文件理由，**Then** 完整文字可读，详情可关闭，并能继续使用工具或处理布局保存失败。

4. **Given** 已有订单图布局，**When** 选闭环并查看文件后从图上方进入该闭环，**Then** 后退一次回到原选择、有效高亮和视野。

5. **Given** A 到 C 经过 B，**When** 点 A、移走指针、点 B、点空白，**Then** 原路径依次在 B 前浮起、保持、换成 B 的直接关系、恢复遮挡。
6. **Given** 已拖组、移动图例并缩放，**When** 取消重排再确认重排，**Then** 取消时保留原图且无布局写入，确认后左起读库与文件，各层居中且组名和成员可恢复。

### Edge Cases

- 缺图、有效空图、损坏图分别显示，空图来自已确认的完整结果。
- 合法文件路径大小写敏感，分组边界只取显式成员。
- 图状态与讲解有无独立。连续完成多个操作后，页面只确认最新已成功落盘的状态。

## Requirements

### Functional Requirements

- **FR-001** 读取项目依赖图，按被依赖方指向使用者展示直接边及原因，支持环和自环（G01）。
- **FR-002** 选中文件后表达讲解、核对及直接关系，按实际讲解入口显式打开，再用站内后退恢复原节点和视野，主要控件提供双语和键盘入口。讲解选择以清单请求发出后的显式打开为准（G01、F4、D026、D028）。回访依 [006 FR-016](../006-file-reader/spec.md#functional-requirements) 使用当前图及布局。
- **FR-003** 拖节点、平移缩放、显式多组命名和成员编辑、拖组、保组重排。激活重排须标明当前图，说明位置替换、视野复位和保组，默认聚焦取消；取消、Esc 或关闭保留选中、视野和坐标且不触发保存，确认后只重排并保存当前图一次。不改变图语义（G02）。
- **FR-004** 自动保存所有合法节点的操作结果，最新操作成功写入后才确认，重启恢复，跨项目独立（G03、F3）。
- **FR-005** 完整图增删协调布局，正式删空也由页面完成协调保存。正式移除后重新登记同路径按新节点放置，存续坐标和成员保留，临时失败保留最后有效排布（G04、F1、F2）。
- **FR-006** 写入限定本项目专用文件，失败保留旧文件及本页操作，过期图或布局写入须拒绝，冲突可见，损坏文件须报告（G05、F2、F3）。
- **FR-007** 工具按当前依赖图查询、幂等增加和更新、移除并校验库图例与使用关系。图例身份独立于文件，使用关系指向已登记文件，文件退出时清理其使用关系（L01、L04）。
- **FR-008** 读者可选择图例，区分标准库和第三方库，获取名称、介绍与逐文件使用理由。界面中英切换保持正文原文。网页和阅读服务中的写入仅限个人排布（L02）。
- **FR-009** 库图例与文件共用全部布局交互及保护，内容更新保留同一实例的位置。旧布局继续可读，暂缺／损坏保留原件，正式移除后的旧标签页写入被拒绝（L03、L04）。
- **FR-010** 首屏主要区域有可访问名称，进入时用共用顶栏指示当前页。依赖图铺满顶栏以下的页面内容区，画布延伸到四边和四角。极短窗口保有操作控件所需的最小画布高度。图操作和详情分别按 FR-019—020 呈现。加载、缺图、未保存、保存失败和冲突的状态及可用的恢复入口就地呈现。
- **FR-011** 默认使用抓手。点工具固定抓手或选择，按住 Ctrl 临时反转，松开、切页或窗口失焦时恢复固定工具。工具按钮与光标表示当前有效工具。左键在空白处或组框背景开始拖动时确定这次动作，直到松手完成。抓手平移，选择工具框住完全落入范围的文件和库节点，两个方向及不同视野下均按相同规则命中，组框与边不参与命中。点节点看详情、拖节点及拖组名移动显式成员的入口独立于工具。组名输入时沿用文本编辑行为。
- **FR-012** 有选区时在松手位置旁显示单个「分组」浮钮，按讲解页选文浮条的样式、窗口边缘避让与键盘可达方式呈现。浮钮和当前图的 Ctrl+G 打开同一就近命名入口，显示选中数量并提前提示将从其他组移出的对象。Enter 确认，Esc 放弃。每对象归属一组，转移后清理空组。成组快捷键须有有效选区且焦点适用。
- **FR-013** 框选和命名草稿属于当前画布交互。空选不显示浮钮，单独框选、取消、切页均不写入布局。左浮条的分组管理提供无需组合键或拖框的创建、改名、增减成员及解散操作。组框上的组名用来拖动，旁边的「⋯」与闭环图共用同款菜单，可改名、调整成员或解散。选择「解散分组」直接移除该组，文件和库图例保留在原位。
- **FR-014** 文件卡横向、近白底、细描边，直边到拐角的弯曲逐渐加深。卡面、描边、选中和键盘焦点沿同一连续圆角，连线依据来向分布在卡边，框选反馈可辨。首行突出含扩展名的文件名，次行显示目录。已核对显示轻量小勾并提供可访问文字，未核对明示「依赖待核对」。库卡以淡紫色、包图标和实际类别识别。详情与可访问名称提供完整身份，能分清长路径与同名文件。
- **FR-015** 文件依赖用实线，库使用关系用虚线，箭头从被使用方指向使用方并落在目标卡边缘。选中节点后直接关系在前景突出，其他文件名保持可读。同排畅通可直连，错层平滑过渡，经过第三张卡时由卡面遮住，点选任一真实端点后沿原线浮至卡面上方，直到改选或点空白。前景线允许点击和拖动其下方的卡，空白处的线段仍可查原因。同侧多线按来向错开，近邻可短接；拖动时走线随卡片更新，反向边、自环及关系原因可辨。
- **FR-016** 浅绿灰底的低对比细点随主图平移缩放，缩远渐淡。空白处光标附近的点略深、略大，外围轻微外推。初调半径约 70 屏幕 CSS px，最大位移约 2 屏幕 CSS px，以 79% 视野实图校准手感。停稳后局部静止，移开后轻柔回弹一次。进入节点、拖图、拖节点或框选时收住。组内外共享格点原点、间距和相位，组内略暖略深，拖组仅移动着色范围和显式成员。
- **FR-017** 左下角小地图显示全图与当前视野框，下方保留抓手、选择和缩放按钮。点小地图定位，拖视野框平移，主图平移缩放反向同步。适配小地图自身边界时保留主图既有排布和视野。窄窗可收起小地图，工具及缩放仍可操作，工具支持键盘和中英文。
- **FR-018** 通过就近浮钮、Ctrl+G 或分组管理确认新组后，只有包含本次新组的布局实际保存成功且仍停留在图页时，才在该组边缘附近亮点、短距离向外传播一圈并恢复。等待中显示待保存，失败显示原因并可重试，同次操作重试成功只播一圈。切页后到达的成功确认、回到图页、重开图、普通点击、平移或改名均无涟漪。系统偏好减少动态效果时保留静态点阵、组内色差、选择轮廓与可读保存反馈，停用鼓胀、回弹及涟漪。悬停、工具与选区均属临时状态。
- **FR-019** 依赖图的重新布局、分组管理、刷新图和布局及简短说明集中在画布左缘的浅色主题窄竖浮条。浮条在画布顶边与左下小地图及工具区的上边缘之间垂直居中。小地图收起后按下方工具区居中。浮条常驻。顶栏开关控制默认收起的闭环目录。默认只显示图标按钮。悬停浮条或键盘聚焦工具时，对应名称以较浅的辅助文字色、常规字重在图标右侧滑入并淡入，离开时淡出。指针可移到名称上持续查看，停留时按 Esc 可收起名称。窄且短的窗口只露出当前操作的名称，给摘要和小地图留位。系统偏好减少动态效果时直接显隐。触屏保有合适的点击区域，原有就近分组、键盘入口及保存反馈继续可用，FR-017 的工具位置及行为保留。
- **FR-020** 选中文件、线或库时在底部中央显示随内容收宽并设上限的摘要。桌面收起态为紧凑的横向单行，两端采用与左浮条同类的圆头轮廓。低透明度填充、轻微模糊、略增饱和度的背景配合细高光、浅描边与柔和阴影形成磨砂玻璃表面。摘要内使用无边框按钮，关闭图标缩小并保留点击区域。展开面板和相关按钮在平台支持时使用连续圆角。直接控件的字号和间距协调，焦点、悬停、按下、选中及禁用状态可辨，抓手与选择工具的当前项有压下的层次感。窄窗随空间调整，入口可达。空关系类别省略。文件摘要显示直接依赖和库用法，并提供已有讲解的一步入口。点或键盘激活任一依赖线或库使用线，直接显示完整两端和原因。点库直接读介绍及所有使用路径、理由。库详情按 FR-008。依赖图以浮层呈现详情与分组编辑，右栏用于闭环。窄窗可用单一可关闭面板，底部工具仍可抵达。面板显隐不改变画布尺寸、视野或个人布局。

- **FR-021** 从闭环目录选择后收栏，按已保存步骤的完整项目路径去重，仅当闭环与当前依赖图的固定提交相同、仓库内项目前缀一致且所有路径均存在时标出全部参与文件。换选、读取失败、版本或路径不符时撤掉旧标记，指出原因。
- **FR-022** 已选闭环名、「阅读此闭环」和「清除高亮」位于整幅画布正上方居中。点文件或空白保留路线。阅读按 ID 直接打开，后退一次按当前资料恢复路线、选择与视野。开合、选择和清除只影响页面。

- **FR-023** 无个人布局及主动重排时，按直接引用从被依赖文件到使用文件向右分层。可见库独占最左层，无库时从文件层开始。各层围绕同一水平中线，密集层可分多列；层间净空大于层内列间净空。多根、孤点及循环可读。旧坐标、组和视野优先恢复，新增对象按相邻关系补位并避让旧位置。

- **FR-024** 两图默认弱化流程线与库虚线，保留缩小时的路径痕迹。悬停、键盘聚焦或触屏点选卡片突出该卡的直接入边、出边及箭头；其他关系继续淡显。此反馈不改坐标、布局修订或导航。

- **FR-025** 拖卡或拖组名时，以整个可见外框与邻近卡、组框的边缘和中心对齐，显示临时细虚线并轻吸附。缩放按屏幕距离判断，继续拖可脱离。拖组排除自身和随行成员，显式成员等量移动。单卡排除所属组框。结束或中断收线，个人布局只保存实际摆放。

### Key Entities

- **文件依赖图**：文件路径、核对状态、直接依赖及原因。
- **画布布局**：稳定对象标识的坐标、组名与成员、平移与缩放。
- **保存修订**：对应当前已落盘布局的一次保存身份。
- **库图例**：归当前图的可摆放实例，包含名称、类别、介绍和逐使用文件的理由。

## Success Criteria

### Measurable Outcomes

- **SC-001** 样例两条边的方向、原因及两类讲解入口均可从页面核对。
- **SC-002** 缩放后拖组，全部成员按同一画布位移移动，其他节点位移为零。
- **SC-003** 一次完整重启后恢复所有已保存位置、组和视野。样例图、源码、讲解在布局操作前后逐项一致。
- **SC-004** 图编辑后所有存续节点保持原位，移除引用以及空组都已清除。失败与过期保存试验中旧布局保持原件。
- **SC-005** 正式删空后由页面完成坐标及组清理，同页刷新可恢复整理。正式重加同路径的两种时序得到相同布局（F1、F2）。
- **SC-006** 特殊文件名与相邻文件均可经页面保存并在新会话恢复。暂扣旧清单再从图选篇时，清单返回后标题、正文和返回视野符合最新操作（F3、F4）。
- **SC-007** 样例在两种界面语言中显示同一标准库的两条不同使用理由及原文，第三方库类别独立可见。重复提交仍只有一个实例及两条关系（L01、L02）。
- **SC-008** 混合编组拖动后布局落盘，修改介绍并关闭页面和服务，重开仍看到更新后的介绍和先前的组、位置和视野。摆放与拒绝的越权写入前后，内容文件逐字节相同（L02、L03）。
- **SC-009** 暂缺或损坏保留原布局，恢复后原位可读。正式移除清除关联和空组，旧页保存被拒绝。发布中途失败后原内容和凭据仍可继续正常重试（L04）。
- **SC-010** 共用试读从讲解进入图，点选 `src/api.mjs` 后点直接依赖线可读「调用 createOrder 处理订单。」等直接关系，通过 `src/service.mjs` 打开讲解再后退，核同一节点、同一视野。缩放、重排及详情入口按 FR-017、019—020 可达。
- **SC-011** 从「订单处理」组框背景开始，在两种缩放下测试正向及反向框选。仅完全被包围的文件及库有选中反馈，窗口边缘的浮钮可达。分别从浮钮和 Ctrl+G 确认命名；重开后核组名、成员、组拖动结果和视野，框内非成员坐标一致。
- **SC-012** 对已有组员分别取消和确认命名，核提示对象、归属、空组清理与保存结果。空选、Esc、仅框选及切页均无布局写入。输入组名或进入讲解、闭环时 Ctrl+G 不触发依赖图命名。左浮条的分组入口可仅用键盘操作。从组名旁的菜单解散一组后重开图，仅该组框消失，节点位置、其余分组和视野与操作前一致。
- **SC-013** 隔离副本触发保存失败时可见原因，恢复后可重试并重开得到待存布局。使用同项目闭环实点步骤并核各图保存结果独立。
- **SC-014** 在 79% 订单图，从空白滑向并选中 `service.mjs`。比较停留、移开及进入节点后的点阵，沿 `rules.mjs`、`audit.mjs` 两条入边及通向 `api.mjs` 的出边逐一追到端口。核库虚线、待核对文字、键盘焦点、完整路径和拖动端点，读讲解再返回。拖「订单处理」时检查组边界内外格点持续对齐。
- **SC-015** 分别固定抓手和选择，在组内外测试反转和提前放开 Ctrl。核失焦恢复、反向框选、贴边浮钮和 Ctrl+G。通过小地图点击、拖框和主图缩放核双向同步，收起和重开后核最后视野及节点坐标。在窄窗实点工具、缩放，再切到闭环选步骤并核其独立视野。
- **SC-016** 在副本经三个入口新建组。暂扣保存响应时可见等待且涟漪为零，释放成功后正确组边缘出现一圈。另触发失败，核原因及零次涟漪，重试成功后一次。未回时切页再返回、普通平移保存和旧组改名均为零次。减少动态效果下成功和失败皆为静态且可区分，重开后组名和成员与成功保存的结果一致。
- **SC-017** 以 [006 SC-013 的中文桌面视口和输入](../006-file-reader/spec.md#measurable-outcomes) 对照 D027，从讲解切入依赖图，开合目录、分别选择 `src/api.mjs` 和 `node:path`，点边查原因。画布从顶栏底边铺至内容区左右及底边，四角见画布。选中及点边查原因前后，画布边界、小地图工具区底边位移均为 0 CSS px，节点坐标和视野一致。小地图展开、收起两态，浮条中点都与画布顶边和左下工具区顶边的中点对齐。目录开合时浮条保留。默认只见图标，鼠标移入或键盘聚焦时较浅的常规字重名称渐显。指针能移到名称上，停留时按 Esc 可消去。底部横向摘要两端圆润，在点阵和节点上能看到适度透光、模糊和边缘高光，文字清楚。按钮无描边，关闭叉较小且保留原点击区域，键盘焦点与当前工具可辨。文件可一步读讲解或沿图上的连线「依赖 service.mjs」「使用 node:path」查完整路径和逐条原因，库详情可查介绍和逐文件理由。实点浮条的分组、刷新、重排与说明。
- **SC-018** 以 [006 SC-011 的窄窗](../006-file-reader/spec.md#measurable-outcomes) 和 [试读细化的短窗](plan.md#d028-试读细化) 核画布贴边，查摘要换行、入口可达及长详情能滚至末尾。短窗切换小地图时浮条随可用高度居中，当前工具名称为摘要留出间距，缩放及成组入口仍可用。用粗指针模式核直接控件的触控范围。启用减少动态效果后，浮条与名称直接显隐，可继续用触控和键盘操作。复验 Ctrl 反转、命中、键盘焦点及分组保存失败后的就地重试。读讲解的完整往返见 [006 SC-014](../006-file-reader/spec.md#measurable-outcomes)，闭环右栏与独立视野见 [009 SC-005](../009-loop-reader/spec.md#measurable-outcomes)。

- **SC-019** 从已排好的订单图选五步闭环，只有 service 和 rules 两卡点亮。换路径工具闭环后标记完整替换，旧提交、缺路径、迟到响应均不产生错标。桌面与 390 CSS px 从中央读图、后退及清除，画布视野一致、布局写入为零。

- **SC-020** 在同一实际文件图对比首开、拖动分组后重开、增点和重排。跨循环组件的引用向右、同层不重叠，选闭环高亮前后坐标一致。

- **SC-021** 从密集目标沿不同落点反查来源，核同一路径被第三张卡遮住，点选端点再移开指针仍能追踪，改选中间卡或点空白后解除。单卡与整组分别对齐卡或组，换倍率验证轻吸附、拖离、收线与重开。
