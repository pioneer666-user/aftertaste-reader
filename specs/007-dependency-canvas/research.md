# D012 Research

- **Decision** 采用 D004 的 Vue Flow 1.48.2、显式成员、由坐标和节点实际尺寸求组框。**Rationale** 实验已真实验证缩放下拖动、组和读写恢复。**Alternatives considered** 自研画布需另实现指针和缩放，嵌套父子节点会将层级与布局绑定。
- **Decision** 沿用 D009 图格式，通过 `apply-graph` 的显式移除凭据确认清理。**Rationale** 结构合法的手改中间稿也可能暂时缺少节点。依据正式工具的移除意图和快照匹配，可以保护用户排布。**Alternatives considered** 仅用完整 JSON 结构、工作区源码存在性或时间间隔猜删除均无法区分意图。
- **Decision** 布局单文件、同服务串行修订比较、图快照比较、同目录原子发布。**Rationale** 两个标签页不能覆盖已确认的新布局，失败后仍可重试原请求。**Alternatives considered** 浏览器站点存储会随访问入口或上下文变化，盲写文件会接受旧标签页。
- **Decision** 主动重排时按组和独立节点确定性网格摆放，回到初始视野。**Rationale** 保留 D004 简单保组约定，环和自环无需特殊排序。**Alternatives considered** 拓扑排序对有环图还需额外约定，自动重排会打扰已有排布。

## D013 增量

- **Decision** 沿用快照凭据，每路径保留最近一次确认移除标记，并在布局记录已接受标记。**Rationale** 同路径重加可得到字节相同的图，布局与旧页面都需要识别已发生的正式移除。**Alternatives considered** 只看当前节点名单无法识别两次发布。图工具直接改布局会越过现有布局写入者。
- **Decision** 布局 PUT 以条目数组发送坐标。**Rationale** 任意合法路径可作为 JSON 值穿过现有解析保护，沿用严格布局校验与磁盘坐标表。**Alternatives considered** 更改通用 JSON 解析策略会扩大影响。

## D014 增量

- **Decision** 用原图文件的可选 `legends` 保存介绍和关联。**Rationale** 图例及使用文件由同一内容发布验证和落盘，旧资料无需迁移，图例可经独立查询按需读取。**Alternatives considered** 单设正文文件会新增内容与引用的发布协调。
- **Decision** 文件路径及带前缀的图例键共用原布局及移除凭据。**Rationale** 两类对象可以同名并混合分组。工具仍只发布图与移除事实，页面沿用布局接口完成持久协调。**Alternatives considered** 分开存位置或让内容工具直接改布局会额外处理混合分组及用户写入冲突。

## D026 增量

- **Decision** 沿用 Vue Flow 的渲染位置及原平移、拖动机制，在依赖图捕获 Ctrl 左键框选，按画布内实际渲染的文件及库节点边界作完整包围判断。**Rationale** 屏幕坐标与可见节点可直接对照，自动涵盖平移、缩放和反向拖动。基线节点尺寸及拖组用法见 D012、D014；手势由 [D026 批准依据](../../docs/work/2026/11/D026-dependency-canvas-selection/task.md) 选定。**Alternatives considered** 共用组件全局开启选区会同时引入闭环交互；沿节点初始坐标猜尺寸会与可见矩形偏离。
- **Decision** 框选和命名草稿留在页面内，浮层借鉴 D023 选文定位和边缘避让，确认走已有布局提交和 `updateGroup`。**Rationale** 仅已确认的改动可以触发保存，已有唯一成员和空组清理规则可复用，失败草稿仍进入现行重试链。**Alternatives considered** 独立持久化选择或新增分组接口会拆分写入冲突保护。

## D027 增量

- **Decision** 保留现有 Vue Flow 的节点、端口、曲线及视野接口，连续圆角、格点和小地图在文件依赖图内绘制。**Rationale** `DependencyEdge.vue` 已从端口取坐标并处理自环，D026 已验证拖动、缩放和实际尺寸。小地图可把同一坐标换算为缩略视图，组着色也能复用现有组框边界。**Alternatives considered** 改主图为自动适配会覆盖读者原视野；给每个组另铺点阵会在边界处错位。
- **Decision** 沿用带修订的布局保存链，在本页记录尚待成功确认的新组。**Rationale** 创建、普通编辑和重新打开都可能显示同一个组。只有本次创建意图与服务确认的那一份布局相符，才能判断何时播放。现有 HTTP 契约已返回确切修订，同一请求可重试。**Alternatives considered** 在组出现、确认命名或任意成功提示时播放，分别会把旧组、失败或无关保存误报为这次新建成功。

## D028 画布浮层

- **选择** 依赖图的操作及详情作为画布内的视觉层，复用现有节点、组表单和详情数据。**依据** D027 的坐标变换和小地图双向定位已经验证，派单同时记录详情出现后工具区上移的实际差值。浮层按画布定位可复用同一要求。**比较** 挤占画布的横条或侧栏会改变相同世界坐标映射后的可见区域。
- **选择** 回访只带选中对象、查看状态及视野。**依据** [既有布局恢复](../../docs/work/2026/11/D027-dependency-canvas-polish/handoff.md) 已验证项目保存修订和重开。回访时正常读当前图，有本页待存内容时尊重既有保存或冲突流程。**比较** 把旧排布塞进访问历史会让回访覆盖读者此后摆放的位置。
- **选择** 闭环保有自己的阅读模式及图实例。**依据** [D016](../../docs/work/2026/11/D016-loop-reader/handoff.md) 的步骤、分支、源码及独立布局已可使用。**比较** 统一改为依赖图的摘要会压缩连续教学内容。
