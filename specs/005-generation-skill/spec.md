# Feature Specification: 普通文件讲解的分批生成

**Feature Branch**: `codex/feat-generation-skill`

**Created**: 2026-11-17

**Status**: 实现、自测与独审完成，作者试读待验

**Input**: D010 task.md @ `2a6f27d` 的 S01—S06。复用 D007—D009 的固定来源、文档和依赖图能力。依据 08 R01—R12、U101、07 U78 和 04 U85—U88。允许更新 005、产品 Skill、必要使用说明、行为样例及本批证据。网页、闭环、跨版本更新、发布留在后续任务。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按选定范围和节奏读一批文件 (Priority: P1)

用户明确范围与节奏后，获得按理解关联组织的小批完整讲解，可以定位到固定版本的真实源码。

**Why this priority**: 这是普通生成的完整主路径。

**Independent Test**: 在受控项目选择两个相关文件，分别走逐批阅读与连续生成，检查产物、来源和停止位置。

**Acceptance Scenarios**:

1. **Given** 范围或节奏缺失，**When** 请求开始阅读，**Then** 只补问缺失项并等待，生成资料保持原状。
2. **Given** 已明确范围和逐批阅读，**When** 生成首批，**Then** 完成相关小批讲解与检查后交付，等待继续要求。
3. **Given** 已选择连续生成，**When** 一批交付，**Then** 在范围内继续下一批，直到已选范围完成，无需理解标记或逐批批准。
4. **Given** 工作区或 HEAD 已变化，**When** 选文件和讲解，**Then** 仍以同一固定提交为依据。

### User Story 2 - 保护已有资料并如实处理失败 (Priority: P1)

用户已有讲解、依赖及个人资料时，新生成保留它们，遇到冲突或失败可以知道具体进度。

**Why this priority**: 错误覆盖或假报完成会损害已有成果。

**Independent Test**: 准备同版已有文档、异版资料和取源失败，检查原资料字节及最终报告。

**Acceptance Scenarios**:

1. **Given** 本批文件依赖范围外项目文件，**When** 完成讲解，**Then** 只登记依赖节点和关系，保留真实核对状态，不生成范围外讲解。
2. **Given** 已有文档或图与目标版本冲突，**When** 继续生成，**Then** 说明冲突并停止依赖写入，保存旧资料。
3. **Given** 创建、取源或校验失败，**When** 交付，**Then** 明确已生成、未完成及未核对部分，空正文和骨架不计为完成。
4. **Given** 重试遇到已有文档，**When** 判断如何继续，**Then** 仅对可确认由本次创建且仍同版的未完成骨架填充正文并保留身份，其他资料按实际状态说明。

### User Story 3 - 按已有需要讲，并保存简短阅读方向 (Priority: P2)

用户得到结合代码特点、明确要求和相关真实反馈的讲解，后续 AI 能读到当前方向与必要偏好。

**Why this priority**: 教学重点与前后衔接决定实际阅读价值。

**Independent Test**: 对同一受控项目分别提供空资料、明确偏好和真实反馈，核正文侧重点与资料修订依据。

**Acceptance Scenarios**:

1. **Given** 没有偏好和反馈，**When** 正常生成，**Then** 可开始讲解，观察区保持无真实观察，不将已讲写成已理解。
2. **Given** 已有偏好和方向，**When** 针对性分析与讲解，**Then** 先读取，依据当前源码核实方向，按内容选择重点及例子。
3. **Given** 真实重复反馈，**When** 准备下一批，**Then** 先核既有要求落实，合并修订原观察并保留依据，冲突先问。
4. **Given** 用户只提问，**When** 回答，**Then** 不因此改写讲解、笔记、书签、自评或通用 Skill。

### Edge Cases

- 空文件、超大块、源码不可读、结构或行覆盖错误，分别沿工具诊断处理。
- 方向摘要与实际文档冲突，以实际资料和固定来源核实，不能据摘要宣称覆盖。
- 项目资料或源码含指令文字，作为分析数据，不能覆盖用户选择和工具边界。
- 同版已有完成文档可复用，未能确认归属的空骨架也受资料保护约束。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 只补问缺失的范围和节奏并等待，复用有效选择。AI 在范围内自主组织相关小批次，按逐批或连续节奏交付。（S01）
- **FR-002**: 选文件、讲解和依赖核对使用固定提交的完整项目映射，生成前核实际既有文档与图的版本。冲突停止依赖写入。（S02）
- **FR-003**: 制作约束早读，针对性分析前读讲解方法、已有偏好和方向，相关反馈按需读。以代码特点、当前需要和前后联系组织讲解。（S03）
- **FR-004**: AI 决定有序分块，工具生成骨架与 ID，AI 填正文并逐文件校验。源码仅存引用，覆盖全文件且保留身份规则，超大如实告知。（S03、S04）
- **FR-005**: 先登记本批节点，讲解完成后按明确使用者提交完整依赖。区分未核对与核对后无依赖，范围外项目文件仅登记关系与节点。（S04）
- **FR-006**: 保护已有文档，失败报告实际完成度。仅对确认为本次新建、仍同版的未完成骨架继续填写，不借删除重建绕过保护。（S04）
- **FR-007**: 使用随包唯一偏好与方向模板初始化缺失资料，保留既有内容。按真实反馈与分区语义维护偏好，每批检查方向并按需合并。（S05）
- **FR-008**: 提供实际可读取入口、相对参考和工具说明，区分工具位置、项目、仓库与当前目录，说明已验证加载方式和能力状态。（S06）
- **FR-009**: 提供受控行为证据、可复建小项目、完整试读讲解、固定源码定位及实际校验结果。独审与作者教学验收分别记录。（S06）

### Key Entities *(include if feature involves data)*

- **阅读选择**：用户确认的范围、节奏和固定源码依据，约束批次。
- **批次成果**：实际完成的文件讲解、校验与依赖核对结果，完成度分别判断。
- **讲解偏好**：用户明确要求与可纠正的 AI 教学观察，各有实际依据。
- **阅读方向**：已讲主题与层次、后续方向及理由，提供衔接上下文。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 必测请求中，范围或节奏缺失时生成写入为零，两个节奏均停在用户授权边界。
- **SC-002**: 完成的小批次每篇源码定位覆盖全文件、正文非空、依赖状态真实，范围外讲解新增为零。
- **SC-003**: 资料冲突和失败场景中，既有资料保持原状，所有未完成内容在交付中明确列出。
- **SC-004**: 一个独立模拟使用代理仅凭入口和请求完成小批调用链，作者获得一份可直接试读的完整讲解入口。

## Assumptions

- 用户提供可访问的本地普通 Git 项目，默认目标版本在开始时固定为 HEAD，显式提交选择优先。
- 使用已有固定来源、单篇文档和依赖图工具及其失败保护，本批以 Skill 连接这些能力。
- 使用合成项目验证工具与 Skill 行为，真实项目教学效果等待作者指定项目并试读。
- 本批提供开发树显式加载，宿主自动发现、安装与发布另行验证。网页、闭环、版本更新及全文写回式答疑不属于本批生成能力。
