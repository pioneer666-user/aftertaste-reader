## User Scenarios & Testing *(mandatory)*

### User Story 1 - 固定并持续读取同一版本 (Priority: P1)

调用 AI 指定目标项目并固定一个本地提交，随后多次读取指定源码，供后续讲解使用。

**Why this priority** | 为每次读取提供一致、可复查的依据。

**Independent Test** | 合成仓库固定 A，工作区修改、提交 B、删除文件后，读取两个文件仍得到 A 的原文。

**Acceptance Scenarios**

1. **Given** 已有提交 A，**When** 省略目标版本进行固定，**Then** 返回当时 HEAD 的完整提交标识，再读文件始终使用该标识。
2. **Given** 本地有历史和分叉提交，**When** 显式固定其中任一个，**Then** 可读取该提交的文件。
3. **Given** 空文件、Unicode、不同换行、BOM 和无末尾换行文件，**When** 读取，**Then** 原文完整保留。
4. **Given** 名称形似完整提交的分支先后指向 A、B，**When** 用该名称直接读取，**Then** 两次均拒绝其冒充固定身份，固定阶段仍可将该分支解析成真实完整提交。
5. **Given** 已固定仓库内子项目 A 且原仓库对象可用，**When** 当前整个子项目目录消失后复用原固定引用，**Then** 共用用例与真实命令仍读取 A 的文件。

### User Story 2 - 明确项目范围并可靠诊断 (Priority: P1)

调用 AI 从任意进程目录指定仓库根或子项目，按项目相对路径读取，并能定位失败原因。

**Why this priority** | 错误项目、错误文件或静默替代会破坏版本依据。

**Independent Test** | 对同一个子项目从不同 cwd 运行真实命令，特殊路径按字面匹配，越界及不支持形态返回明确问题。

**Acceptance Scenarios**

1. **Given** 仓库内子项目，**When** 从不同 cwd 读取含中文、空格或 Git 特殊字符的文件，**Then** 返回相同文件及项目到仓库的路径依据。
2. **Given** 非仓库、无提交、无效版本、缺失对象或文件，**When** 调用，**Then** 给出可区分问题、必要定位和下一步。
3. **Given** 越界路径、选项注入、符号链接、子模块、目录、二进制或不支持编码，**When** 调用，**Then** 拒绝并说明类别，失败输出无源码正文。
4. **Given** 成功或失败调用，**When** 比较目标文件和 Git 状态，**Then** 目标保持原状，无工具保存的源码副本。
5. **Given** 独立于任何普通工作仓库的 bare 或普通非仓库目录，**When** 固定，**Then** 分别返回不支持目标与非仓库的稳定诊断。
6. **Given** 固定引用的根与前缀不一致或含越界、元数据路径，**When** 读取，**Then** 拒绝该映射，不能借历史读取绕过项目边界。

### Edge Cases

- 提交中的文件在当前工作区已修改、删除或替换为链接，仍从提交读取普通文件。
- 子项目在目标提交不存在、路径中途为链接或子模块，按相应定位和类型失败处理。
- Git 不可用、对象不可读、部分克隆缺对象、替换引用或进程环境干扰，均保持本地确定对象依据。
- 调用者伪造固定引用、给空值或错误类型，入口执行运行时校验。
- 历史读取只依赖原仓库与提交树，不要求现存子目录，也不跟随当前工作区中的链接。原仓库缺失或对象不可读仍准确失败。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001** 系统必须明确目标项目根、Git 根及项目相对仓库路径，输入不依赖调用进程 cwd，文件只在该项目范围解释。
- **FR-002** 系统必须提供独立固定阶段，默认当时 HEAD，也支持本地已有提交，返回完整标识，允许历史和分叉提交。
- **FR-003** 后续读取必须核实固定的完整提交身份，拒绝可移动引用冒充完整 ID，后续对象读取始终沿核定依据。返回原文及版本和路径依据，工作区变化与 HEAD 移动不影响结果。
- **FR-004** 系统必须保留空文件、Unicode、换行和末尾状态，明确拒绝不支持的文件类型与编码。
- **FR-005** 系统必须区分定位、版本、对象、文件及 Git 执行失败，中文说明、稳定问题标识和退出状态分明，失败无源码正文。
- **FR-006** 系统必须对目标只读，避免 shell 参数拼接、越界、跟随链接或子模块、自动下载和源码持久副本。
- **FR-007** 系统必须提供真实命令及共用用例，并验证二者成功和失败行为一致。
- **FR-008** 原仓库和对象可用时，必须允许复用固定映射读取当前已消失的子项目。首次固定仍要求现存项目，读取须核对字段、仓库根与项目前缀关系，并拒绝越界、元数据、提交树链接及 gitlink。
- **FR-009** 目标解析和固定引用校验必须由共用用例负责，同次读取不重复定位项目，保留必要仓库和对象检查。

### Key Entities *(include if feature involves data)*

- 目标项目映射，包含项目根、仓库根和两者相对路径。
- 固定引用，包含映射及完整提交标识，可供多次调用复用。
- 读取结果，包含固定引用、项目相对路径、仓库相对路径、内容对象标识与整文件文本。
- 诊断，包含稳定问题标识、中文说明、必要定位和下一步。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001** 固定 A 后跨越工作区修改、B 提交和删除操作，两个文件均返回 A 的原文和同一完整依据。
- **SC-002** 仓库根与子项目在两个不同调用目录得到一致定位，所有越界和注入样例均拒绝。
- **SC-003** 已声明支持的文本样例逐字节还原一致，失败场景均有对应问题标识，成功和失败输出互不混淆。
- **SC-004** 成功和失败前后目标文件及 Git 状态一致，真实命令与共用用例均经隔离样例验证。
- **SC-005** 形似完整 ID 的移动分支在 A、B 两个位置均被拒绝，有效的两种完整提交身份仍可读取。
- **SC-006** 删除当前整个子项目后，共用用例与两个不同调用目录的真实命令均能复用原引用读取 A，映射篡改样例均拒绝，独立 bare 与非仓库诊断可区分。

## Assumptions

- 本批只交付整文件取源，教学、文档生成、范围校验、页面和服务沿 D006 后续安排。
- 依赖本地可读的 Git 对象和既定 Node/Git 环境，对暂不支持的目标形态准确诊断。
- 具体命令、字段与支持编码由本批 plan/contracts 定稿，属于已授权技术细化。
