# Phase 0 Research: 项目笔记

## 磁盘与两页并发

- **Decision** 使用带格式版本的项目 JSON，同一服务逐条比较修订，安全替换复用 D019 的同目录临时文件、同步、原件比较与更名。
- **Rationale** 两页改不同笔记可合并，陈旧编辑或删除得到明确冲突。相同提交重试可识别。保存失败保留旧文件。
- **Alternatives considered** 整表提交会覆盖其他笔记。每篇一个文件增加枚举、文件命名和目录管理。多进程同步超出本地服务的保证。

## 正文与撤销

- **Decision** 原生文本编辑框撰写 Markdown，预览提供可点击正文。保持当前编辑器节点，输入和确认分开。每条笔记只发一个未完成请求。
- **Rationale** 浏览器原生撤销可跨过保存。状态只反映已确认的草稿，较早响应不覆盖新输入。失败可重试相同快照，后续输入排队。
- **Alternatives considered** 富文本编辑框需要处理光标、原生撤销、粘贴和 HTML 结构。保存时从服务重写文本框会丢失撤销记录。

## 当前块链接

- **Decision** 用 Markdown 链接文字保存选文，目标为带标记的项目内片段，形如 `#aftertaste-block/<文档路径编码>/<块ID>`。预览区区分链接并接管点击。要求选区两端都在同一讲解正文容器内。
- **Rationale** 保留路径和 ID，可回到现有阅读器，无需外部协议或字符定位。标点、空白和换行通过实体转义。
- **Alternatives considered** 自动创建书签会产生另一份无关记录。源码行、讲解字符下标和历史快照不是当前块的稳定依据。

依据现有文件存储、Markdown 渲染与文档加载实现，并由独立于实现的规划研究子代理核对原生编辑、编码和 Windows 文件锁方案。

## D035 阅读与编辑

沿用上面的原生编辑与 Markdown 渲染。筛选和选择只改变本页状态，写入仍只由编辑动作触发。窄窗切预览时用 CSS 保留输入框，实现在同一次编辑中继续输入与撤销。回读长文时将引用相对滚动区的偏移和链接目标保存在站内历史，兼顾原句位置与键盘续读。

## D036 · 两种起笔共用草稿

[D035 的试读与写失败验证](../../docs/work/2026/11/D035-personal-record-workbench/handoff.md)覆盖逐条草稿和重试。入口传入空正文或已有块链接即可沿用这条保存路径，共用加载中的 Promise 后再建稿，避免两处入口各自管理加载与保存。

## D037 · 随手记与阅读现场

沿用 D020/D036 已实测的按 ID 保存、冲突及丢响应重放。Vue 的 textarea v-model 在组合提交后更新，保留编辑节点可延续原生撤销。
