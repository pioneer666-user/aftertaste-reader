# 02 · 资料目录与文件映射

状态：讨论草稿。依据：[作者 U4、U6—U8、U14、U19—U20、U22、U34](../../../tasks/AR1-回甘首版需求设计/amendments.md)。返回[总入口](spec.md)。

## 已确认要求

- **FR-008**：生成的 Markdown 放在用户指定项目的 docs/aftertaste 下。（U4）
- **FR-009**：文件讲解根据用户指定项目的真实文件名命名。（U4）
- **FR-013**：从用户项目派生的讲解 Markdown、依赖图属于可重建资料；不能由用户项目重建的阅读器程序、渲染资源等必须保留。该分类不授予自动删除权。（U6）
- **FR-014**：用户手改讲解后展示修改后的内容，由用户承担其内容责任；不自动以重新生成的文本替代手改内容。后续主动更新的覆盖或合并策略仍待定。（U6）
- **LIMIT-001**：讲解内容依赖 AI，可能存在解释错误，这是项目接受的能力边界。脚本校验仅针对结构、源码定位及约定的覆盖范围；校验通过不代表解释正确，不据此追加未获批的语义审查系统。（U7）
- **FR-015**：当前文件讲解在 docs/aftertaste/current 下镜像源码目录，保留源码完整文件名后再加 .md；例如 backend/app/auth.py 对应 docs/aftertaste/current/backend/app/auth.py.md。U34 在 U8 的路径约定上增加 current 层，文件命名不变。（U8、U34）
- **FR-016**：展示时发现文档不适配或阅读器专用解析失败，页面明确报错，提供让用户交给 AI 的修复提示词，同时按普通 Markdown 样式展示已有文档。不能依赖 AI 主动运行校验脚本才发现问题；由用户决定何时修复，不自动恢复或引入整套更新事务。（U8）
- **FR-031**：文件讲解 Markdown 保存源码定位与讲解，不要求讲解 AI 抄写用于左侧展示的源码；对应源码由程序从本套资料绑定的确定 Git 提交中提取。网页完整展示源码的要求不变。（U20）
- **P-001**：尽量缩小讲解 AI 的职责，将可按确定规则执行的机械工作交给程序，避免让 AI 重复完成易抄错、算错的步骤；AI 负责理解、划分讲解任务及撰写解释。程序的结构校验不能替代 AI 的内容判断，也不保证解释正确。（U20，沿用 U7、U17）
- **FR-034**：按讲解文档的镜像目录与文件名推导源码路径，不在每篇文档头重复维护源码路径字段。文档头保存 Git 提交依据，见 01 的 FR-035。（U22）

FR-008、009、015 规定产品运行后的讲解产物位置和命名。本项目用于开发讨论的 specs/ 不是这些产物，不混为同一目录。

U95 闭环目录落实：按 U94 的具体存储设计授权，独立闭环成果存于 `docs/aftertaste/loops/`，与当前文件讲解的 `current/` 及文档更新记录的 `history/` 同级；不因清理某条文档更新记录而删除旧闭环。此处只确定目录根及归属，子目录与协议随闭环更新流程制定，详见 [04 U95](04-reading-modes.md#u95--旧闭环独立阅读与当前依赖图适配)。

U97 已确认进一步结构：`loops/<闭环ID>/current/` 保存各闭环当前维护的完整成果，`loops/<闭环ID>/history/<更新ID>/` 保存 `update.md` 与完整 `before/`、`after/`。各闭环独立更新，current 不保证已适配整套文件资料的当前版本，展示须反映真实版本及完成状态。流程与确认边界见 04 U96 后的 U97 确认说明。

## 用户场景与验收草案

用户指定项目并生成某份源码的讲解，能够在该项目 docs/aftertaste/current 下找到与真实源码名称对应的 Markdown。

命名验收至少包含：普通文件、不同目录同名文件、同一目录同主名但不同扩展名文件；按 FR-015 分别产生不同路径。降级验收：AI 留下不完整专用结构且未执行独立校验时，打开阅读页仍能看到错误、修复提示词和原文的普通 Markdown 展示，不把页面整体变成空白。

## 已确认的命名规则（U8）

镜像源码相对于目标项目的路径，并保留原扩展名后再加 .md。U34 已确认在当前资料路径增加 current 层，例如：

```text
源码：backend/app/auth.py
讲解：docs/aftertaste/current/backend/app/auth.py.md
```

保留原扩展名可区分 auth.py 与 auth.ts；镜像目录可区分 api/auth.py 与 services/auth.py。用户指定项目边界及重命名规则另行讨论。

## 源码定位（U22 已确认的部分）

源码路径由镜像命名推导，文档顶部记录 Git 提交，块标记提供源码行范围；三者一起确定对照源码，不读取最新工作区文件替代。此前“文档头再次记录源码相对路径”的候选不采用。仓库与项目的路径基准、文档头语法及整套版本核对方式尚未定。重命名时 Git 的相似度判断只能辅助匹配，不能保证恢复文档身份。

定位验收：`docs/aftertaste/current/backend/app/auth.py.md` 在所选项目范围内映射到 `backend/app/auth.py`；以 current 为当前讲解镜像根，不能把 current 当作源码路径的一部分。头部记录提交 A 时，源码定位依据 A，不能因 HEAD 或工作区变化而偷换为新源码。该例不决定用户指定子目录与 Git 仓库根的映射规则。

## Markdown 与源码的分工（U20 已认可）

Markdown 保存定位与讲解，不保存一套供左侧展示的源码副本；源码按固定提交由程序读取。直接以普通 Markdown 打开时，文档提供讲解和定位，完整源码对照由阅读器提供。正文中的教学示例代码不因此被禁止，也不能被当作左侧真实源码的权威来源。

源码范围如何划分仍是 AI 的内容判断；程序可检查所选范围是否存在、连续、完整覆盖且不重叠，不能据此证明分块合理或讲解正确。沿用既有的工具生成 ID 与机器检查设计，不据此增加自动语义分块算法。程序实现仍须验证，不将分工原则表述成软件绝不出错的保证。

验收场景：Markdown 只含合法定位与讲解，无左侧源码副本，阅读器仍可展示固定提交的完整源码；工作区中的同名文件被修改后，展示仍取固定提交。正文中的示例代码不替代程序提取的源码。源码如何进入离线产物属于 D-001 的后续选型，不因本轮决定运行方式。

## 机器校验建议（U6 提议，规则待确认）

支持采用脚本校验，使结构错误可重复检查；但校验通过不能证明解释正确。

候选规则：

1. 必填元信息存在、格式正确，引用源码属于本套资料的选定提交。
2. 源码路径在固定提交中存在，行范围有效；按 U20 不再要求 Markdown 保存供展示的源码摘录，也不将正文教学示例当作真实源码来源。
3. U14 已确认文件讲解须完整展示该文件源码，每个对照块对应本文件的连续范围，见 [FR-024](06-document-blocks.md)。此前“可用略过记录代替完整展示、闭环文件讲解仅覆盖部分范围”的候选不再适用。U19 进一步确认范围不重叠、每行恰好归属一个对照块，对照块按源码顺序排列，纯讲解块可穿插；检查依据见 06 的 FR-029—FR-030。
4. 段落标识无冲突，引用目标存在，必需章节齐全；允许哪些 Markdown 格式由后续规范规定。

源码缺段可在覆盖约定明确后机器检查；AI 说错含义、遗漏业务解释不能只靠结构校验证明。U8 已确认展示时出错则提示并降级，不阻断普通 Markdown 阅读。专用结构解析与普通 Markdown 渲染应分开；若文件根本无法读取，不能声称已展示其原文。普通 Markdown 渲染器异常时是否再显示纯文本，是 AI 建议，尚未确定。

修复提示词建议包含：讲解文件路径、目标提交、对应源码路径、具体错误和相关片段；不依赖用户自行拼接。这些字段及提示文案待定。版本对应错误也须有可检查依据，不能承诺仅靠语法解析发现所有中断状态。

## 重建与手改的边界

项目派生资料可以重新生成，但 AI 重生成不保证逐字相同；用户手写补充也未必能从源码恢复。按 U6，目前接受手改内容由用户负责，不自行扩展自动备份或编辑历史功能。允许工具在用户主动更新时怎样处理这些补充，仍需单独确认。

验收草案：合法的手改讲解经过选定刷新流程后展示修改结果；重建派生资料不会覆盖阅读器程序。校验失败按 FR-016 处理；刷新流程尚未确定。

## 需要讨论的底层选择

| 议题 | 未决问题 |
| --- | --- |
| 路径基准 | 镜像相对于用户指定子目录，还是整个 Git 仓库根 |
| 文档身份 | 文件重命名或移动后，旧讲解如何定位、保留和继续维护 |
| 内容边界 | 哪些属于讲解正文，哪些是源码版本、范围、定位等元信息 |
| 元信息承载 | 文档顶部保存 Git 提交已确认；具体语法、整套目标版本的表达与核对方式尚需明确 |
| 多文件内容 | 闭环总览和跨文件说明放在哪里，如何避免与源码镜像命名冲突 |
| 原始与生成资料 | 可重建原则已确认；索引、快照、缓存和个人记录的具体归属与重建流程待定 |
| 个人内容 | 进度、疑问、批注是否随项目保存，是否与讲解文档分开 |
| 定位 | 行号之外是否还需要原文或段落标识，防止代码插行、文档改写后错位 |
| 写入边界 | 哪些目录允许工具写入；用户修改的讲解如何在更新时保全 |
| 失败与恢复 | 已确认错误提示、修复提示词与普通 Markdown 降级；具体检测规则和提示词内容待定 |
