## 已认可的设计

| 编号 | 已认可内容 | 来源 |
| --- | --- | --- |
| FR-018 | 只保留对照块与纯讲解块：对照块源码在左、讲解在右；纯讲解块没有左侧源码。取消纯源码块，简单源码至少配一句作用说明，不为凑格式强迫扩写 | U11、U12 |
| FR-019 | AI 依据规范划分文档块，每块大致只讲一件事，任务单一，避免块过大；Skill 提供规范和限制，内容组织仍由 AI 完成 | U11 |
| FR-020 | 检查发现特别大的块时发出警告，不报错；AI 必须明确告知用户这个块很大，使用户知情 | U11 |
| FR-021 | 用户按 AI 划分的文档块标记理解情况，区分未标记、已理解、明确不理解三种记录 | U11、U12 |
| FR-022 | 分别检查源码行数和讲解文字量：源码超过 60 行，或讲解超过 1,200 个非空白字符，任一满足即警告；等于阈值不警告 | U12 认可检查方式并授权 AI 确定具体限值 |
| FR-023 | 每个文档块拥有稳定短 ID，在同一文档文件内唯一；ID 与阅读顺序分离，顺序由 Markdown 中的位置决定。创建时生成并写入，插入块不重编旧 ID；同一块修改标题、补充讲解或调整位置时保留 ID；检查同篇内的重复 ID | U14、U15 |
| FR-024 | 一个对照块对应本文件的一个连续源码范围；一篇文件讲解的源码展示须完整覆盖该文件，不能只抽取部分代码 | U14 |
| FR-025 | 优先为人需要理解、具有可读性的代码生成讲解；推荐不为冗长的机器生成文件生成讲解，但不强制禁止 | U14 |
| FR-026 | 使用“文档路径＋块 ID”定位；块 ID 为 8 位随机小写英文字母和数字，字符集为 a–z、0–9，同一文档内唯一 | U16 |
| FR-027 | 块拆分或合并后，所有结果块生成新 ID，原 ID 不再作为当前文档的有效块 ID；同一块普通修改保留 ID 的既有规则继续有效 | U18 |
| FR-028 | 拆分、合并后的新块理解状态从“未标记”开始，不自动继承原块的“已理解”或“明确不理解” | U18 |
| FR-029 | 同一文件讲解中，对照块的源码范围不重叠；结合完整覆盖规则，每行源码恰好归属一个对照块，包括注释与空行 | U19 |
| FR-030 | 对照块在文档中按源码行号从前到后排列；纯讲解块可以穿插在开头、中间或结尾，不占用源码范围 | U19 |
| FR-032 | 块采用成对的 HTML 注释标记包围普通 Markdown 正文：开始标记记录 ID，可选源码范围；有范围为对照块，无范围为纯讲解块。具体块语法由 AI 在本轮授权内确定，见末节 | U21 授权内的 AI 格式设计 |
| FR-033 | 辅助脚本生成带合法 ID 和结构标记的块骨架，AI 决定源码分块范围并填写讲解；脚本不替 AI 自动决定语义分块 | U21，沿用 U17、U20 |

FR-020 的“知情”不等于新增批准流程。不擅自要求用户先批准才能继续，也不擅自规定必须在生成前告知。仅体积超限属于警告，不按 FR-016 当作文档损坏触发降级；独立存在的格式错误仍按原规则处理。

FR-021 已确定标记粒度，不继续提出“现成块还是任意选中文本”的二选一。复制提问或注释是否允许选中文字属于不同功能，不由此顺带限制。

## 块形式的最终取舍（U12）

| 形式 | 当前状态 | 展示含义 |
| --- | --- | --- |
| 对照块 | **已认可** | 左侧源码，右侧讲解 |
| 纯讲解块 | **已认可** | 只有讲解，无左侧源码；是否横跨内容区尚未作为布局要求确认 |
| 纯源码块 | **已取消** | 为源码增加至少一句作用说明，使用对照块 |

## 超大块检查口径（作者授权内的 AI 决定）

| 检查对象 | 警告条件 | 计数口径 |
| --- | --- | --- |
| 对照块中的源码 | 大于 60 行 | 按该块所引用源码的物理行计数，包含空行与注释；连续范围为结束行减开始行加 1，不按浏览器折行计数 |
| 任一种块中的讲解 | 大于 1,200 个非空白字符 | 对讲解正文的 Markdown 原文按 Unicode 码点计数，排除 Unicode White_Space 字符；中文、字母、数字、标点、Markdown 标记及正文中的示例代码都计入；不计结构元信息和左侧所引用的源码 |

讲解标题若属于正文 Markdown 则计入，独立结构字段不计入。无左侧源码的纯讲解块仅进行讲解长度检查。精确计数以这套原文规则为准，不随 Markdown 渲染器或浏览器布局变化。

确定理由：60 行源码为完整逻辑保留一定空间，又能提醒 AI 检查是否夹带了多个任务；1,200 字符允许配必要例子，但能提醒集中在一块的长篇讲解。二者是首版设计阈值，不是经过用户实验得到的最佳阅读长度，也不是建议 AI 每块都写满的目标。

这里明确不采用自动拆块或长函数禁用：逻辑完整、确需保留的大块可以继续展示，只警告并由 AI 明确告知用户。该决定不引入可配置阈值界面或新的暂缓事项。

## 理解记录（U12 已认可）

- **未标记**：用户尚未明确标记为已理解或不理解，沿用“尚未确认吃透”的含义；不能等同于用户主动表达困惑。
- **已理解**：用户明确确认理解这一块。
- **明确不理解**：用户主动指出这一块存在理解困难，与未标记区分。

三种记录是已确认的含义，不擅自扩展其他状态。保存机制、按钮交互与状态切换不是本轮授权 AI 自行决定的范围。

## 验收场景草案

- 对 40 行源码，依次使用 1—20 行和 21—40 行的对照块，覆盖、重叠与顺序检查通过；两块之间插入纯讲解块不改变结果。
- 使用 1—20 行和 20—40 行时，检查发现第 20 行重复归属；使用 1—20 行和 22—40 行时，检查发现第 21 行遗漏。
- 先展示 21—40 行的对照块、再展示 1—20 行的对照块，即使完整覆盖且不重叠，也不符合源码顺序要求。
- 一个块拆成两个或更多块，每个结果块均使用新 ID，不将原 ID 留给其中某个块；原块无论为已理解、明确不理解或未标记，新块均从未标记开始。
- 多个块合为一个块，结果块使用新 ID，不沿用任何输入块 ID；无论输入块状态相同还是不同，新块均从未标记开始。
- 同一块只改标题、补充讲解或调整位置，不因上述拆分合并规则重建 ID。此场景仅检查身份规则，不顺带决定普通修改后的理解状态处理。
- 在同篇两个既有块之间插入新块，新块获得新 ID，原有 ID 不变；按 Markdown 中的新位置顺序阅读。
- 同一文档内的重复 ID 必须能被检查发现；不同文档出现相同块 ID 不构成此规则下的冲突，跨文档定位须带上文档身份，不能只靠块 ID。
- `k7m2x9qa` 符合 ID 格式；不足或超过 8 位、包含大写字母或其他符号均不符合。随机字符不要求每个 ID 同时包含字母与数字，唯一性仍需检查，不能靠格式判断。
- 已生成讲解的文件，其全部源码均可在对照块中查看，不能用省略号或略过记录代替未展示的源码；这不要求为项目内所有文件都生成讲解。
- 每个对照块引用本文件的连续源码范围；完整覆盖要求包含文件内的注释和空行，不等于要求逐行写一段解释。
- 机器生成文件默认不作为优先讲解对象；用户选择讲解时不能仅因其为机器生成而拒绝，仍遵守完整覆盖与超大警告要求。
- 同一份讲解中包含对照块和纯讲解块，前者正确显示左右对应，后者不虚构源码。
- 源码为 60 行、讲解为 1,200 个非空白字符，结构与定位合法：不触发超大警告。
- 源码为 61 行、讲解低于阈值：触发源码超大警告，正常展示，AI 明确告知用户。
- 源码低于阈值、讲解为 1,201 个非空白字符：触发讲解超大警告；纯讲解块遵守同一阈值。
- 两项均超限时，检查结果反映两项超限；不因超大本身报错、阻断阅读或触发损坏降级。
- 改变浏览器窗口导致源码折行，不改变源码计数；仅增加讲解中的空白不改变讲解计数。
- 用户对块 A 标记已理解、对块 B 明确标记不理解，可以区分两种用户表达。保存、取消或改选的具体行为在功能讨论中确认，不由此文擅自实施。
- 讲解是否聚焦一件事属于内容质量判断；机器可检查量化大小，但不声称靠行数证明语义单一。

以上是已确定的验收条件，尚未实现校验器或运行产品测试。

## 稳定短 ID（U15—U16 已认可）

ID 只需在同一文档文件内唯一，不要求跨文档全局唯一。U16 确认格式为 8 位随机小写字母和数字，例如 `k7m2x9qa`，字符集为 a–z、0–9。它表示块的身份，不编码阅读位置、标题或源码行号。顺序按 Markdown 中的位置确定，工具生成及同篇重复检查沿用 U15 对上一轮建议的认可。

该值称为“块 ID”，不是标准 UUID；不限定为 UUID 截取后的十六进制字符。随机生成不等于天然不会重复。具体冲突处理仍是 AI 建议：新建 ID 若与本篇已有 ID 重复就重新生成；已有文档中的重复 ID 应报告，不自行重写可能已被用户记录引用的 ID。

“文档路径＋块 ID”定位已由 U16 认可。例如文档 `docs/aftertaste/current/backend/app/auth.py.md` 中的块 `k7m2x9qa`，不能只凭后者跨文档定位；示例按 U34 增加 current 层。块级字段格式见 U21 授权内设计；文档路径字段、路径基准、文件重命名后的身份维护尚未确认。拆分合并的 ID 与理解状态按下节 U18 决定执行，其他用户记录的关联方式不由此顺带定案。没有新增正式暂缓项。

## 拆分、合并与理解状态（U17—U18 已认可）

U29 对历史差异范围作出补充：首版只处理块的新增、删除、修改，不识别或展示拆分、合并关联。下列新 ID 及初始状态规则继续有效；重新分块在历史比较中体现为旧块删除、新块新增。源码变化但正文不变也算块修改，见 [01 的 FR-042—FR-043](01-source-version.md)。

| 操作 | 结果块身份 | 结果块理解状态 |
| --- | --- | --- |
| 一个块拆成两个或更多块 | 所有结果块各自生成新 ID，不保留原 ID 给其中任何一个块 | 全部从未标记开始 |
| 多个块合成一个块 | 合并结果生成新 ID，不继承任何原块 ID | 从未标记开始 |

原 ID 停用仅表示它不再是当前文档中的有效块 ID，不据此要求建立历史块数据库，也不授权删除用户记录。新 ID 仍遵守 FR-026 的格式和同篇唯一要求；同一块修改标题、补充讲解、调整位置保留 ID 的 FR-023 不变。

依据 U17，是否拆分或合并、具体分界和结果讲解内容由 AI 结合源码与阅读需要决定，Skill 教 AI 遵守操作规则，不替 AI 决定内容。操作后继续满足已有的连续源码范围、整文件完整覆盖、单块单一任务和超大警告规则；不新增自动拆分、合并算法。

U18 仅确认上述两条规则。书签、注释等用户记录如何关联原块和新块，以及普通修改后的理解状态如何处理，尚未获作者确认；不把 AI 上轮建议全部视为已批准，也不新增正式暂缓事项。

## 源码归属与展示顺序（U19 已认可）

一篇文件讲解的对照块按源码顺序完整展示原文件，不重复占用任何源码行。对于非空文件，第一个对照块从第 1 行开始，后续对照块从上一对照块结束行的下一行开始，最后覆盖至文件末行。纯讲解块不参与源码覆盖，可以在任意块间补充背景、关联或总结。

讲解需要回顾前面的源码时，可以在讲解正文中引用，不再为同一源码范围另建对照块；具体引用语法没有在本轮确认。FR-023 的“调整位置保留 ID”仍有效，但调整后的文档必须满足 FR-030，不表示允许随意打乱对照块的源码顺序。闭环阅读路线的顺序不由单篇文件的顺序规则顺带决定。

## 块级 Markdown 格式（U21 授权内的 AI 设计）

以下语法由作者授权 AI 确定，不伪称作者逐字段指定；只是设计规格，尚无解析器或骨架脚本实现。文件级元信息和整套资料的版本信息不在本节定案。

```markdown
<!-- aftertaste:block id=k7m2x9qa lines=1-20 -->

## 读取配置

这里填写这一段源码的讲解。

<!-- aftertaste:end -->

<!-- aftertaste:block id=p4n8c2wr -->

## 背景说明

这里填写不单独对应源码范围的讲解。

<!-- aftertaste:end -->
```

| 项目 | 格式约定 |
| --- | --- |
| 开始标记 | `<!-- aftertaste:block id=块ID lines=起始行-结束行 -->`；纯讲解块省略整个 `lines` 字段，不另设类型字段 |
| ID | 必填，沿用 FR-026 的 8 位小写字母数字与同篇唯一要求；示例 ID 不可当作新块的固定值反复复制 |
| 源码范围 | 行号从 1 开始、首尾均包含，单行也写成 `lines=7-7`；范围必须有效且满足完整覆盖、顺序和不重叠规则 |
| 结束标记 | `<!-- aftertaste:end -->`；每个开始标记必须对应一个结束标记，不允许块嵌套 |
| 标记位置 | 标记独占文档顶层的一行，不放进列表、引用或代码块；正文代码块中的同样文字仅为示例，不当成结构标记 |
| 正文 | 标记之间是普通 Markdown；标题不决定块边界，正文可以包含列表、表格和教学代码示例。此处不规定讲解的措辞与语言风格 |
| 格式错误 | 非法或重复字段、写错的源码范围、缺少配对标记等属于结构错误；不能把错误的 `lines` 静默当作纯讲解块。沿用报错、修复提示与普通 Markdown 降级规则 |

生成分工（U22 已认可）：AI 读取固定提交源码后提供完整的有序分块清单，明确每块有无源码及其范围；块数由清单得出，不另传一个需要保持一致的计数。辅助脚本据此生成带 ID、范围和成对标记的骨架，AI 再填写正文。脚本不猜测块类型或语义分界，检查范围不能证明分块合理。骨架生成不等于完成文档，也不保证正文正确；具体命令参数格式、更新现有文件的写入方式尚未决定。

验收补充：两种块按有无 `lines` 正确识别；正文增加标题不产生新块；缺结束标记或 `lines=20-1` 时报告结构错误；正文围栏代码块内出现标记示例不截断外层块。以上为设计条件，尚未运行验证。

## 模板与语言风格的职责建议

U21 提出脚本生成骨架、模板供 AI 参考模仿的配合方向。AI 推荐保留简短结构模板，说明两种块怎样填写、展示合法示例，并提醒不要复制示例 ID；模板应与骨架生成规则一致，不维护另一套格式。此处记录建议，不据此创建模板产品文件。

讲解的措辞、叙述顺序和示例写法属于后续语言风格讨论，不混入底层块语法。作者希望认真设计这些内容，但尚未决定是否另建语言 Skill，也未确认具体写作要求；本轮不作选型或新增正式暂缓项。
