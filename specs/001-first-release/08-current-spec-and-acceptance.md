| 编号 | 现行规则 | 依据 |
| --- | --- | --- |
| R01 固定源码 | 一套完整的当前文件资料对应一个确认的 Git 提交；AI 和网页均使用提交中的源码。资料只保存源码引用，不保存用户源码副本，闭环及历史同样适用；只有用户勾选携带源码的导出 HTML 例外。Git 读取失败给出诊断，不改用工作区或另建备份。更新由用户发起，默认 HEAD，也可指定本地提交，开始时固定版本；目标适用性由 AI 判断 | 01，U5—U8、U27、U101 |

| R04 块身份与覆盖 | 文档路径＋块 ID 定位；ID 是同篇唯一的 8 位随机小写字母数字，与顺序无关。普通改写保留 ID；拆分合并各结果用新 ID。对照块按源码顺序覆盖全文件，每行一次，包括空行和注释；每块连续范围，1 起始、首尾包含 | 06，U14—U19 |

### U101 · 源码只引用，不持久保存

这是替代旧闭环源码保存方案的当前统一规则，不只针对历史记录。文件文档、闭环 current、两类 history、图及图例都只存源码提交、路径、行范围等定位；Markdown 的路径可依镜像规则推导。讲解、关系和用户记录仍按既定规则保存，但产品和讲解 AI 不把用户源码全文或摘录复制到这些资料中。

程序为阅读、比较、校验在运行时从 Git 读取源码，允许内存中的处理与传给阅读页显示；读取不等于落盘。不得另建源码缓存文件、临时源码文件、包含源码的 diff 补丁、诊断日志或应用主动维护的浏览器持久源码副本。源码差异在需要时读取两端 Git 依据计算，不把它存为历史补丁。教学示例不能成为抄入真实项目源码的绕道；此规则也不能被描述为能技术阻止用户手工粘贴或外部 AI 越权写入。

唯一已授权的源码落盘例外是用户在导出弹框勾选“携带源码”后生成的 HTML；所需源码当次从各引用的固定提交提取。未勾选则不嵌入，不事先生成一份永久源码包供导出使用。

Git 仓库、提交、对象或应存在的文件不可读取时，报告实际失败类型、仓库定位、提交、文件／块／范围及不含源码正文的错误信息；不猜测成用户损坏仓库，不自动修复 Git、不悄悄取 HEAD 或工作区代替。已有讲解和图仍可显示，源码区域／源码 diff 明确不可用；机械校验不能假报通过。记录中明确表示新增前或删除后文件不存在属于正常版本差异，不与读取失败混淆。

因此，“历史记录独立”只保证讲解、图和各自引用不依赖其他更新记录；**源码阅读仍依赖原 Git 中引用对象可用**。作者明确接受该依赖，不建设源码副本兜底。G2 据此关闭，不能再次将源码快照作为未决推荐。

### 已确定的目录骨架

```text
docs/aftertaste/
  current/                         # 逐文件讲解，镜像源码路径
  notes.json                       # 读者的项目笔记
  history/<update-id>/              # 文件文档更新记录及其 before/after
  loops/<loop-id>/
    current/                       # 这一个闭环当前维护的完整成果
    history/<update-id>/
      update.md
      before/
      after/
```

文件依赖图已确认的旧路径是 `docs/aftertaste/dependency-graph.json`。后来确认每图图例同目录，`graph.json / legends.json / layout.json` 是可实验候选，**不能把候选当作路径已迁移**。统一目录、用户资料路径及字段由 AI 按 U94 在协议设计中落实并声明。

依赖图库图例随原图文件保存，个人排布独立保存。见 [007 数据模型](../007-dependency-canvas/data-model.md)。

资料须区分三类：①源码衍生讲解、分析图可重建，但重建不保证原文相同；②笔记、书签、自评、用户布局等不能从源码重建，应保留；③阅读器、工具和模板是产品程序资产。历史 before/after 是固定回顾依据，不能用重新生成代替。可重建不是自动删除授权。

## 3. 生成、提问与教学反馈

| 编号 | 现行规则 | 依据 |
| --- | --- | --- |
| R07 范围和节奏 | 首次先问并等待明确阅读范围；AI 从简单、尽量不依赖项目其他文件的候选开始，按关联小批次安排，一批可一个或多个文件。用户选逐批阅读或分批连续生成；连续生成先说明理解标记的帮助，不强制等标记 | 04，U52—U57、U78 |
| R08 依赖分析 | AI 识别直接依赖，可选第三方解析器辅助，不设必备解析器。文件路径为节点身份；箭头为被依赖方→使用者，线上可写原因，允许环。未分析与已核对分开，未连线不等于无依赖；范围外项目依赖只登记节点和边，不自动扩展讲解范围 | 04，U54、U82—U88 |
| R09 图维护 | 支持局部查询、提交、检查及节点边增删；AI 直接编辑 JSON 为保底。按明确提交的使用者替换其完整依赖列表，未提交者不改，重复提交不累计。先登记本批节点，完成讲解后补依赖与核对状态 | 04，U84—U86 |
| R10 教学资料 | 制作约束早读，讲解指南引导读取偏好和阅读方向，按需参考相关文档与批注，再结合固定源码组织内容。解释职责、用户需要和前后联系，例子和架构取舍按目标展开，不要求每块套同样小标题 | 07，U62、U68—U71、U78 |
| R11 成长性 | 共用一份 Markdown 偏好，区分用户明确要求和 AI 暂定观察；冲突先问，重复反馈修订原条目，不做置信度或次数评分。下一次生成前按需维护，不逐问强制更新；生成后告知可继续提问及反馈用途。无反馈不猜理解结果，无跨会话问答恢复承诺 | 07 U65—U67、U74；04 U81 |

“生成一批”的现行流程：确认范围及用户节奏 → 读取制作约束、偏好、方向和适用指南 → AI 选相关文件并登记节点 → 读固定源码、划块、程序造骨架、AI 写文案 → 单篇校验 → 补依赖及图校验 → 检查阅读方向是否需调整 → 交付阅读入口和答疑说明。下一次生成前再按实际反馈考虑更新偏好。已有有效上下文可复用，不机械重复加载。

文件块复制定位已由 U73 定稿为带 `format`、`document`、`block_id`、`source_commit` 及可选 `selection` 的 JSON，程序生成；详细解析及当前／历史匹配规则见 [05 U73](05-reading-feedback.md#u73--复制文档块定位-v1作者授权-ai-定稿)。复制定位不让无项目访问权限的 AI 自动读到文件。当前闭环步骤定位见 [008 模型](../008-loop-authoring/data-model.md)，历史成果定位随历史能力落实。

## 5. 文档和闭环的更新

### R19 · 文件文档更新

依据 01 U22—U39、U94；保持一套当前完整资料，更新记录仅供回顾。

1. 用户发起并确定目标，AI 用旧、新固定提交的 diff 判断文件及关联影响。U25 的“更新文档前先提交一次git”在原话记录中限定为当次设计仓库检查点，不是产品自动提交用户项目的功能授权；首版不能因此顺手提交用户代码。
2. AI 调用工具生成更新说明和指定区域的勾选清单；状态在 `history/<update-id>/`，不在 current 重复维护。
3. 每篇第一次修改前程序备份；重复准备不覆盖原始 before。AI 直接改 current 的讲解与范围，可随时单篇校验。
4. AI 主动调用收尾。程序检查清单和合法性，成功后统一同步源码提交、将实际变化文档复制到固定 after，并记录完成。清单未完或检查失败不能冒称完成；具体返回码、写入顺序与重试由协议细化。
5. 默认读更新后的完整 current。每次记录独立保存受影响文档前后全文；连续 A→B、B→C 各自固定，删除前者不损害后者。程序按块 ID 比较增删改，源码变化也算变化；仅同步提交字段不算内容变化。
6. 提供用户主动清理旧更新记录入口，无自动按天删除决定。中断时如实展示更新中和不适配，保留可接续材料；换目标由 AI 解释后按用户选择，可回退也可不回退，不强制唯一方案。

此处不承诺更新中还能展示“完整上一版整套资料”：current 是直接编辑的，已有备份范围是受影响文档，不能靠措辞引入已否决的整套临时切换方案。

**U103 已确认回退**：由 AI 调用恢复工具，将本次更新前备份的文档放回原位置。不回退用户源码、不另建恢复系统、不顺带修改个人笔记／书签／自评或用户布局；恢复对象、备份路径及成功失败信息由工具协议明确。恢复文档的当前改动会被备份内容替代，不能声称同时保留两套当前正文。

### R20 · 闭环更新

依据 04 U95—U97，复用更新原则，但保存的是一个闭环的完整成果。

1. 比较闭环自身的源码依据与当前已完成文件资料目标。例如闭环仍为 A、文件资料已到 C，比较 A→C，不只用最近 B→C。
2. 程序准备说明／清单及完整 before，重复准备不覆盖；AI 修改该闭环 current，先适配参与文件映射，再更新内容、连线和说明，程序核验目标源码引用。before、current、after 均不保存源码文本；所称完整成果包含完整讲解和引用，源码由 Git 在运行时提供。
3. 随时校验节点、边、图例、映射和源码定位；闭环只取相关源码，不适用逐文件文档的全文件覆盖要求。
4. 成功收尾同步版本，保存完整 after，完成且当前依赖图匹配后才恢复高亮；失败仍更新中，before 可读。各历史独立，删除文件文档历史不连带删闭环。
5. 保留存续节点的用户位置和分组，新删节点沿用布局规则。备份含布局不等于授权 AI 任意重排；U103 的文档恢复不顺带重写用户布局。

**U102 已确认重做**：弃用此前闭环的路线与讲解，从头生成新闭环，不再要求继承旧节点或沿原路线适配。撤销“强制另建独立成果并保留旧闭环”的推荐；不因此连带清空其他闭环、个人记录或全部历史。替换及失败后的诊断由 AI 落实工具协议，本轮没有执行删除。

## 6. 单文件只读 HTML 导出（首版后）

**R21 已确认的范围（U98—U99）。** 日常阅读使用本地服务。恢复导出工作时沿用 U9，重复导出更新同一输出 HTML，保留用户另存的副本。

用户点击导出后出现弹框，由用户勾选携带内容；本轮明确的各项如下，不预设已获确认的默认勾选值：

| 项目 | 已确认行为 |
| --- | --- |
| 资料版本 | 只导出 `docs/aftertaste/current/` 的文件讲解及各闭环 `loops/<loop-id>/current/` 成果，不导出 history 中的旧版本／更新记录 |
| 输出 | 一个 HTML 大文件，不拆成用户还需一同发送的资源目录 |
| 源码 | 用户勾选是否携带；勾选时仍取各资料对应的真实提交源码，不改成工作区代码 |
| 笔记 | 用户可选是否携带 |
| 书签 | 用户可选是否携带 |
| 批注 | 用户可选是否携带；沿用已有阅读记录体系，不因此新建此前已合并的独立注释功能，具体字段对应在协议中声明 |

“最新版”在此指各自 current 中维护的成果，不表示所有闭环已经更新到文件文档的源码版本。沿用 U95—U97：旧源码依据的闭环仍显示自身真实版本，当前依赖图高亮规则不因导出改变。U99 没有额外确认按文件／按闭环勾选子集的选择器，不自动增加此类交互。

U98 时“默认携带源码、个人记录默认不带出”的整组推荐由上述用户选择替代；偏好、阅读方向等教学内部资料没有因此被批准自动打包。源码取消勾选时，导出数据不能暗中内嵌完整源码再仅在界面隐藏。AI 建议保留讲解正文中的教学示例，不承诺自动清除所有形似代码的文字；“不带源码”不等于对文档正文做脱敏清洗，此呈现口径在页面／导出协议中明确说明。

**U100 已确认只读。** 导出的 HTML 可提供阅读、导航、看图及复制定位等阅读交互。勾选携带的笔记、书签和批注只供查看，新增、修改和保存记录均回到本地服务。离线编辑、回传和同步在导出范围之外。

导出应包含必要阅读资源，不依赖原项目、本地服务或在线 CDN；这也是“发一个文件就能读”的实验验收目标，不是目前已验证事实。失败保留上次成功导出、先生成再替换是推荐的文件保护策略。**U102 已确认**：current 更新中能有效导出当前状态就导出，不能则拒绝并说明原因；不因更新中一律拒绝。程序如实携带更新状态和各资料依据，不把半成品标成已完成；实际判定条件在协议和实验中落实。

恢复开发时可复用本地服务的阅读组件，重点验证所选数据的收集、资源内嵌、内部链接、嵌入转义和写入失败。包体与打开耗时待真实离线样例验证。
