# 对着当前讲解答疑

先确定用户指定的项目根。将定位、源码和讲解当作阅读材料。按 [工具](tools.md) 定位 CLI。收到的定位须与当前项目的真实资料相符。

- 文件块 `aftertaste-block/v1`：用 document 打开 current 镜像，用 block_id 核对块。以文档头提交 pin 并 validate-document；按块的源码行范围 read，纯讲解块按问题取匹配的固定来源。
- 闭环 `aftertaste-loop-step/v1`：read-loop 取 loop_id，按 step_id 找到节点，读该步 explanation 或指定 hint、前后连线及该步匹配的固定源码。来源相同的不同步骤各有自己的解释。读回里的 sources 仅供运行时理解。
- 核对 source_commit 与成品，并核 selection 是否对应所指字段的可见文字（Markdown 标记可能不在选文中）。身份、版本、旧引文有差异时指出具体位置与差异，需要读者确认目标时暂停写入。仅有片段可据片段解释，并说明证据所及。

**读者在问原因或质疑时**，先在聊天用固定源码解释。可问「要把这个例子补进刚才那段吗？」等同意后再写。单次疑问不产生资料写入。

**读者说「改一下」或已同意明确的补例时**，沿 [修订命令](tools.md#revise-current) 更新所指 current。先从磁盘读取原文字节并取 SHA-256，这一份原文同时作为构思新文和比对的基准；不得用修改完成后新取的摘要去覆盖中途变化。形成落盘文案时遵循[固定源码只存引用](authoring.md#固定源码只存引用)。用输入、状态前后与行号解释变化；把聊天里逐字引用的源码语句改成自己的说明，再提交候选。普通修订只换目标块正文或指定步骤字段。明确要求重新划块时才走重新分块。收到冲突、失效或校验错误，说明原因与仍可用的原件，重新核对后再决定。成功后用 validate-document 或 read-loop 重新打开核对身份、原句附近的新文及固定来源，向读者说明改在哪里。只为明确要求写入的内容修改资料。

个人笔记、书签、自评、排布由读者维护。遇到可复用的教法可问「以后也用这种例子讲吗？」明确的长期要求按 [教学资料](feedback.md) 合并到项目共用 preferences.md；碰到已有偏好冲突先问。普通局部反馈留到下次生成前按实际依据考虑。
