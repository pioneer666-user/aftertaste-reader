# 生成或重读跨文件闭环

用户只想问清一段代码时，先在聊天回答。用户明确要串成并保存一条路线，按以下流程选题并生成。用户想重读已有闭环时，直接按项目路径和闭环 ID 使用 [读回工具](tools.md#闭环)，沿已存内容回答。源码不可用时说明具体引用，仍可继续读讲解。

## 提出完整路线

1. 确认目标项目和读者想理解的过程。沿[共同讲解方法](teaching.md#项目讲法)只读项目偏好以核讲法，复用已明确的选择。路线已定且讲法待选时，给三项后结束本轮，答复后继续第 2 步。路线还待选时，可从第 2 步取得必要依据，在同轮提供可用路线和需确认的讲法。一次关注点只用于本次串讲。
2. 从 `docs/aftertaste/current/` 找相关已有块，从当前文件依赖图了解文件关系。读取资料记录的提交，并用相应版本 `pin`。对候选用图查询、文档校验和固定 `read` 核起点、关键调用或数据、分支及结果。按文件讲解和图的实际版本判断可用性。开始编写时读已有阅读方向并复用适用的反馈。
3. 简述每条可讲完整的候选，从哪里进入、追到哪个结果、能回答读者什么问题。前文已明确选择、仍有完整依据的路线直接沿用。讲法和路线都已明确后才准备写入成果，教学资料也在这个时点后按[偏好维护](feedback.md#讲解偏好)保存。只等尚未明确的选择，保持已有资料原状。
4. 发现关键步骤缺少有效讲解，指出具体文件、步骤和缺什么。例如“能跟到服务的异常，但入口如何把异常变成响应还没有已讲解的块”。说明目前已有资料确实能支持的范围，留给读者选择。只有另行明确发起普通讲解任务时才按其流程补材料。

## 把每一步讲到结果

- 给出本路线要回答的问题，独立串讲先说明为什么会得到这个结果。关键步骤写清收到什么、哪个条件决定走向、哪条路径走不到，以及固定源码依据。档位只调整术语说明、例子和详略，三档都要回答同一个问题。可以回到先前读过的文件，或从同一原块引出不同教学步骤。
- 新写的串讲、步骤和连线，例子都围绕当前路线的输入、条件和结果。用同一组假设输入对照各分支的状态变化、跳过的操作和返回值。接口装配、持久化边界或响应封装决定结果时，在对应步骤正文写清它如何造成该结果。其他设计变化和取舍留在文件讲解。
- 给每条边理由，说明调用、数据变化、条件分支或教学关系。关键边或某一步的库用法可选写 `label`，提示条件、返回值或其他关系。按教学目的独立选用 `color`，缺省跟随主题。即使区分不了红绿，读者也应能从方向、文字及理由理解结果。用独立的推荐阅读顺序安排先读哪一步，实际运行与分支时序写在正文及边说明里。用到假设输入时标明是教学示例。
- 在值得读者停一下的判断或转折旁，可给该步骤写 `annotation`（Markdown）。用一句或一小段指出左右这条路线的条件、来源或结果。例如「数量 `0` 能转成数字，但**低于下限**，所以集合仍为空」。其余步骤省略。即便两步引用同一块，也各自选写；源码入口由工具按该步固定版本生成。
- 用 [工具](tools.md#闭环)的 JSON 引用原文件和块。工具从有效文档取出原讲解和行号，连同本次的文字、关系及提示保存。避免粘贴项目源码。沿固定源码核到具体步骤确实用库时，选该图例 ID 与文件，在该节点的 `library_uses` 里写本步用途。同文件其他步骤各自核对。没有相关库时省略图例。
- 保存前逐段回读新写的串讲、步骤和连线，保留能直接回答路线问题的条件、实际路径和被跳过的动作。简单写法对照、假设增加另一种入口等独立取舍留在文件讲解。原块讲解由工具照原样附在成品里。调用 `create-loop` 后核机械校验，再用 `read-loop` 读回成果。失败看具体字段、块或 Git 诊断。已有 ID 可以直接重读，另一个主题使用新 ID。
- 交付这条闭环的 ID、读回入口及它回答的问题。提醒「可以复制对应步骤的定位来问，也可以告诉我把哪里讲清楚」，相关反馈按 [教学资料](feedback.md) 帮助后续讲解。
