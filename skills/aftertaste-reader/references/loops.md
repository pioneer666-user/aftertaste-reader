# 生成或重读跨文件闭环

用户只想问清一段代码时，先在聊天回答。用户明确要串成并保存一条路线，按以下流程选题并生成。用户想重读已有闭环时，直接按项目路径和闭环 ID 使用 [读回工具](tools.md#闭环)，沿已存内容回答。源码不可用时说明具体引用，仍可继续读讲解。

## 提出完整路线

1. 确认目标项目和读者想理解的过程。沿 [共同讲解方法](teaching.md) 读取项目现有偏好与阅读方向，并复用适用的反馈。选线阶段只读现有资料，缺少偏好或阅读方向可以继续。一次关注点只用于本次串讲。
2. 从 `docs/aftertaste/current/` 找相关已有块，从当前文件依赖图了解文件关系。读取资料记录的提交，并用相应版本 `pin`。对候选用图查询、文档校验和固定 `read` 核起点、关键调用或数据、分支及结果。按文件讲解和图的实际版本判断可用性。
3. 简述每条可讲完整的候选，从哪里进入、追到哪个结果、能回答读者什么问题。等读者明确选择后，才准备写入这条成果。前文已经明确选定且仍有完整依据时可直接沿用。
4. 发现关键步骤缺少有效讲解，指出具体文件、步骤和缺什么。例如“能跟到服务的异常，但入口如何把异常变成响应还没有已讲解的块”。说明目前已有资料确实能支持的范围，留给读者选择。只有另行明确发起普通讲解任务时才按其流程补材料。

## 把每一步讲到结果

- 给出本次目标及独立串讲。每个关键步骤写清从前一步接到什么、怎样走向下一步、哪个条件决定结果。可以回到先前读过的文件，或从同一原块引出不同教学步骤。
- 沿用同一组假设输入，在分支正文带出各自的状态变化、跳过的操作和返回值，在汇合点对照两种结果。接口装配、持久化边界或响应封装决定结果时，把依据写进对应步骤正文；读者可以不展开提示就沿请求读完。
- 给每条边理由，说明调用、数据变化、条件分支或教学关系。用独立的推荐阅读顺序安排先读哪一步，实际运行与分支时序写在正文及边说明里。用到假设输入时标明是教学示例。
- 用 [工具](tools.md#闭环)的 JSON 引用原文件和块。工具从有效文档取出原讲解和行号，连同本次的文字、关系及提示保存。避免粘贴项目源码。沿固定源码核到具体步骤确实用库时，选该图例 ID 与文件，在该节点的 `library_uses` 里写本步用途。同文件其他步骤各自核对。没有相关库时省略图例。
- 调用 `create-loop` 后核机械校验，再用 `read-loop` 读回成果。失败看具体字段、块或 Git 诊断。已有 ID 可以直接重读，另一个主题使用新 ID。
- 交付这条闭环的 ID、读回入口及它回答的问题。提醒「可以复制对应步骤的定位来问，也可以告诉我把哪里讲清楚」，相关反馈按 [教学资料](feedback.md) 帮助后续讲解。
