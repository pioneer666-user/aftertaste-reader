# 普通文件分批生成

本页用于第一次与后续批次的普通新生成。先完成入口要求的制作、教法与教学资料读取。调用细节见 [工具](tools.md)。

## 1. 核边界和实际资料

确认目标项目，沿[共同讲解方法](teaching.md#项目讲法)核项目讲法，并核范围及逐批／连续节奏。缺项就问并结束本轮，三项明确后再核对下文资料。默认版本在首次开始时 pin HEAD，之后保留完整 pin 映射，HEAD 或 cwd 变化时继续同一固定来源。

开始分析前枚举 `docs/aftertaste/current/` 的实际 Markdown 并读其头部提交，读取既有 dependency-graph.json 的 source_commit 与结构。目录／图缺失属于首次生成情况，方向摘要只供参考。核相关既有文档的实际内容与校验结果，确认哪些已完成。

既有任一 current 文档或图与目标提交冲突、头部无法判断、既有图损坏时，说明实际资料状态，停止依赖写入。版本更新尚待接入，保留旧文档、版本字段与工作区。资料冲突时也保留偏好及方向原文。

同版完成文档可复用，列清本批新增和已存在内容。遇到 DOCUMENT_EXISTS，读取并报告现状。仅有本次成功创建证据、确认仍为同版且未完成的骨架可以接着填正文，保留已有 ID／范围。其他既有空骨架或不完整文档说明需单独处理，保存原件。

## 2. 读固定源码并选批次

按工具参考[枚举固定文件](tools.md#固定文件枚举)，在用户范围内选择候选路径，再按示例[读回选定文件](tools.md#读回选定文件)。读取相关项目文件核依赖与理解难度，按教法选择小批次。范围外项目文件可用于核依赖背景，遵守用户明确的读取限制。现有解析工具可按语言与环境辅助，结果仍须结合固定源码判断。

首批可从当前核对过的简单基础开始，然后衔接使用者。选批无需逐批审批，扩大生成范围须先取得用户选择。工作区新增或更改的文件保持与固定树区分。图缺边／新节点 unreviewed 只表明尚待核对。

## 3. 登记本批节点

本批文件确定后，在保存讲法或登记图节点前，按[写入前检查 Git 可见性](tools.md#project-privacy)核文件讲解、依赖图和本批要写的教学资料。放行后，按[教学资料](feedback.md#讲解偏好)保存本次明确的项目讲法。用 apply-graph 的 register 登记路径。已有状态及关系由工具保留。提交前核固定映射和输入只含获准本批文件，新登记是 unreviewed。

## 4. 逐文件制作和检查

AI 决定完整有序块清单，create-document 返回工具骨架，再填正文。按源码顺序讲清代码怎样运行，让读者只打开这篇文件也能从头读。相邻几行共同完成一件事时连起来讲，在决定行为的语句写明值、条件和结果。第 1 档展开基础和例子，第 2 档在实际分工的关键处用[内置起始讲法](teaching.md#第二档的内置起始讲法)解释设计，第 3 档压缩熟悉语法，讲清本文件职责、调用和边界。

保持 [制作约束](authoring.md) 的源码引用和 ID 规则。校验前回读正文，确认源码顺序、关键行为和所选讲法都能从本篇读出来。逐篇 validate-document 并据真实诊断修正。

一篇填写并校验满足完成条件后才转下一篇。操作失败时核实际落盘结果再决定可安全续做的独立文件，保留已完成资料与原诊断。任一未完成文件不得在批次报告或方向中写成已完成。

## 5. 核对依赖并收尾图

本批讲解完成后，按使用者逐个提交 `analysis=reviewed` 的完整项目文件依赖及原因。完成核对且无项目文件依赖时才给空 dependencies。未核对完只保留 register 状态，勿用空列表覆盖。

范围内尚未讲解及范围外的真实项目依赖都可登记节点／边，保持其实际分析状态。范围外背景到此为止，不递归展开其全部依赖或生成讲解。

多数依赖只需完整理由。只有线上几个字确实能帮读者追踪关键关系时，才在该依赖或该文件的库用法选填 `label`，例如「取自登录上下文」。配色按讲解目的独立选用，字段见[图工具](tools.md#库图例)。

对既有文件先 query-graph，核已有关系并给完整列表。工具按指定使用者替换，其余使用者关系保留。

理解本批代码时确实需要认识某个标准库或第三方库，就在本图添加库图例。先用 query-legends 找到可沿用的实例 ID。介绍说明该库提供的能力，并为每个实际使用文件写明它借用了哪一项能力、解决什么问题。图例端点用已登记或同批登记的文件路径，按固定源码核对实际用法。关联保存在 uses，项目内文件依赖照常独立核对。更新介绍时只提交该实例 ID 与新介绍，保留读者摆放。用法变化时先查已有关系，再提交完整 uses，保留仍成立的关联。具体输入见[工具](tools.md#库图例)。

收尾运行 validate-graph，读 sourceCheck、diagnostics 和 analysis 状态，明确尚未核对部分。程序校验字段、端点和固定源码，讲解 AI 对教学内容和用法准确性负责。

## 6. 检查阅读方向

按 [教学资料](feedback.md) 读取方向，有变化则合并实际已讲主题与后续理由。无真实反馈时保持观察区，无需因生成新讲解修改教学偏好。初始化及保存遵循资料保护。

## 7. 交付与继续

给实际讲解文档入口、固定提交／源码路径／行范围、简短内容及前后联系。列实际机械检查、正文状态、超大警告、未完成文件和未核对依赖。Git 失败带不含源码正文的错误类别与定位。

新讲解本批全部校验并读回后，按[启动与交付](tools.md#reader-launch)选一处本批起读块，告知读者，一批只请求打开一次。有多篇时交代从哪篇哪个块开始。当前只是答疑、正在等确认、本批失败或仍待校验时，不触发交付启动。

提醒「可以复制对应块的定位来问，也可以告诉我把哪里讲清楚」。逐批阅读到此等待用户继续，已有选择下次复用。连续生成在已确认范围内继续下一相关小批，直到范围内文件均已完成或具体障碍需用户输入。每批收尾照常进行。依赖资料失败不写成整批成功，列仍可阅读的成果与阻塞部分。

### 用问句按需展开依赖

先保留读者理解主线所需的文件和关系。遇到能单独回答的问题，例如“订单创建后在哪里记录审计事件？”，可只收起相关的审计线。沿固定版本核对真实端点和理由，目标使用文件路径，方向为依赖项指向使用者。通过 `apply-graph` 的 `legendUpserts` 一次提交下列实例，再用 `validate-graph` 和 `query-legends --id audit-trail` 读回。

```json
{"type":"switch","id":"audit-trail","question":"订单创建后在哪里记录审计事件？","nodes":[],"edges":[{"from":"support/audit.mjs","to":"src/service.mjs"}]}
```

开关可省略。只更新已有问句时沿用 id，提交完整开关定义。目标消失时，在同一批更新中修正或移除开关。
